## 这解决什么问题

用 CubeMX 配 STM32 的人，配时钟的全部方法常常是这一套：

```
看最大频率 → 拉满 → 看到变红 → 除以 2 → 红没了 → 生成代码 → 烧进去
```

红字消掉那一刻，配置在工具眼里已经合法了。**可它在板子上会变成什么，没有人说过。**

这不是猜的。两条 B 站教学视频里，老师自己就是这么教的：

| 原话 | 出处 |
|---|---|
| 「它这里显示最大是 72 兆赫兹，那么咱们**直接给它拉满**」 | 电子科技大学创客中心《如何使用 STM32CubeMX 快速配置工程》14:29 |
| 「大家看到这样一框图**看起来非常复杂是吗**？大家不要慌」 | 同上 08:36 |
| 「如果你这个地方选 No Debug……会导致芯片程序**只能下载一次，第二次下不进去了**」 | 同上 07:01 |
| 「此倍频器有 ×1 和 ×2 两个值，**但我们无法自己设置**」 | keysking《STM32 时钟树动画讲解》 |

而「配错会长什么样」，是在第三条讲 ADC+DMA 的视频里数出来的：

- 采样率不够 → 波形退化成台阶，串口原始数据**五个值一循环**（3968、2509、290、365、2635），一个信号周期只被采到 5 个点
- Overrun 选「保留」→ 读数**卡死在 747** 一动不动，曲线变一条平线，**屏幕上没有任何报错**

> 配错的时候，芯片不会告诉你「你配错了」，它只会给你一个看不懂的现象。

## 这个工具做什么（三件 CubeMX 不做的事）

| # | 做什么 | 为什么 CubeMX 不做 |
|---|---|---|
| ① | **把红字翻译成人话**：不只是「超了」，而是「哪一格超了、改成几、改完是多少」 | CubeMX 只变红，不给改法 |
| ② | **算它不算的那个数**：TIM3 出 1kHz 时 PSC/ARR 填多少、ADC 实际采样率、串口波特率误差 | CubeMX 只给总线时钟，中间那步全靠自己算；它的 TIM 页**不显示算出来的频率** |
| ③ | **预测配错会看到什么现象** | CubeMX 管配置合不合法，不管跑起来会怎样 |

### 明确不做

- ❌ 不替代 CubeMX，不生成完整工程
- ❌ 不绑定代码库（HAL / LL / 标准库都无关）
- ❌ 不支持这三款以外的芯片（只做 3 款，因为每一款都逐条校准过）

### 支持的芯片

| 芯片 | 封装 | 内核 | 主频 | 可用 IO | APB1 / APB2 上限 | ADC 上限 |
|---|---|---|---|---|---|---|
| STM32F103C8T6 | LQFP48 | Cortex-M3 | 72 MHz | 37 | 36 / 72 | 14 |
| STM32F407ZGT6 | LQFP144 | Cortex-M4 | 168 MHz | 114 | 42 / 84 | 36 |
| STM32F411CEU6 | UFQFPN48 | Cortex-M4 | 100 MHz | 36 | 50 / 100 | 36 |

## 数据是怎么来的（这部分最值得看）

数据不是抄教程，也不是模型编的：

| 步骤 | 方法 | 结果 |
|---|---|---|
| 1. 引脚 | 解析 CubeMX 自带器件库 `db/mcu/*.xml`（2016 个文件 / 19 系列 / 4801 颗） | 194 个引脚，逐条核对封装 |
| 2. 时钟上限与分频可选值 | 直接读 `db/mcu/IP/RCC-*.xml` 的 `RefParameter` | 精确到每个可选值和默认值 |
| 3. 算得对不对 | 用 **CubeMX 6.15.0 官方 CLI** 逐组设置 → 回读时钟值 | 9 组全部对上 |
| 4. 交叉验证 | 三条教学视频逐帧拆解，画面上的数值与数据比对 | 发现并修正了 7 处错误 |

### 几个自己踩出来、值得记一笔的发现

**1. F103 的 HSE 进 PLL 前有可选 ÷1 / ÷2（PLLXTPRE）**

很多教程写 `SYSCLK = HSE / 2 × PLLMUL`，也有说「F1 不能除 2」的。实测：

| HSEDivPLL | PLLMUL | CubeMX 回读 SYSCLK |
|---|---|---|
| ÷1 | ×9 | **72,000,000** |
| ÷2 | ×9 | **36,000,000** |

真相是：**默认 ÷1，可以选 ÷2**。要跑满 72MHz 必须用 ÷1（用 ÷2 时即使 ×16 也只有 64MHz，反而上不了 72）。

**2. F103 的 USB 预分频是「可选」，不是固定**

`USBPrescaler` 默认是 **÷1**，可选 ÷1 / ÷1.5。
所以「PLL 配到 72，USB 自然就是 48」是错的——**必须手动选 ÷1.5**。默认档下 USB 拿到的是 72MHz，插电脑认不到设备。

**3. CubeMX 管总线，不管外设上限**（而且不同系列还不一样）

| 芯片 | ADC 预分频在哪 | CubeMX 会拦超限吗 |
|---|---|---|
| F103 | 时钟树里 | **不拦**（器件库无任何约束）→ 配出 36MHz（上限 14）只灰显、不报红 |
| F407 / F411 | ADC 参数页 | **会禁用**超限档位（`Action="DISABLE"`） |

**4. 定时器的 ×2 是硬件自动的，用户改不了**

APB 分频 ≠ 1 时，定时器时钟自动 = PCLK × 2。这个倍频器「有 ×1 和 ×2 两个值，但无法自己设置」。

## 怎么跑起来

### 参考实现（最快）

页面要 `fetch` 同目录的 `stm32-data/data.json`，直接双击打开会被浏览器的本地文件策略拦住。起个本地服务器：

```bash
# 在仓库根目录
python -m http.server 8000
# 打开 http://localhost:8000/参考实现.html
```

页面底部有断言结果（**28 项全通过**才算对）。也可以自动跑：

```bash
python 脚本/浏览器自测.py
```

### 重新生成数据

```bash
python 脚本/_parse_mcu_db.py    # 从器件库解析
python 脚本/_build_data.py      # 生成 data.json + 核对表
python 脚本/自检.py              # 73 项数据自检
```

> 需要本机装有 STM32CubeMX（默认路径 `D:\STM32CubeMX`，可在脚本里改）。
