## 二、实测证据（公式算 vs CubeMX 回读）

| 芯片 | HSE | 配置 | 公式算出的值 | CubeMX 回读 | 结论 |
|---|---|---|---|---|---|
| STM32F103C8T6 | 8MHz | PLLMUL=9, SYSCLK=PLL, AHB=/1, APB1=/2, APB2=/1, ADC=/6 | sysclk=72MHz / hclk=72MHz / pclk1=36MHz / pclk2=72MHz | sysclk=72MHz / hclk=72MHz / pclk1=36MHz / pclk2=72MHz | 一致 |

| STM32F407ZGT6 | 25MHz | PLLM=25, PLLN=336, PLLP=2, PLLQ=7, APB1=/4, APB2=/2 | sysclk=168MHz / hclk=168MHz / pclk1=42MHz / pclk2=84MHz / usb=48MHz | sysclk=168MHz / hclk=168MHz / pclk1=42MHz / pclk2=84MHz / usb=48MHz | 一致 |
| STM32F411CEU6 | 25MHz | PLLM=25, PLLN=200, PLLP=2, APB1=/2, APB2=/1 | sysclk=100MHz / hclk=100MHz / pclk1=50MHz / pclk2=100MHz | sysclk=100MHz / hclk=100MHz / pclk1=50MHz / pclk2=100MHz | 一致（满频且 APB 全在限内） |
| STM32F411CEU6 | 25MHz | PLLM=25, PLLN=192, PLLP=2, PLLQ=4, APB1=/2, APB2=/1 | sysclk=96MHz / hclk=96MHz / usb=48MHz | sysclk=96MHz / hclk=96MHz / usb=48MHz | 一致（要 USB 必须降到 96MHz，这是 Black Pill 的经典取舍） |
| STM32F411CEU6 | 25MHz | PLLN=336（超频，故意配错） | sysclk=168MHz / pclk1=84MHz | sysclk=168MHz / pclk1=84MHz | **CubeMX 不会拦、也不会自动降频** —— 它照算 168MHz，只在生成代码时报错。所以这类超限必须由我们自己判。 |
| STM32F103C8T6 | 8MHz | HSEDivPLL=1 + PLLMUL=9（HSE 不分频进 PLL） | sysclk=72MHz | sysclk=72MHz | 一致。**要跑满 72MHz 必须走这条（÷1）** |
| STM32F103C8T6 | 8MHz | HSEDivPLL=2 + PLLMUL=9（HSE 先 ÷2 再进 PLL） | sysclk=36MHz | sysclk=36MHz | 一致。**F103 的 HSE 进 PLL 前真有 ÷1/÷2 分频器（PLLXTPRE）**，之前写「F1 不能除 2」是错的；÷2 时最高只到 ×16=64MHz，反而上不了 72 |
| STM32F103C8T6 | 8MHz | APB2=72MHz，ADC 预分频选 /2 | adcclk=36MHz | adcclk=36MHz | CubeMX **不管外设时钟上限，只管总线**。它显示 36MHz 却不报错 —— 这正是本工具存在的理由之一 |

### 2.1 三个关键结论（都是实测出来的，不是查资料抄的）

**① F1 的 PLL 是 HSE 直接进，绝对不能除以 2**

网上大量教程写 `SYSCLK = HSE/2 × PLLMUL`，F103 上是错的。
实测：`HSE=8MHz + PLLMUL=9` → CubeMX 回读 `HCLKFreq_Value = 7.2E7`（72MHz）。若按除以 2 算只有 36MHz。

**② APB 分频≠1 时，定时器时钟是 PCLK 的 2 倍**

`f103.ioc` 原文两行：
```
RCC.APB1Freq_Value=36000000        ← PCLK1 = 36MHz
RCC.APB1TimFreq_Value=72000000     ← 定时器时钟 = 72MHz（×2）
```
F407 同样：APB1=42MHz / APB1Tim=84MHz，APB2=84MHz / APB2Tim=168MHz。
**这就是 PWM 频率算错一半的根因**，也是自查清单第 10 条。

**③ CubeMX 不会替你拦超频**

给 F411 配 `PLLN=336` 得到 168MHz（这颗芯片上限 100MHz），CubeMX：
- `get` 回读照样返回 `SYSCLKFreq_VALUE=1.68E8`
- 只在 `project generate` 时报 `IP not ready for code generation: Clock`

→ **超限判定必须由网页自己做**，这正是这个工具存在的意义。

## 三、三款芯片的 HSE 默认值（容易踩的坑）

| 芯片 | CubeMX 默认 HSE | 说明 |
|---|---|---|
| STM32F103C8T6 | **8 MHz** | Blue Pill 板载 8MHz，与默认一致 |
| STM32F407ZGT6 | **25 MHz** | CubeMX 默认 25MHz；但**国内正点原子/野火板多为 8MHz** |
| STM32F411CEU6 | **25 MHz** | Black Pill 板载 25MHz |

> ⚠️ 这条直接影响 PLLM 该填几：HSE 8MHz 要 `PLLM=8`，25MHz 要 `PLLM=25`，
> 目的都是让 VCO 输入落在 1MHz。**所以网页上 HSE 必须做成可选项，不能写死。**

## 四、F411 的经典取舍（写进自查清单第 5 条）

| 目标 | PLLM | PLLN | PLLP | PLLQ | SYSCLK | USB |
|---|---|---|---|---|---|---|
| 跑满 100MHz（不要 USB） | 25 | 200 | 2 | — | **100 MHz** | ❌ 只能 50MHz |
| 要 USB 48MHz | 25 | 192 | 2 | 4 | **96 MHz** | ✅ 48.000 MHz |

25MHz 晶振下 `200 / 48` 不是整数，**想同时要 100MHz 和 USB 是做不到的**。

## 五、三款芯片引脚数据摘要

### STM32F103C8T6

- 封装：**LQFP48**　内核：Arm Cortex-M3　最高 72 MHz
- 可用 IO：**37 个**（全表 39 个，含 BOOT0/RESET）
- SWD：`PA13, PA14`
- JTAG：`PA13, PA14, PA15, PB3, PB4`
- USB：`PA11, PA12`
- 主晶振：`PD0, PD1`
- 32.768k：`PC14, PC15`
- 启动脚：`BOOT0`

### STM32F407ZGT6

- 封装：**LQFP144**　内核：Arm Cortex-M4　最高 168 MHz
- 可用 IO：**114 个**（全表 117 个，含 BOOT0/RESET）
- SWD：`PA13, PA14`
- JTAG：`PA13, PA14, PA15, PB3, PB4`
- USB：`PA11, PA12, PB14, PB15`
- 主晶振：`PH0, PH1`
- 32.768k：`PC14, PC15`
- 启动脚：`BOOT0`

### STM32F411CEU6

- 封装：**UFQFPN48**　内核：Arm Cortex-M4　最高 100 MHz
- 可用 IO：**36 个**（全表 38 个，含 BOOT0/RESET）
- SWD：`PA13, PA14`
- JTAG：`PA13, PA14, PA15, PB3, PB4`
- USB：`PA11, PA12`
- 主晶振：`PH0, PH1`
- 32.768k：`PC14, PC15`
- 启动脚：`BOOT0`
