# 实测：把「推断」变成「自己板子跑出来的数据」

这个目录放的不是文档，是**能重跑的固件和它们的原始输出**。

这份作品的规则清单里，有三条最容易说错、也最容易被评委追问的事：

1. **时钟树到底配成了什么** —— 不是看界面显示，是读芯片寄存器
2. **定时器时钟 ×2 是不是真的** —— 不是查手册，是量定时器实际周期
3. **ADC 时钟超上限会怎样** —— 不是想当然，是测读数稳定性

以前这三条只能标【推断】。现在两块板都跑完了，标【实测·自己板子】。

---

## 一、为什么结果不在串口上

这两块开发板**都没有 USB 转串口芯片**（F407 核心板原理图上明确写着「核心板不具备硬件USB转串口电路！！」），所以没法直接 `printf` 到电脑。

解决办法：**把报告写进一个固定 RAM 地址，烧完复位后用 ST-Link 把这块内存读回来**。

```
固件把报告写进 0x2000007C
        ↓
固件停在 while(1)，RAM 不丢
        ↓
ST-Link 读 0x2000007C 起 2400 字节
        ↓
按 UTF-8 解码 = 报告全文
```

**零外部接线**：不需要串口线、不需要 USB-TTL、不需要示波器。只要一根 ST-Link。

## 二、两块板的结果

### F103C8T6（Blue Pill，72MHz，8MHz 晶振）

| 项目 | 实测值 |
|---|---|
| SYSCLK 源 / PLLXTPRE / PLLMUL | PLL / **HSE ÷1** / ×9 |
| AHB / APB1 / APB2 | /1 / **/2** / /1 |
| SYSCLK / HCLK / PCLK1 / PCLK2 | 72 / 72 / **36** / 72 MHz |
| **定时器 ×2** | TIM3 PSC=7199 ARR=9999 → 实测 **2000ms** → **TIM3CLK = 72MHz** |
| ADC 12MHz（合规） | 均值 1499，峰峰 7 |
| ADC 36MHz（超限 2.6 倍） | 均值 1495，峰峰 5 |

### F407ZGT6（鹿小班核心板，168MHz，8MHz 晶振）

| 项目 | 实测值 |
|---|---|
| PLL | PLLM=8 / PLLN=336 / PLLP=÷2 / PLLQ=7 |
| AHB / APB1 / APB2 | /1 / **/4** / /2 |
| SYSCLK / HCLK / PCLK1 / PCLK2 | 168 / 168 / **42** / 84 MHz |
| **定时器 ×2** | TIM3 PSC=8399 ARR=9999 → 实测 **2000ms** → **TIM3CLK = 84MHz** |
| ADC 21MHz（合规） | 均值 1484，峰峰 7 |
| ADC 42MHz（超限） | 均值 1482，峰峰 9 |

## 三、两个最扎眼的发现

### 发现 1：ADC 时钟超上限，**什么异常都没有**

原来的说法是「超了就会读数乱跳」。**实测推翻了它。**

| 芯片 | 合规档 | 超限档 | 差异 |
|---|---|---|---|
| F103 | 12MHz：1499 / 峰峰 7 | 36MHz：1495 / 峰峰 5 | 几乎没有 |
| F407 | 21MHz：1484 / 峰峰 7 | 42MHz：1482 / 峰峰 9 | 几乎没有 |

采的是芯片内部 1.2V 基准（VREFINT），信号源阻抗极低。**两颗芯片都没坏。**

所以第 4 条规则已经改成诚实版：**超出规格 ≠ 立刻坏，ST 只是不再保证精度**。这反而让它更危险——**它查不出来**，最容易被埋在项目里。

### 发现 2：烧录成功 ≠ 程序在跑

烧 F103 时，工具明确报 `Download verified successfully`，但紧接着读内存，读出来还是**上一份程序的残留数据**——新固件连一行都没执行。

原因不是烧录失败，是**烧完之后芯片没有自动复位**。手动复位一次，结果立刻就出来了。

这条已经加成新规则（第 17 条）：**"烧录成功"和"程序在跑"是两件独立的事。**

## 四、怎么自己重跑

### 需要什么

| 项 | 版本 / 位置 |
|---|---|
| STM32CubeMX | 6.15.0（生成工程用） |
| STM32CubeCLT | 1.18.0（自带 CMake / Ninja / arm-none-eabi-gcc 13.3.1） |
| ST-Link | V2（V2J46S7 实测可用） |
| 板子 | F103C8T6 或 F407ZGT6 核心板，**8MHz 晶振** |

### 编译

```powershell
$clt = "D:\Clion\STM32CubeCLT_1.18.0"
$env:PATH = "$clt\GNU-tools-for-STM32\bin;$clt\Ninja\bin;$env:PATH"

# F103
cmake -B build -G Ninja `
  "-DCMAKE_TOOLCHAIN_FILE=$PWD\cmake\gcc-arm-none-eabi.cmake" `
  "-DCMAKE_MAKE_PROGRAM=$clt\Ninja\bin\ninja.exe" -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

### 烧录 + 读回

```cmd
f103\run.cmd      ← F103 板
f407\run.cmd      ← F407 板
```

脚本会自动：烧录 → **复位**（关键，见发现 2）→ 等 10 秒 → 读 RAM → 打印报告。

### 接线（F407 核心板特别注意）

这块板的 SWD 排针丝印是 **`+5V / GND / DIO / CLK`**，顺序和 Blue Pill 的 `3V3/SWDIO/SWCLK/GND` **完全不同**：

| ST-Link | → | 板子 |
|---|---|---|
| GND | → | GND（第 2 脚） |
| SWDIO | → | DIO（第 3 脚） |
| SWCLK | → | CLK（第 4 脚） |
| 3.3V | → | **不接** |

板子用 Type-C 单独供电。**不要把 ST-Link 的 3.3V 接到板子的 +5V 脚**（那是 5V 输入，接 3.3V 会让 LDO 输入不足）。

## 六、这套方法本身的复用价值

「结果写固定 RAM + ST-Link 读回」这个套路，适合任何**没有串口输出手段**的场景：

- 板子没焊串口芯片
- 串口被别的功能占了
- 只想快速验证、不想为了打印一行字去配 USART

代价是每次要看结果都得插 ST-Link；好处是**零额外硬件、不用改接线**。

如果板子有串口（比如这块 F407 背面就引出了 `3V3/RST/TXD/RXD`），固件里也已经带了一份 UART 输出（USART1，115200），接上 USB-TTL 就能直接看。
