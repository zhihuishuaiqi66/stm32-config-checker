## 观察到的现象与数字

1. **00:00 的初始状态**：ADC1 页已打开但 3 个通道全是 `Disable`，`Configuration` 区空白 —— 说明"没选通道就没有参数页签"。
2. **00:30 差分/单端的唯一证据**：IN1 下拉只有三个选项 `Disable` / `IN1 Differential` / `IN1 Single-ended`，讲师选的是 **Single-ended**；全程**没有**出现过差分配置下的任何参数或波形。
3. **ADC 时钟**：画面只有一句 `Synchronous clock mode divided by 4`，**没有任何 MHz 数值**；本段也没出现 ADC 专用时钟选择器。
4. **"普通转换" 对应的界面证据**：`Continuous Conversion Mode = Disabled` + `End Of Conversion Selection = End of single conversion` + `Overrun behaviour = Overrun data preserved`（本段画面里 Overrun 一直是 `Overrun data preserved`，未见改动）。
5. **超时时间 = 100**（`HAL_ADC_PollForConversion(&hadc1, 100)`），03:00 出现在画面上；这是本段唯一一个"超时"数值。代码里**没有任何地方**把返回值 / HAL_StatusTypeDef 赋给变量（PollForConversion 的返回值被丢弃，直接下一行取 GetValue）。
6. **API 返回值证据（03:48）**：画面打开了 `stm32g4xx_hal_adc.c`，能读到 `uint32_t HAL_ADC_GetValue(const ADC_HandleTypeDef *hadc)` 的实现：`return hadc->Instance->DR;`，并注明 EOC 标志由硬件在读 DR 时自动清除。使用者侧写成 `uint32_t ADC_Value = HAL_ADC_GetValue(&hadc1);`，即返回值类型 **uint32**。
7. **串口实测数值**：`889` —— 04:48 文本区逐行 `889`（底部接收计数 `22 / 500000`），右侧 `IO` 面板显示 `889.0000`；04:54 清空文本框后计数变 `80 / 500000`，`IO` 仍是 `889.0000`。**画面里始终只有 889，没有出现 888 / 890**。
8. **波形**：VOFA+ 的曲线区全程是一条**水平直线**（落在 y 轴 `482.949` 刻度附近），没有正弦/三角/方波 —— 因为本段输入是直流电平（信号发生器到 06:35 之后才打开）。
9. **"没有输出" 现象（04:36）**：串口已连接（COM12 115200，FireWater）、但文本区与曲线区**全空**，计数 `0 / 500000`；04:42 画面上 `printf` 被改成带 `\n` 的版本并重新下载，04:48 才有数据 —— 即"没换行 → 看不到输出"。
10. **持久报错标记**：从 02:00 起直到 05:00，Problems 面板一直显示 `1 error, 9 warnings, 0 others`，`Errors (1 item)` 与 `Warnings (9 items)` **始终是折叠状态，本段从未展开**，看不到具体内容；编译/下载本身是成功的（`Download verified successfully`）。
11. **CubeMX 生成代码时的弹窗**：02:00 / 02:06 两次出现 `Device Configuration Tool Updating Code...` 进度框（带 `Cancel`）。
12. **IDE 的 AI 悬浮条**（03:24）：鼠标停留代码上时出现 `AI 搜索 / 翻译 / 解释 / 复制 / 朗读` —— 这是录制者 CubeIDE 的 AI 助手功能，不是教程内容。
13. **画面时间戳线索**：任务栏 23:41（00:00）→ 23:53（04:54），控制台编译时间 `23:47:00 **** Build of configuration Debug for project G431RBT6_TEST`。
