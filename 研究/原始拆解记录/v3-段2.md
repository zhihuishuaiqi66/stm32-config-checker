## 观察到的现象与数字

### 1. 单次转换 + 软件触发：读到一个死数 889
- 05:00、05:06 两帧 VOFA+：`I0 = 889.0000`，曲线完全平直，文本区连续刷 `889`。
- 这是本段第一个“错”的现象，画面与台词（数据一成不变即 100% 错）一致。
- 需要主人复核的是：`889` 恰好只有一次读数——即 `HAL_ADC_Start` 在 while 外面 + `Continuous Conversion Mode = Disabled` 的组合结果。

### 2. 把 Start 挪进 while 之后：先读到 0
- 07:15–07:27：`I0 = 0.0000`，文本区全 `0`，曲线贴 0 线（缓冲计数 56688 → 156039 之间波动）。

### 3. 输入频率过高 → 波形失真（本段最关键的“现象证据”）
| 时间 | VOFA+ 波形形态（画面直读） | `I0` |
|---|---|---|
| 07:33 | 密集尖齿，一屏 20+ 周期，峰谷不等高 | `1275.0000` |
| 07:39 | 同上，更乱，明显折点/台阶 | `3917.0000` |
| 07:41 | 密集锯齿，约 20 个周期 | `274.0000` |
| 07:45 | 仍带锯齿，约 11 个周期，谷底有平台 | `805.0000` |
| 07:47 | **干净正弦，约 3 个周期** | `3769.0000` |
| 07:51 | **干净正弦，约 4~5 个周期** | `184.0000` |

- 07:45 那一帧的参数有变化：`Delta 90 → 91 ms`、`80.1 → 81 ms/X-div`（VOFA+ 自动量程在跳）；09:21 恢复后又是 `Delta 90 / 80.1 ms/X-div`。
- 结论（画面可证）：**同一套 CubeMX 配置下，仅改变输入正弦频率，采样波形就从“密集锯齿”变成“干净正弦”** —— 即采样率相对信号频率不够。

### 4. 勾上连续转换模式却没改 Overrun → 读到死数 747
- 08:15 把 `Continuous Conversion Mode` 改成 `Enabled`；
- 08:21、08:27 两帧 VOFA+：`I0 = 747.0000` **一动不动**，文本区刷 `747`，曲线平直；
- 直到 **08:51**（下拉 08:45 展开）把 `Overrun behaviour` 从 `preserved` 改成 **`overwritten`** 后才恢复（09:15 读到全 0 → 09:21 出干净正弦 `I0 = 731.0000`）。
- **画面证据链完整**：`Enabled` + `preserved` = 747 死数 → 改 `overwritten` = 波形正常。这条可以直接喂给自查工具当规则。

### 5. 恢复后的正常波形数值
- 09:21：正弦，一屏约 3 个周期；串口序列 `0 → 19 → 147 → 398 → 731 → 1128 → 1683 → 2257 → 2811 → 3291 → 3662`（12 位 ADC，满量程 4095 量级，与 3.3 Vpp / 1.65 V 偏置匹配）。
- VOFA+ 侧栏固定值：数据引擎 `FireWater`；`At: 9 ms`；`缓冲区上限 500000 /ch`；`Auto点数对齐 100`；`80.1 ms/X-div`（09:21，而 07:45 失真时是 `91 ms / 81 ms·X-div`）；y 轴刻度标签 `6984.338 / 5990.773 / 4817.208 / 3733.643 / 2650.078 / 1566.514 / 482.949 / -600.616 / -1684.181 / -2767.746 / -3851.311`。

### 6. 信号发生器设定（RIGOL DG972，屏幕直读）
- 06:51 与 06:57 两帧稳定显示：`Continuous` / CH1 / `1.000,000,000 kHz` / `3.300,0 Vpp` / `1.650,0 Vdc` / `0.000 °` / `Sine` / `HighZ`。
- 该机显示格式为“小数点后按 3 位一组用逗号分隔”：`1.000,000,000 kHz` = 1.000000000 kHz = **1 kHz**；`3.300,0 Vpp` = **3.3 Vpp**；`1.650,0 Vdc` = **1.65 V**。
- 出现该数值的画面只有 06:51、06:57 两帧（其后镜头离开发生器屏幕）。
- **重要**：400 Hz 与 100 Hz 这两次改频，**画面上没有出现 DG972 的频率数值**（他是在机器上拧/改，镜头没给屏幕）。所以 400/100 Hz 只有音频，**不能作为画面证据**。

## 讲师强调的坑

1. **ADC 读数是死数 = 配置错**（05:00 画面 889 不动）。台词 04:53/05:09 明确“一直是同一个数你就是错的”，画面直接给了这条的实例。
2. **软件触发 + 单次转换 = 只转换一次就关机**。05:27 画面里 `Continuous Conversion Mode = Disabled`、`External Trigger Conversion Source = Regular Conversion launched by software` 两行同屏，就是这句话的配置证据。
3. **必须把 `HAL_ADC_Start` 放进 while 循环**（07:59 画面里第 95 行被灰掉、第 102 行成了 loop 内第一句）。
4. **连续转换模式必须配 `Overrun data overwritten`**（08:51）。画面同时把两件事绑死：`Continuous Conversion Mode = Enabled` + `Overrun behaviour = preserved` → 747 死数；改成 `overwritten` → 波形正常。
5. **采样太慢时高频信号会烂**：同一配置只改输入频率，波形从密集锯齿变干净正弦（07:33 → 07:47）。
6. **讲师自己在本段打了免责红字**：08:50–08:56 画面叠 `此处请自己鉴别` / `可能口误`。这正落在“Overrun 该选哪个”的讲解上，说明**这段口播的因果解释不可靠，应以 CubeMX 界面的选项名为准**（`ADC_OVR_DATA_OVERWRITTEN`）。
7. **阻塞式 `HAL_ADC_PollForConversion(...,100)` 会卡主循环**（09:45 之后切到画图讲 ADC/CPU/DMA/RAM 的框图，对应台词“阻塞会影响实时性”）。注意：**这段因果是他用画图讲的，屏幕上没有任何代码/时序数据支撑**。
