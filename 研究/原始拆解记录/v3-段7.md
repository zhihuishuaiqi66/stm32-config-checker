### 2. **"5 点/周期" 采样不足的显微镜级证据（30:30、30:36、31:25 – 32:23）**

接收区（Rx）显示的是**逐点打印的 ADC 原始值**，其排列呈严格 **5 值一循环**：

```
3968, 2509, 290, 365, 2635, 3967, 2525, 297, 356, 2620, 3967, 2541, 307, 347, ...
```

- 每 5 个数构成一个完整周期：**峰（≈3967/3968）→ 下降段（≈2509/2525/2541）→ 谷（≈290/297/307）→ 谷后（≈347/356/365）→ 上升段（≈2620/2635）**。
- 上面这 14 个数里，5 值序列**重复了将近 3 次**（数值有 1~2 个 lsb 抖动，两次峰顶只差 1），这是"**一个信号周期只被采到 5 个点**"的最直接画面证据。
- 图形上的对应表现：**峰顶是一段平线**（因为相邻两个采样点几乎等值），坡段是**直线**，整体成了"梯形波"而不是正弦 —— 这正是本项目需要的"采样率偏低 → 波形失真"的可见形态。
- 同一现象在 31:25 之后的画面里**保持原样**（接收区数值序列与 30:30 完全相同），直到片尾。

### 4. 采样率推算：画面上到底给了什么（**画面事实**）

- 画面里唯一与"采样率/触发频率"直接相关的数字，是 TIM3 的两个框：
  - `Prescaler (PSC - 16 bits value)` = **`170 - 1`**
  - `Counter Period (AutoReload Register - 16 bits value)` = **`10 - 1`**
  - `Trigger Event Selection TRGO` = **`Update Event`**
- 之后 `Prescaler` 被改成 **`17 - 1`**（`Counter Period` 保持 `10 - 1`）。
- **画面从未显示 TIM3 的输入时钟频率、也从未显示算出来的更新频率**；`Clock Configuration` 页在本段一次都没出现。也就是说，"170 MHz"和"100 K / 1 M"这几个数**只存在于讲师口述里，屏幕上没有对应的像素**。
- 由此可做的**唯一算术**（可见数字 ×1 + 口述数字 ×1）：
  - `f_update = f_TIM3CLK / (PSC+1) / (ARR+1)`
  - 原配置：`170 MHz / 170 / 10` = **100 kHz**（对应讲师口述"采用率 100K"）
  - 改后：`170 MHz / 17 / 10` = **1 MHz**（对应讲师口述"直接变成一兆"）
  - 校验点：`1 MHz / 20 kHz` = **50 点/周期**（讲师口述的"50 个点"）
- ⚠️ 但**画面上能直接数出来的只有 5 点/周期**（第 2 条），而 5 点/周期对应的是 **100 kHz 采样**；改 PSC 之后 31:25 起的波形与 30:30 是**同一段数据**（接收区数值逐字相同，据此推断未重新下载），所以"50 点/周期"在屏幕上**没有出现过**。

## 讲师强调的坑（**以下全部为口述，ASR 转写，仅作对照，未经画面证实**）

> 台词错字对照：Qb/Hell/DNA/采用率/正情波/波情/计元器/主色/卷地/FT收 → CubeMX / HAL / DMA / 采样率 / 正弦波 / 波形 / 寄存器 / 阻塞 / 接地 / FFT

1. **波形好不好看，取决于采样率**（30:22）：
   「如果你想让你的波形特别好看的话，你得把你的**采样率弄得非常高**。」
   —— 对应画面：30:30 起一直是"5 点/周期"的梯形波，确实不好看。
2. **一个周期采几个点，是采样率 ÷ 信号频率**（30:29 – 30:34）：
   「20K 就是一个周期之内……我们现在**采样率是 100K**……也就是说现在一个周期 **5 个点**，一个点、两个点、345，5 个点。」
   —— 对应画面：接收区 5 值一循环，与口述吻合（**这是全片最干净的一处"口述↔画面"互证**）。
3. **ADC 采样率不是 ADC 自己决定的，是定时器决定的**（30:39）：
   「我们这个 ADC 的采样率，我们是**受定时器控制的**。」
4. **ADC 有上限，先看芯片能承受多少**（30:48 – 30:54）：
   「一是看你这个 ADC 最大能承受多少兆……**STM32F431 的 ADC 最大能承受的是 4 兆**的采样率。」
5. **定时器可以做到 4 MHz**（30:56）：「定时器完全可以弄到四兆的。」
6. **把 PSC 的 0 删掉，采样率直接上一兆**（30:59 – 31:11）：
   「现在我是 **100K**，是吧？我采样率是 100K，你把这个**零 1 删掉**……它直接变成**一兆**了，这就非常非常快了。」
   （ASR 原句为"你把这个零1删掉。你把这个013呢，它直接变成一兆了"，转写明显有错字；"删掉一个 0"这一解释来自画面 **`170 - 1` → `17 - 1`**，不是台词原文。）
   —— 对应画面：31:16 PSC 从 `170 - 1` 变成 `17 - 1`，但**没有再下载**。
7. **每周期 50 个点就没问题**（31:11 – 31:20）：
   「一兆就是……除以 20K，一个周期可以采 **50 个点**，所以这个波形还原还是比较好的。」
   （ASR 原句为"一兆就是1000赫兹，100千0赫兹，10000除以20K"，单位处转写乱了；画面只给了 `17 - 1` / `10 - 1` 两个框。）
8. **做 FFT 根本不需要那么高点**（31:20 – 31:34，本段最重要的"反结论"）：
   「其实这个波形还原太好看，其实也没多大用处……因为如果我们在做 FFT 的时候，我们其实**不需要那么多点，也不需要 50 个点**……**10 个点一般都是比较足够的**，都是可以进行 FFT 然后进行计算的，而且都是比较准的。」

**⚠️ 与画面冲突/需保留处**
- 口述 30:30 说"现在一个周期 5 个点"，画面确实是 5 点 —— 吻合。
- 口述 31:07 说"它会以一兆的数字在采"，但**画面没有一兆的证据**（没有重新编译、波形/数值与 100K 时完全相同）。**这条在评审时应按"未验证的口述"处理。**
- 口述 "F431"、"170 兆" 都只是口头数字，CubeMX 里只有 PSC/ARR 两个框能对上。

## 看不清

1. **CubeIDE 那 1 条 `error` 的内容读不出来**：Problems 面板只展开了 `Warnings (9 items)` 分组，error 行没有展开；`1 error` 只出现在汇总行。面板底部还有 1–2 行警告被窗口边缘裁掉。
2. **PC4 / PC5 的网络标签读不出**：两个引脚是绿色（已占用），但标签在芯片图下方被裁切，放大 6 倍仍只见两个"∨"省略号标记。
3. **`Prescaler` 输入框有 3 帧被编辑光标遮挡**（31:06、31:12、31:18 的闪烁竖线正好压在最右侧数字上），只有 31:16 那帧能确定读成 `17 - 1`。
4. **30:00 那一帧"接收区数值"与"方波"形状对不上**：画面是方波，但 Rx 前 14 个数（0, 17, 98, 179, 260 … 983）是等差递增序列（步长≈80），不像方波的长期恒定值。该列数值究竟属于第几通道、是否已被 FireWater 解析平移，**画面没有任何标注可判断**。
5. **`数据 IO` 面板的语义不明**：画面只在右侧写"数据 / IO / 数值"，没有说明它是第几通道、是瞬时值还是缓冲末值；不同帧数值从 983 / 2169 / 1839 / 0 / 111 / 347 / 21 之间跳。
6. **y 轴量程异常无法解释**：多帧 y 轴跑到 `-3287 … 6873`，超出 12 位 ADC 的 0–4095；工具里没有任何提示说明这是解析量程还是叠加了偏置。
7. **31:24.5 那一帧画图板是空白**：手绘图形的完整版只存在约 2 秒（31:23–31:24.5），17 个采样点（红点）的具体个数受绘图笔宽度影响，**只能数到"十几个"，不敢给精确值**。画图板里分格长条的格数同样只能估到"20 余格"。
8. **`Δt = 9 ms` 与 100 K/1 M 采样率对不上**：这是 VOFA+ 的时间轴参数，画面没有任何地方把它和真实采样间隔关联；31:36 之后 x 轴甚至跑到了 `-344547 ms`。该字段含义**无法从画面确认**。
9. **本段没有任何 ADC 时钟类界面**：无 `ADCCLK`、无 `Prescaler`（ADC 那一个）、无 `Sampling Time`、无 `Continuous Conversion Mode`、无 `Overrun`、无 `External Trigger` 页 —— 若要复核"ADC 时钟配错的现象"，**必须回到 30:00 之前的段落**，本段只能提供 TIM3 侧的 PSC/ARR 与"5 点/周期"的波形证据。
