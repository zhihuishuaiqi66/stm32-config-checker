## 三、还剩 5 条致命，必须改规格书正文

### 🔴 F1 · ADC 采样率公式漏掉 12.5 个转换周期（三个审查员同时指出）

**现状**（规格书 4.4.2）：
```
采样率 = ADCCLK ÷ 采样周期数
12MHz、1.5 周期 → 800 万次/秒
```

**正确**：F1 的 ADC 总转换时间 = **(采样周期数 + 12.5) / ADCCLK**
```
12MHz、1.5 周期 → 12,000,000 / (1.5+12.5) = 857,000 次/秒
```
**错 9.3 倍**，而且 800 万次/秒已经超过 F103 数据手册标称的 **1 Msps** 上限。

**自检方法**（审查员给的，很漂亮）：ADCCLK=14MHz（合法满速）、1.5 周期 → 14e6/14 = **正好 1 Msps**，对上手册。

**重算后的表**（12MHz）：

| 采样周期 | 1.5 | 7.5 | 13.5 | 28.5 | 41.5 | 55.5 | 71.5 | 239.5 |
|---|---|---|---|---|---|---|---|---|
| 采样率上限 | **85.7 万** | 60.0 万 | 46.2 万 | 29.3 万 | 22.2 万 | 17.6 万 | 14.3 万 | 4.76 万 |

**要改三处**：4.4.2 公式与表、2.3.2 的 ADC 卡、3.3 第 4 条规则。
**F4 另核**：RM0090 的 12 位模式固定转换周期是 **12**（不是 12.5）。

### 🔴 F2 · 「官方默认 = 72MHz 全绿」说反了

CubeMX 新建工程的默认是 **HSI + PLL 关闭**（F1 = 8MHz，F4 = 16MHz），不是 PLL 72MHz。
**要改**：五步演示第 1 步改成「满频基准」并明说不是官方默认；另外第 1 步画面有 ADC 灰点，不能写"全绿"。

### 🔴 F3 · 赛道论证缺失 —— 为什么这是 StudyHack 而不是工程实践

全篇没有一处回答这个。评委第一个筛的就是赛道，一句「这是给工程师的效率工具」就能出局。
**建议改法**：把定位从「效率工具」改成**「学习判题器」**——
学生先猜「这样配会怎样」→ 页面揭示真实结果（predict-then-reveal）；
16 条规则每条加一张知识点卡 + 一道 30 秒自测；用 localStorage 记「我错过哪几条」。
这样它就从"帮我把活干成"变成"帮我学懂"，站得住 StudyHack。

### 🔴 F4 · 缺少输入入口 ——「打开就能用」是断的

用户手上已经有 CubeMX 生成的 `.ioc`（纯文本），但规格书里没有任何导入入口，
要求用户把 8~10 个下拉逐一重画一遍 —— 摩擦比直接回 CubeMX 看还大。
**建议改法**：首屏加「把 .ioc 拖进来」，`FileReader` 读文本 → 正则取
`RCC.PLLSourceVirtual / PLLMUL / HSE_VALUE / APB1CLKDivider / APB2CLKDivider / ADCPresc / PLLM,N,P,Q` → 反填三屏。
纯前端可实现，不需要后端。

### 🔴 F5 · 导出件里写了一句做不到的话

屏 3 导出的文件头固定打印「已用 6.15.0 CLI 回读，与页面一致」。
但**纯静态站没有后端**，页面不可能对用户当前这套配置跑 CubeMX CLI。
真正回读过的只有 9 组固定配置。
**要改**：文件头改成状态字段——「本组参数在已回读清单内 → 已回读（附 CLI 输出）；否则 → 公式计算，未回读」。
