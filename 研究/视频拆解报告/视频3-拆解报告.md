## ⚠️ 先说三件必须先纠正的事

### 1. 这条视频的芯片不是 F1/F4，是 **STM32G431RBTx（G4 系列）**

| 画面证据 | 值 |
|---|---|
| CubeIDE 工程 | `G431RBT6_TEST.ioc` |
| 芯片 | **STM32G431RBTx / LQFP64** |
| HSI | **16 MHz**（不是 F1 的 8MHz） |
| PLL | HSI ÷4 ×85 ÷2 = **170 MHz**（G4 有 PLLR，F1/F4 没有） |
| SYSCLK/HCLK/PCLK1/PCLK2 | 全部 **170 MHz** |

**结论：它的配置数值一个都不能搬进我的工具**（我的工具只做 F103/F407/F411）。
但它的**现象模式可以借鉴**。

### 2. 我之前以为的「ADC 时钟证据」是错的

我上一轮看到大纲里有这句台词，以为抓到了宝：

> 07:30「哎，可以看到我们频率降下来了，它才正确，呃，频率高了就不行」

**7 个智能体一致指出：这句说的是信号发生器 DG972 输出的正弦波频率（1 kHz），不是 ADC 时钟。**

画面证据：
- 信号源屏幕：**RIGOL DG972，1.000,000,000 kHz**、3.3 Vpp、偏移 1.65 V、Sine
- ADC 的 `Clock Prescaler` 全程是 **`Synchronous clock mode divided by 4`**，从 05:21 到 18:24 **四次截图完全一致，从没改过**
- **全片从未打开 Clock Configuration 页**，所以画面上没有任何 ADCCLK 的 MHz 数字

→ **这条视频不能证明「ADC 时钟超限 → 读数乱跳」，那个缺口还在。**

### 3. 这条视频没有示波器、没有 PWM 输出

TIM3 在这里是**用来触发 ADC 的**（TRGO = Update Event），不是输出 PWM。
所以**我的 PWM 换算器没被验证**——只验证了公式本身（见下）。

## ✅ 真正拿到的三样东西（很有价值）

### A. 「采样率不足 → 波形变形」的直接实证 ★★★

这是**产品最缺的那类证据**：配置有一个数不对，你眼睛能看到什么。

| 项 | 内容 |
|---|---|
| 配置 | TIM3 的 `Prescaler (PSC) = 170 - 1`、`Counter Period (ARR) = 10 - 1` |
| 推算采样率 | 170 MHz ÷ 170 ÷ 10 = **100 kHz**（讲师口述，画面上没显示） |
| **看到的波形** | 退化成**梯形/台阶波**：峰顶是一段平线、上升下降是直线 |
| **决定性的数字证据** | 串口接收区原始 ADC 值呈**严格 5 值一循环**：<br>`3968, 2509, 290, 365, 2635 │ 3967, 2525, 297, 356, 2620 │ 3967, 2541, 307, 347` |
| 含义 | 一个信号周期只被采到 **5 个点** → 波形当然不对 |

**这一条可以直接写进作品帖**：不是"采样率不够会失真"这种空话，而是"你会看到台阶、而且数据是 5 个值在循环"。

### B. 「Overrun behaviour 选错 → 读数卡死」的完整故障链 ★★

这是一条**从头到尾的故障 → 排查 → 修好**的过程，正是产品想帮人跳过的那段。

| 阶段 | 配置 | 现象 |
|---|---|---|
| 05:00–05:13 | `Continuous Conversion Mode = Disabled` + `HAL_ADC_Start` 在 while 外 | VOFA+ 只有一条**平线**，读数**死锁 889** |
| 08:21–08:33 | 开了 Continuous，但 `Overrun behaviour = Overrun data preserved` | 读数**卡死 747**，曲线平直 |
| 08:51 | 改成 `Overrun data overwritten` | 09:21 波形**恢复正常** |

**注意讲师自己在 08:50 叠了红字「此处请自己鉴别」「可能口误」**——所以这条要引就只引画面（死数 747、平线），别引他的因果解释。

### C. TIM 的 PSC/ARR 公式被验证了 ★

画面数值 + 讲师口述能对上：

```
170 MHz ÷ (170-1+1) ÷ (10-1+1) = 170 MHz ÷ 170 ÷ 10 = 100 kHz
```

**与我的公式 `f = TIMxCLK / (PSC+1) / (ARR+1)` 完全一致。**
（但注意：这是讲师口算，CubeMX 界面上**没有**显示算出来的频率——这反而是我的卖点：CubeMX 不显示最终频率。）

### D. 附赠：「程序卡死」的画面实证

18:28 打开串口工具时 tooltip 写「未连接」，18:32 连上后 **4 秒里缓冲计数一直是 78876 没涨、接收区整片空白**。
这就是"没有新数据进来"的画面，对应讲师说的「程序卡死了」。
