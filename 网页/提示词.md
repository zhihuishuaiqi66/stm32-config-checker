# 给 Qoder 的提示词（按轮次复制）

> 用法：打开 Qoder → 新建会话 → **复制第 1 轮整段**发出去 → 看预览 → 再发第 2 轮。
> **一轮只做一件事**，别合并。

## 第 1 轮 · 骨架 + 第 1 屏（时钟台）

```
用 /sites 帮我做一个纯前端的静态网站，名字叫「能跑吗 · STM32 配置台」。

重要前提：
- 纯静态站，只用 HTML/CSS/JavaScript，不需要数据库、不需要后端。
- 所有计算都在浏览器里跑，不要调用任何接口。
- 中文界面。

这个网站给电子类专业的大学生用。他们在用 STM32CubeMX 配时钟树时，只会调到自己想要的主频，
却算不清下面这些东西实际是多少。这个工具就是帮他们算清楚，并告诉他们哪里超了。

先做首页 + 第 1 屏。

【首页】
标题：能跑吗 · STM32 配置台
副标题：算 CubeMX 不算的数，翻译它不告诉你的红字。
下面放三个大按钮进入：① 时钟台 ② 体检台 ③ 导出
再放一行小字：本工具的所有结论都标了证据来源（实测 / 手册 / 待核），不含猜测。

【第 1 屏 · 时钟台】
顶部一个芯片下拉框，只有三个选项：
- STM32F103C8T6（F1 系列）
- STM32F407ZGT6（F4 系列）
- STM32F411CEU6（F4 系列）

下面分左右两栏。

左栏是输入区（可调参数）：
- F1 系列：HSE 输入频率（8 / 16 / 25 MHz 三选一）、HSE 进 PLL 的分频（÷1 或 ÷2）、PLL 倍频（×2 到 ×16）、AHB 分频、APB1 分频、APB2 分频、USB 预分频（÷1 或 ÷1.5）、ADC 预分频（÷2/÷4/÷6/÷8）
- F4 系列：HSE 输入频率、PLLM、PLLN、PLLP（只能 2/4/6/8）、PLLQ、AHB 分频、APB1 分频、APB2 分频、ADC 预分频

右栏是实时结果区，用户改任何一个参数，右边立刻重算。要显示这些值：
SYSCLK、HCLK、PCLK1、PCLK2、USB 时钟、ADC 时钟、TIMxCLK

【最关键的显示要求】
TIMxCLK 必须单独高亮，并且写清楚：
- APB1 分频 = 1 时，TIMxCLK = PCLK1
- APB1 分频 ≠ 1 时，TIMxCLK = PCLK1 × 2（硬件自动翻倍，用户在 CubeMX 里改不了）

举例：F103 在 APB1 = ÷2 时，PCLK1 显示 36 MHz，TIMxCLK 显示 72 MHz，
并在旁边写一行小字：「这个 ×2 在 CubeMX 里没有可填的格子，只能算进去」。
这一格是全站最重要的东西。

【超限提示】
每一格数值都跟芯片上限比，超了就变红并显示上限值：
- F103C8T6：HCLK 上限 72、APB1 上限 36、APB2 上限 72、ADC 时钟上限 14、USB 要求 48
- F407ZGT6：HCLK 上限 168、APB1 上限 42、APB2 上限 84、ADC 上限 36、USB 要求 48
- F411CEU6：HCLK 上限 100、APB1 上限 50、APB2 上限 100、ADC 上限 36、USB 要求 48

【计算公式（照这个算，不要自己发挥）】
F1 系列：
  PLL 输入 = HSE ÷ (HSE 分频)
  SYSCLK = PLL 输入 × 倍频
  HCLK = SYSCLK ÷ AHB 分频
  PCLK1 = HCLK ÷ APB1 分频
  PCLK2 = HCLK ÷ APB2 分频
  USB 时钟 = SYSCLK ÷ USB 预分频
  ADC 时钟 = PCLK2 ÷ ADC 预分频

F4 系列：
  VCO 输入 = HSE ÷ PLLM        （必须落在 1~2 MHz，否则标红）
  VCO 输出 = VCO 输入 × PLLN   （必须落在 100~432 MHz，否则标红）
  SYSCLK = VCO 输出 ÷ PLLP
  HCLK = SYSCLK ÷ AHB 分频
  PCLK1 = HCLK ÷ APB1 分频
  PCLK2 = HCLK ÷ APB2 分频
  USB 时钟 = VCO 输出 ÷ PLLQ
  ADC 时钟 = PCLK2 ÷ ADC 预分频

【配色】
深色背景（#0d1117 附近），代码/数字用等宽字体，正常值浅绿或白色，
超限用红色 #ef4444，待核对用琥珀色。整体像一个工程仪表盘，不要花哨。

先只做这些，做完给我预览。
```

**第 1 轮验收点**

| 检查 | 怎么试 |
|---|---|
| 三款芯片都能选 | 切到 F103，左边参数应变成 F1 那一套 |
| 改一个数右边立刻变 | 把 F103 的 APB1 从 ÷1 改成 ÷2 |
| **PCLK1 = 36 时 TIMxCLK 必须是 72** | 这是本轮的生死线 |
| 超限变红 | F103 把 HCLK 拉到 72 以上，应立刻红 |

## 第 2 轮 A · 第 2 屏骨架 + 3 张示例规则卡

```
现在加第 2 屏「体检台」。

这一屏按「你遇到什么现象」来组织，不按配置项组织。共 17 条规则，分 5 组：
A 组 · 烧进去了，板子没反应（4 条）
B 组 · 第二次就下不进去了（2 条）
C 组 · 灯不亮 / 引脚不听使唤（4 条）
D 组 · 能跑，但数值不对（3 条）
E 组 · 红色和灰色：CubeMX 到底在提醒什么（4 条）

每张规则卡有 6 个字段，按这个顺序：
1. 判定（怎么算出来它有问题）
2. 你会看到（板子上的真实现象）
3. 怎么办（具体改成几）
4. 错因（为什么会这样）
5. 自测（一个问题和答案，答案默认折叠，点击才展开）
6. 出处（这条结论的证据来源）

【重要】第 5 个字段「自测」，答案必须默认折叠。
这是这个网站的学习设计：先让用户自己猜会怎样，点开才看到答案。

【重要】第 6 个字段「出处」，用带颜色的标签区分：
- 【实测·自己板子】绿色 —— 我们在真实芯片上跑过
- 【实测·CLI】蓝色 —— 本机 CubeMX 命令行回读
- 【实测·库】蓝色 —— CubeMX 器件库文件
- 【手册】灰色 —— ST 参考手册
- 【待核】琥珀色 —— 还没验证，如实标出来

先做骨架 + 下面这 3 张卡作为模板，其余的先留占位：

卡片 1：❌ 10 · 定时器时钟翻倍（硬件自动，用户改不了）
判定：APB1 或 APB2 的分频不等于 ÷1 时，硬件自动把定时器时钟翻倍：TIMxCLK = PCLK × 2。
你会看到：定时器/PWM 的频率比按 PCLK 算出来的快一倍——你以为按 PCLK 算出 1kHz，实际是 2kHz。
这件事已经在我们自己的板子上量过了：F103（PCLK1 = 36MHz、APB1 ÷2）把 TIM3 配成 PSC=7199 / ARR=9999，
实测 2 个周期 = 2000ms → TIM3CLK 确实是 72MHz；F407（PCLK1 = 42MHz、APB1 ÷4）配 PSC=8399 / ARR=9999，
同样实测 2000ms → TIM3CLK 84MHz。两颗芯片、两个不同分频值，都精确等于 2000ms。
怎么办：算 PSC/ARR 时用 ×2 后的定时器时钟，不要用 PCLK。
错因：定时器挂在 APB 总线上，但它内部要按「总线时钟的 2 倍」来数数才能做到高分辨率。ST 把它做成硬件自动：只要 APB 分频不是 1，定时器时钟就自动 ×2。这个倍频器在时钟树图上画着，但没有可填的格子——你改不了它，只能算进去。
自测：Q：F103 的 APB1 用 ÷2，PCLK1 = 36MHz，挂在上面的定时器时钟是多少？
答案：72MHz（36 × 2），不是 36。我们在自己板子上实测：TIM3 配 PSC=7199/ARR=9999，2 个周期正好 2000ms，只有 72MHz 才对得上。
出处：【实测·自己板子】F103 与 F407 各实测定时器周期 2000ms；【手册】RM0008 / RM0090 定时器时钟。

卡片 2：❌ 4 · ADC 时钟超上限
判定：ADC 时钟 = PCLK2 ÷ ADC 预分频（÷2 / ÷4 / ÷6 / ÷8），结果和上限比：F103 是 14MHz，F407 和 F411 都是 36MHz。
你会看到：可能什么异常都没有——这才是最危险的。
我们在 F103（ADC 时钟 36MHz，超上限 2.6 倍）和 F407（42MHz）上各采 48 次芯片内部 1.2V 基准：
F103 均值 1499 对 1495、峰峰 7 对 5；F407 均值 1484 对 1482、峰峰 7 对 9——读数几乎没有变化。
怎么办：F103 在 PCLK2 = 72MHz 时，÷2 = 36 超、÷4 = 18 还超，必须 ÷6 = 12（或 ÷8 = 9）才合规；
F407 在 PCLK2 = 84MHz 时，÷2 = 42 仍超 36，要往 ÷4 = 21 或 ÷6 = 14 走。
错因：ADC 是模拟电路，采样保持之后要做 12 位逐次逼近，每一位都要固定时间比较。时钟太快，比较器还没比完就进下一位。
但要注意：超出规格不等于立刻坏，ST 只是不再保证精度——所以它查不出来，最容易被埋在项目里。
自测：Q：ADC 时钟超过数据手册上限，板子会立刻坏吗？
答案：不会。我们实测两颗芯片超限后读数几乎没变化。但这不代表没问题——ST 不再保证精度，什么时候翻车取决于信号源阻抗和你的精度要求。
出处：【实测·自己板子】F103 ADCCLK 36MHz、F407 ADCCLK 42MHz 采内部基准无显著变化；【手册】RM0008 ADCCLK 最大 14MHz、RM0090 最大 36MHz。

卡片 3：❌ 17 · 烧录显示成功，但板子像没烧进去（其实没复位）
判定：烧录工具报了 Download verified successfully，但板子行为没有任何变化——串口没输出、LED 不闪。
先按顺序查三件事：① 烧完有没有复位；② BOOT0 是不是被拉高；③ 程序有没有卡在 Error_Handler。
你会看到：跟完全没烧进去一模一样。
我们烧 F103 时就是这种情况：工具报 verified successfully，但紧接着去读芯片内存，
读出来还是上一份程序的残留数据，新固件连一行都没执行；手动复位一次，结果立刻就出来了。
怎么办：烧完按一下板上 RESET 或断电重上电再看；确认 BOOT0 跳线在 0 侧；
如果复位后还是不动，去查 HSE 是否起振。
错因：「烧录成功」和「程序在跑」是两件独立的事。SWD 烧录只负责把数据写进 Flash，不负责让 CPU 从头执行一遍。
至于烧完要不要自动复位、怎么复位，取决于烧录器和它的参数，不是芯片决定的。
自测：Q：烧录工具提示 verified successfully，串口却一个字都没有，最先该查什么？
答案：先按一下 RESET（或断电重上电）——烧录成功只代表 Flash 写对了，不代表 CPU 已经重新启动。
出处：【实测·自己板子】F103 烧录后未自动复位，读回 RAM 仍是旧程序数据；手动复位后立即正常。

先做这些，做完给我预览。
```

## 出问题怎么描述

**不要**说「不好看」「不对」，要说具体现象：

| 你看到的 | 你就这样说 |
|---|---|
| 某一格数字是错的 | 「F103 选 HSE 8MHz、÷1、×9 的时候，SYSCLK 显示成 xxx，应该是 72MHz」 |
| 少了东西 | 「体检台只有 12 张卡，应该有 17 张」 |
| 位置不对 | 「TIMxCLK 应该更醒目，现在跟其他数字一样大小」 |
| 打不开 / 白屏 | 「预览是白屏，控制台好像报错了」（把报错截图发它） |

**原则：给现象 + 给期望值。** 越具体，它改得越准。
