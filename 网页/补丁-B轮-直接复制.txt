❌ 1 · SYSCLK 超频（主频拉到超过芯片上限）

**判定**：把时钟树算到底的 SYSCLK 拿去和上限比：F103 72 / F407 168 / F411 100 MHz【实测·库】。F1 的算法是（HSE ÷ PLLXTPRE，或 HSI÷2）× PLLMUL；F4 的算法是 VCO_in = HSE ÷ PLLM、VCO_out = VCO_in × PLLN、SYSCLK = VCO_out ÷ PLLP【手册】。  
**你会看到**：点 GENERATE CODE 时弹出 `IP not ready for code generation: Clock`，代码生成失败；但时钟树里照样显示你填的超频值，不自动降频【实测：F411 超上限时生成被拦、界面不降】。如果绕过这一步、或工程是旧的，烧进板子就是"不按预期跑"【待核：未上板复现】。  
**怎么办**：把乘数降回来。F411 的 PLLN 从 336 改回 200 → 100MHz，正好压在上限【实测】；F103 把 HSE ÷1 送进 PLL、PLLMUL 改成 ×9 → 72MHz（改成 ÷2 ×9 就是 36MHz）【实测】。  
**错因**：SYSCLK 是芯片的总节拍，CPU、Flash 取指、总线全按它走。数据手册写的 72/168/100 是"保证能正常工作的上限"，不是建议值——超了，Flash 等待周期档位、PLL 锁定范围都开始不保证，取回来的指令可能是错的。所以超频的后果不是"跑快点"，是"跑飞"；CubeMX 只是个计算器，它算得出数不代表芯片受得住。  
**自测**：Q：F411 用 25MHz 晶振、PLLM=25、PLLN=200、PLLP=2，SYSCLK 是多少？能不能生成代码？　<details><summary>答案</summary>A：VCO_in = 25÷25 = 1MHz → VCO_out = 200MHz → SYSCLK = 200÷2 = 100MHz，正好等于上限，合法、可以生成【实测：PLLN=200 → 100MHz；合规即可生成】。</details>  
**出处**：【实测·库】三款上限 72 / 168 / 100；【实测】F411 PLLN=200 → 100MHz、PLLN=192 → 96MHz；F103 HSE ÷1×9 = 72、÷2×9 = 36；【实测】SYSCLK 超限时生成报 `IP not ready for code generation: Clock`，时钟树不自动降频；【手册】数据手册"最大主频"、RM0090 的 PLL 公式与 PLLP 取值；【推断】PLLN=336 → 168MHz（25÷25×336÷2 = 168）；【待核】超频配置烧进板子的实际表现。

❌ 7 · BOOT0 当普通 IO（板子上电从"错的存储器"启动）

**判定**：功能落在 BOOT0 上（按键、LED、串口），或 BOOT0 在上电瞬间被外设拉高。CubeMX 器件库里 BOOT0 是启动脚，不计入可分配的普通 IO（F103 的 37 个里没有它）【实测·库】。  
**你会看到**：程序上电不跑——芯片从系统存储器启动，停在等串口下载的状态；按一下复位有时又能跑【待核：三条视频都没演示】。  
**怎么办**：BOOT0 还给启动电路：按板子原理图接下拉到地，别在 CubeMX 里把它配成外设；按键/灯换一个普通 IO。  
**错因**：上电或复位的一瞬间，芯片会"看一眼"BOOT0 的电平，据此决定从哪块存储器取第一条指令——0 从 Flash（你的程序），1 从系统存储器（ST 内置的串口下载程序）【手册】。这个锁存只在上电那一瞬间发生，之后你在程序里怎么改都晚了，所以"程序里点灯"永远等不到。它不是可分配的外设脚，是"开机开关"。  
**自测**：Q：板子上电后程序不跑、串口没输出，但按一下复位又能跑，先怀疑哪里？　<details><summary>答案</summary>A：先怀疑 BOOT0 上电时被拉高或悬空，芯片从系统存储器启动；查 BOOT0 的下拉电阻【手册；具体表现待核】。</details>  
**出处**：【手册】RM0008 启动配置（BOOT0/BOOT1 决定 Flash / 系统存储器 / SRAM）；【实测·库】BOOT0 列为启动脚、不计入 37 个可用 IO；【推断】"上电不跑、复位能跑"的机制；【待核】三条视频都没演示这个现象。

❌ 8 · 选了 HSE 但晶振脚被占

**判定**：RCC 里 HSE 选了 Crystal/Ceramic Resonator，但主晶振脚已被别的功能占用：F103 是 PD0/PD1，F407 和 F411 是 PH0/PH1；开了 LSE 还要算上 PC14/PC15【实测·库】。  
**你会看到**：引脚图上这对脚立刻变绿，标上 `RCC_OSC_IN` / `RCC_OSC_OUT`（开了 LSE 则是 `RCC_OSC32_IN/OUT`）；你在别处再点这个脚就冲突；时钟树里 HSE 那格可能灰着改不动【待核：该界面表现未逐帧截到】；或者代码里时钟初始化卡在超时等待，串口一个字都不打【待核：未上板复现】。  
**怎么办**：两条路——把占脚的功能挪走（视频里老师点开 PC14 看到第一项就是 RCC_OSC32_IN，于是把 LED 改到 PC13）【视频B@16:18】；或者干脆关掉 HSE/LSE，用内部 HSI（代价：F103 主频最高 64MHz，见第 16 条）。  
**错因**：晶振脚在封装里直接连着芯片内部的振荡器电路，它的"第一职业"就是接晶振。RCC 一旦把 HSE 打开，CubeMX 就把这一对脚锁给 RCC，别的功能再点它就是抢同一个物理脚。晶振起不来 → PLL 拿不到输入 → 后面整棵时钟树全是空算，芯片停在等就绪。  
**自测**：Q：F103 想把 LED 接 PC14，同时还要开 LSE 跑 RTC，行不行？　<details><summary>答案</summary>A：不行。PC14 是 LSE 的 OSC32_IN【视频B@09:18】，开了 LSE 就归 RCC。视频里老师正是看到 PC14 下拉第一项是 RCC_OSC32_IN，才把 LED 改到 PC13【视频B@16:18】。</details>  
**出处**：【视频B@06:24】HSE 改 Crystal 后 PD0/PD1 立刻变绿标 RCC_OSC_IN/OUT；【视频B@09:18】LSE 一开 PC14/PC15 变绿标 RCC_OSC32_IN/OUT；【视频B@16:18】点开 PC14 下拉第一项就是 RCC_OSC32_IN，老师因此改用 PC13；【实测·库】三款主晶振脚 / 低速晶振脚如上；【待核】上板卡死的具体表现。

❌ 16 · RCC 里没开 HSE 就用 PLL（主频顶到 64 就上不去）

**判定**：主时钟用了 PLL，但 RCC 的 High Speed Clock (HSE) 还是 Disable——PLL 的输入只能落回内部 HSI。注意：**CubeMX 新建工程默认就是 HSI + PLL 关 + HSE Disable，不是"72MHz 全绿"**【实测】。  
**你会看到**：HSE 那一格是灰的；PLL Source 只能选 HSI，前面还挂着一个 ÷2，输入显示 4MHz；HCLK 最高只到 64MHz，72 怎么调都出不来【实测：默认态与 HSI 参数；64 为推断：4×16】。  
**怎么办**：先到 RCC 把 HSE 从 Disable 改成 Crystal/Ceramic Resonator，再回时钟树把 PLL Source 选成 HSE；F103 要跑满 72，就是 HSE 8MHz ÷1 ×9【实测】。  
**错因**：F1 的 PLL 只有两个输入源：HSE（外部晶振，可再 ÷1 或 ÷2）和 HSI÷2。HSI 是芯片内部 RC 振荡器，出厂 8MHz、精度差；进 PLL 前固定 ÷2，只剩 4MHz。PLL 倍频上限 ×16，所以天花板是 4×16 = 64MHz——这是硬约束：缺了外部晶振，72MHz 在物理上就不成立。F4 同理，PLL 输入要靠 HSE ÷ PLLM 落进 1~2MHz，HSI 那条路精度不够，要 USB 这种精确 48MHz 的功能更别想。  
**自测**：Q：F103 没焊外部晶振、只开 HSI，PLL 倍频拉到最大能到多少？为什么到不了 72？　<details><summary>答案</summary>A：8MHz ÷2 = 4MHz，×16 = 64MHz；72 需要 HSE 8 ÷1 ×9 = 72，没有外部晶振就凑不出来【手册 + 推断：4×16 = 64】。</details>  
**出处**：【实测】新建工程默认 HSI 8MHz（F4 16MHz）/ PLL 关 / HSE Disable；HSI 8MHz、进 PLL 前固定 ÷2、PLL 倍频 ×2~×16；F103 HSE ÷1×9 = 72；【视频B@05:24→06:24】RCC 页 HSE 从 Disable 改成 Crystal/Ceramic Resonator 的完整动作；【视频B@10:00 一带】默认状态 PLL 源是 HSI、前面一个 ÷2、输入为 4；【视频A@11:15–11:35】HSI 进 PLL 前固定 ÷2（画面蓝色 /2）；【手册】RM0008 时钟树；【推断】64 = 4×16；【待核】上板实际最高主频未测。

❌ 6 · 调试脚被占用（SWD 被改成别的功能）

**判定**：PA13/PA14 被配成别的功能，或者 SYS 的 Debug 不是 Serial Wire——这两根就是下载/调试用的 SWD 线【实测·库】。  
**你会看到**：第一次烧完还能连；改完再烧，烧录软件报"找不到目标 / No target connected"，电脑连不上芯片，板子还在跑上一次的程序【待核：与第 13 条同一现象，本轮未上板复现】。  
**怎么办**：PA13/PA14 让给 SWD（SYS → Debug 选 Serial Wire），要当 IO 就换脚；已经连不上的，按老师说的用串口方式重刷一遍。  
**错因**：SWD 是两线调试口：SWDIO 走 PA13、SWCLK 走 PA14。程序一旦把这两脚改成普通输出，调试模块就没了对外通路；下次烧录器连上来，芯片已经"不在听"——这叫把梯子踢了，人还在楼上。所以这两脚永远要留给调试，别拿它点灯。  
**自测**：Q：把 PA13 配成 GPIO 用来点灯，会有什么后果？　<details><summary>答案</summary>A：第一次能烧，之后烧录器连不上——SWD 两线被占，调试口没了；点灯请换脚【与视频B@07:01 同一机制；上板表现待核】。</details>  
**出处**：【视频B@07:01】原话「如果你这个地方选 No Debug……会导致你的芯片程序只能下载一次，第二次下不进去了……」；【视频B@06:54–07:18】Serial Wire 时 PA13/PA14 变绿标 SWDIO/SWCLK，改回 No Debug 标注立刻消失；【实测·库】三款 SWD 都是 PA13/PA14；【待核】"找不到目标"的报错原文没截到。

❌ 13 · Debug 选 No Debug（程序只能下载一次）

**判定**：SYS → Debug 这一格是 No Debug，没有选 Serial Wire。  
**你会看到**：第一次下载正常、程序也能跑；第二次按下载，烧录器连不上——就是老师说的"只能下载一次，第二次下不进去了"。  
**怎么办**：SYS → Debug 改成 Serial Wire，重新生成代码、再烧一次；已经锁住的，用串口烧录方式救回来。  
**错因**：Debug 这一项决定芯片给"下载/调试"留哪套口：JTAG、Serial Wire、还是全不留（No Debug）。选了 No Debug，生成的初始化代码会把调试口的脚全交还给 GPIO、调试模块关掉。下次烧录器想通过 SWD 说话，芯片已经没有这个口了——"只能下载一次"就是这么来的。  
**自测**：Q：老师说的"芯片程序只能下载一次"，是哪一个选项选错了？　<details><summary>答案</summary>A：SYS → Debug 选了 No Debug；改成 Serial Wire 就恢复【视频B@07:01】。</details>

❌ 9 · 同一引脚被两个外设抢

**判定**：两个功能点名同一个引脚。芯片里每个脚能接哪几个外设是定死的，同一时刻只能开一个（F4 看 AFR 复用功能选择，F1 看各外设配置位 + AFIO 重映射）【手册】。  
**你会看到**：刚配好一个功能，另一个悄悄被顶掉、引脚变回黄色；或者代码里一个外设没初始化，上板一个正常、另一个没反应【待核：CubeMX 弹窗原文未逐帧截到】。  
**怎么办**：换脚或换外设实例。例：F103 的 PA2 上，USART2_TX 和 TIM2_CH3 是同一个脚的两个候选【实测·库】，两个都要用就有一个得换脚。  
**错因**：芯片内部每个引脚只有一条"通道"能接到外设，走哪条由复用功能选择寄存器决定，一个位置只能填一个外设编号。你配第二个，就把第一个的编号覆盖了——脚上的信号没了内部通路，前一个外设看起来像"没初始化"。这不是资源不够，是"一个插座只插一个插头"，后插的把先插的顶掉。  
**自测**：Q：PA2 上同时要 USART2_TX 和 TIM2_CH3，能都工作吗？　<details><summary>答案</summary>A：不能。PA2 的候选功能里两者并列【实测·库】，同一时刻只能选一个；要两个都跑，其中一个必须换脚。</details>  
**出处**：【实测·库】PA2 的复用功能列表 = ADC1_IN2 / ADC2_IN2 / TIM2_CH3 / USART2_TX（一个脚挂着四个候选）；【手册】RM0008 复用功能表与 AFIO；【待核】顶掉时的界面提示原文。

❌ 11 · 引脚不属于当前封装（F411 没有 PB11）

**判定**：功能落到当前封装没有的引脚上。可用 IO：F103 LQFP48 = 37 个、F407 LQFP144 = 114 个、F411 UFQFPN48 = 36 个；F411 的 UFQFPN48 没有 PB11【实测·库】。  
**你会看到**：在 CubeMX 引脚图上根本找不到这个脚（不是灰，是没有）；板上也焊不出这根脚；代码里对它的操作落不到硬件上。  
**怎么办**：换成当前封装里有的脚，或者换封装/换芯片；工具在用户点名时直接说"这颗封装没有这个脚"。  
**错因**：芯片裸片里有这个引脚，不代表封装（黑色塑封壳 + 那几十根金属脚）把它引出来了。封装越小能引出的脚越少，芯片内部的功能被"关在壳里"。所以能不能用，取决于"这颗芯片 + 这个封装"的组合，不是只看芯片型号的功能表。  
**自测**：Q：F411CEU6（UFQFPN48）能用 PB11 吗？　<details><summary>答案</summary>A：不能，这颗封装的引脚表里没有 PB11（可用 IO 只有 36 个）【实测·库】；换脚或换封装。</details>  
**出处**：【实测·库】本机 CubeMX 6.15.0 器件库：F411 的 UFQFPN48 引脚表里没有 PB11（可用 IO 36）；F103 LQFP48 = 37、F407 LQFP144 = 114；【手册】ST 数据手册的引脚定义表。

❌ 12 · JTAG 脚当 IO 用

**判定**：用 PA15 / PB3 / PB4（或 PA13/PA14）当普通 GPIO，而 SYS 的 Debug 还停在 JTAG。  
**你会看到**：这几个脚配成输出后没反应、电平一直不变，换成别的脚就正常；把 Debug 改成 Serial Wire 之后，这几个脚才开始听使唤【待核：未上板复现】。  
**怎么办**：SYS → Debug 选 Serial Wire（只占 PA13/PA14 两线，把 PA15/PB3/PB4 放出来），或者把这几个功能换到别的脚。  
**错因**：芯片上电默认把 JTAG 全功能打开，占 5 个脚（PA13/PA14/PA15/PB3/PB4）。JTAG 模块没关，这 5 个脚就归调试口管，你的 GPIO 配置写下去不生效——像房间还被占着，你贴的标签没人看。改成 Serial Wire 只留两线，剩下三个才交还给你。  
**自测**：Q：为什么把 Debug 从 JTAG 改成 Serial Wire 之后，PB3 突然能点灯了？　<details><summary>答案</summary>A：JTAG 占 5 个脚，Serial Wire 只占 PA13/PA14；改成 Serial Wire 后 PB3/PB4/PA15 被放出来归 GPIO【实测·库 + 手册】。</details>  
**出处**：【实测·库】三款 JTAG 脚都是 PA13/PA14/PA15/PB3/PB4；【手册】RM0008 的 AFIO 重映射与 JTAG 禁用；【待核】PB3/PB4 作 GPIO 的上板表现未复现。

❌ 15 · GPIO 开漏输出驱动 LED（灯不亮）

**判定**：GPIO 设成 Output Open Drain，而 LED 是"引脚→电阻→地"的接法——这种接法要引脚输出高电平才亮。  
**你会看到**：灯不亮（或一直暗着），万用表/示波器量这个脚永远是低；改成 Push Pull 立刻正常。  
**怎么办**：GPIO mode 从 Output Open Drain 改回 Output Push Pull。  
**错因**：开漏输出只有一个"往下拉"的开关（N 沟道 MOS 接地），没有"往上推"的管子。它输出"1"其实是"松手"，靠外部上拉电阻把电平拉高；没有外部上拉就是高阻态，灯拿不到电流。推挽有上下两个管子，能真正把脚推到高电平。  
**自测**：Q：LED 一头接 3.3V、一头接引脚（低电平点亮），开漏能点亮吗？　<details><summary>答案</summary>A：能——开漏能把脚拉到低，灯就亮（这也正是开漏擅长的方向）。但如果 LED 是"引脚→电阻→地"（要高电平点亮），开漏就点不亮。关键看 LED 接法。</details>  
**出处**：【视频B@18:34】老师把 GPIO mode 切成 Output Open Drain 演示、18:48 又切回 Push Pull；【视频B@17:33–18:36 台词】推挽有驱动能力、能强制拉高拉低，开漏没有驱动能力、要变高必须外部加上拉；【手册】RM0008 GPIO 输出模式。


【D 组 · 能跑，但数值不对】

❌ 5 · USB 时钟不是 48MHz

**判定**：USB 时钟 ≠ 48MHz。F103：USB = PLLCLK ÷ USB 预分频，这一档只有 ÷1（默认）和 ÷1.5 两个选择，要 48 必须手动选 ÷1.5 且 PLL 正好 72MHz【实测 + 手册】；F4：USB = PLL 的 VCO 输出 ÷ PLLQ，要 48 就得让 VCO_out ÷ PLLQ = 48【手册】。  
**你会看到**：插上电脑认不到设备、虚拟串口不出来、枚举反复重试【待核：未上板复现】。F103 时钟树上 USB 那格写的 72 是 PLL 输出，不是 USB 实际频率；USB 分频器灰色只代表 USB 没开，不代表 0MHz【视频B@12:33】。  
**怎么办**：F103 两步走——先把 PLL 调到 72（HSE ÷1 ×9），再把 USB 预分频从默认的 ÷1 改成 ÷1.5，72 ÷ 1.5 = 48；F411 在 25MHz 晶振下二选一——PLLN=192 + PLLQ=4 → 96MHz 且 USB 48【实测】，或者 PLLN=200 → 100MHz 但 PLLQ=4 只有 50，USB 保不住【实测】。  
**错因**：USB 全速口是 12Mbps 的串行通信，芯片内部要一个正好 48MHz 的时钟去采每一位；差一点就采错位，电脑那边握手失败 → 认不到设备。F103 只有 PLLCLK 一个源，72 ÷ 1.5 = 48 是唯一走法，默认的 ÷1 会把 72MHz 直接送进 USB（超上限）。F4 多一个 PLLQ 通道，48 由 VCO_out ÷ PLLQ 凑，所以 PLLN 和 PLLQ 要一起配。  
**自测**：Q：F103 的 PLL 已经调成 72MHz，USB 为什么还是认不到？　<details><summary>答案</summary>A：因为 USB 预分频还停在默认的 ÷1（72MHz 直进 USB，超了 48 上限）。手动改成 ÷1.5 → 72÷1.5 = 48MHz 才行【实测：档位只有 1 和 1.5；推断：72÷1.5 = 48】。</details>  
**出处**：【实测】F103 的 USB 预分频只有 ÷1（默认）/÷1.5 两档；【实测】F411：PLLN=192/PLLP=2/PLLQ=4 → 96MHz + USB 48；PLLN=200 → 100MHz、PLLQ=4 → 50；【实测】F407：PLLM=25/PLLN=336/PLLP=2/PLLQ=7 → 168MHz、USB 48；【手册】RM0008（F103 USB = PLLCLK÷1.5）、RM0090（F4 USB = VCO÷PLLQ）；【视频B@12:33】灰格含义；【推断】72÷1.5 = 48、÷1 时 72 超 48 上限；【待核】上板枚举表现、CubeMX 对 F103 "USB=72" 是否变红。

❌ 14 · HSE 频率和板子实际晶振不一致（8 vs 25）

**判定**：CubeMX 里 RCC 填的 HSE 输入频率，和板子上那颗晶振不是同一个数。默认值：F103 8MHz、F407 25MHz、F411 25MHz【实测】。  
**你会看到**：串口全是乱码、延时明显变长或变短、USB 认不到、定时器频率不对；时钟树上每个数字都"对"，因为它们全按你填错的晶振算。**【实测·自己板子】**把 8MHz 的板子按 CubeMX 默认 25MHz 配，PLL 输入会变成 25÷8 = 3.125MHz，超出 1~2MHz 规格 → **PLL 锁不上，芯片直接不启动**（不是跑偏，是根本不跑）。  
**怎么办**：看板子上晶振的丝印，把 RCC 的 HSE 输入频率改成实际值（F407 国内板多是 8MHz，就从默认 25 改成 8），整棵树会跟着重算。  
**错因**：整棵时钟树都是从 HSE 这一个数乘除出来的，而这个数是"你告诉 CubeMX 的"，不是它自己量的。填 25 实际 8，所有倍频分频都按 25 算：主频、串口波特率、定时器、USB 全部按 8/25（约 0.32 倍）偏。波特率一偏，串口收到的每一位都对不上，就是乱码。  
**自测**：Q：板子上是 8MHz 晶振，CubeMX 里 HSE 填了 25，串口会怎样？　<details><summary>答案</summary>A：实际波特率变成设定值的 8/25 ≈ 0.32 倍，收发每一位错位，串口乱码；看晶振丝印改成 8 就对【推断：8÷25 ≈ 0.32】。</details>  
**出处**：【视频B@09:29】原话「这个 8 是可以改的……如果你用到一些其他开发板，你可能需要去查一下那个硬件电路，以防止这里晶振频率变了」；【实测】三款默认 HSE 8 / 25 / 25；【推断】波特率按 8/25 偏；【实测·自己板子】鹿小班 F407ZGT6 核心板（LXB407ZG-P1 V2.0）原理图 X2 = **8MHz** 晶振；固件按 PLLM=8 配置后 HSERDY 正常、跑到 168MHz 并成功输出报告——若晶振真是 25MHz，VCO 输入会到 3.125MHz 锁不上，芯片根本跑不起来，**能跑通本身就是 8MHz 的证明**。【待核】改错后串口乱码的具体表现未逐条复现。

❌ 2 · APB1 超限

**判定**：算出来的 PCLK1 大于上限（F103 36 / F407 42 / F411 50 MHz）【实测·库】。  
**你会看到**：PCLK1 那个数字变成品红色，APB1 预分频那一格也是品红，Clock Configuration 标签页前冒出一个品红小圆点，Resolve Clock Issues 按钮从灰变可点；但界面不告诉你该改成几、改完别处会变成多少【视频B@14:03–15:00】。  
**怎么办**：APB1 预分频加大一档：F103 从 ÷1 到 ÷2（PCLK1 72→36）；F407 用 ÷4 → 42；F411 用 ÷2 → 50【实测】。代价是挂在 APB1 上的外设时钟跟着降，定时器还要再翻倍一次（见第 10 条）。改 HCLK 回车 CubeMX 会自动求解（Searching Solution），但它只帮你凑合法，不帮你算代价【实测】。  
**错因**：APB1 是低速外设总线，串口 2~5、I2C、TIM2~7 这些挂在上面。芯片工艺决定了它跑不到 CPU 那么快，超了不是"更快"，是总线时序不满足、外设读写可能出错。工具只标红不自动改，因为它不知道你要保哪些外设——分频一改，挂在上面的所有外设时钟一起降。  
**自测**：Q：F103 的 HCLK = 72MHz，APB1 停在 ÷1，PCLK1 是多少？合规吗？　<details><summary>答案</summary>A：72MHz，超了 36MHz 上限，必须改成 ÷2（72÷2 = 36，正好卡上限）【实测】。</details>  
**出处**：【视频B@14:03–15:00】选中 PLLCLK 后 PCLK1=72 立刻品红、标签页出现品红点、Resolve 按钮可点；【视频B@14:12】原话「这边出现红色了，红色的就有问题」；【视频B@14:51】原话「他这里写着是 36 兆赫兹是最大值……咱们直接除以 2」；【实测·库】三款 APB1 上限 36 / 42 / 50；【实测】改 HCLK 回车触发自动求解。

❌ 3 · APB2 超限

**判定**：算出来的 PCLK2 大于上限（F103 72 / F407 84 / F411 100 MHz）【实测·库】。  
**你会看到**：PCLK2 数字变品红、APB2 预分频那一格变红，和 APB1 超限是同一套提示；F407 上要特别小心：HCLK 拉到 168，APB2 上限只有 84，分频停在 ÷1 就是 168。  
**怎么办**：APB2 预分频 ÷1 → ÷2（F407：168→84，正好压到上限）。改完挂 APB2 的 ADC、串口 1 时钟都会变，ADC 那条要回头查（见第 4 条）。  
**错因**：APB2 是高速外设总线，ADC、串口 1、SPI1、TIM1/8 都挂在上面。它的上限比 APB1 高一倍，但也不是和 CPU 同频：F407 HCLK 168 时 APB2 最多 84，所以必须 ÷2。关键是——**ADC 就挂在 APB2 上**，你在这里按下的分频，会直接改掉第 4 条要算的 ADC 时钟。  
**自测**：Q：F407 的 HCLK = 168MHz，APB2 用 ÷1 行不行？　<details><summary>答案</summary>A：不行，168 > 84 上限；改成 ÷2 → 84 正好合规【实测】。</details>  
**出处**：【实测·库】三款 APB2 上限 72 / 84 / 100；【视频B@14:12】同一套红色提示机制；【视频B@14:29】原话「它这里显示最大是 72 兆赫兹」——PCLK2 旁印的就是 72 MHz max；【视频B@14:51】同类超限的处置就是"除以 2"；【手册】RM0008/RM0090 总线与 ADC 挂载关系。
