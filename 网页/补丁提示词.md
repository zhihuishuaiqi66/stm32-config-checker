## 第 A 轮 · 加第 4 屏「体检台」+ 学习模式（最重要）

```
在现有站点上加一个新标签页，叫「体检台」，放在「自查」和「导出」之间。

这一屏和「自查」不一样：
- 「自查」是自动检查你当前配的参数，机器告诉你能跑不能跑。
- 「体检台」是按「你板子上出现什么现象」来查，17 条规则分 5 组，
  每条卡片的答案默认折叠，用户先自己想，点了才展开。

这是我们这个作品和普通查表工具的根本区别，请务必做对。

【顶部】
一个开关，标签写「学习模式」，默认打开。
- 打开时：所有规则卡的自测答案默认折叠，点一下才展开。
  开关旁边显示一行小字：「学习模式已开：先自己猜，再点开看答案。」
- 关闭时：所有答案默认展开，变成普通查阅模式。

【正文】
17 条规则卡，分 5 组，分组标题：
A 组 · 烧进去了，板子没反应
B 组 · 第二次就下不进去了
C 组 · 灯不亮 / 引脚不听使唤
D 组 · 能跑，但数值不对
E 组 · 红色和灰色：CubeMX 到底在提醒什么

每张卡片的结构：
1. 编号 + 标题
2. 判定
3. 你会看到
4. 怎么办
5. 错因
6. 自测（一个问题，答案折叠）
7. 出处（带颜色的标签）

【出处标签的颜色规则】
- 【实测·自己板子】绿色 #22c55e —— 我们在真实芯片上跑过
- 【实测·CLI】蓝色 #38bdf8 —— 本机 CubeMX 命令行回读
- 【实测·库】蓝色 #38bdf8 —— CubeMX 器件库文件
- 【手册】灰色 #94a3b8 —— ST 参考手册
- 【待核】琥珀色 #f59e0b —— 还没验证

先做这一屏的骨架 + 下面 3 张卡，其余我下一轮给你：

卡片 A1：❌ 10 · 定时器时钟翻倍（硬件自动，用户改不了）
判定：APB1 或 APB2 的分频不等于 ÷1 时，硬件自动把定时器时钟翻倍：TIMxCLK = PCLK × 2。
你会看到：定时器/PWM 的频率比按 PCLK 算出来的快一倍——你以为按 PCLK 算出 1kHz，实际是 2kHz；定时中断也比预期来得快。
这件事已经在我们自己的板子上量过了：F103（PCLK1 = 36MHz、APB1 ÷2）把 TIM3 配成 PSC=7199 / ARR=9999，实测 2 个周期 = 2000ms → TIM3CLK 确实是 72MHz；F407（PCLK1 = 42MHz、APB1 ÷4）配 PSC=8399 / ARR=9999，同样实测 2000ms → TIM3CLK 84MHz。两颗芯片、两个不同分频值，都精确等于 2000ms。
怎么办：算 PSC/ARR 时用 ×2 后的定时器时钟，不要用 PCLK。
错因：定时器挂在 APB 总线上，但它内部要按「总线时钟的 2 倍」来数数，才能做到高分辨率。ST 把它做成硬件自动：只要 APB 分频不是 1，定时器时钟就自动 ×2。这个倍频器在时钟树图上画着，但没有可填的格子——你改不了它，只能算进去。
自测问题：F103 的 APB1 用 ÷2，PCLK1 = 36MHz，挂在上面的定时器时钟是多少？
答案：72MHz（36 × 2），不是 36。我们在自己板子上实测过：TIM3 配 PSC=7199 / ARR=9999，2 个周期正好 2000ms，只有 72MHz 才对得上。
出处：【实测·自己板子】F103 与 F407 各实测定时器周期 2000ms；【手册】RM0008 / RM0090。

卡片 A2：❌ 4 · ADC 时钟超上限
判定：ADC 时钟 = PCLK2 ÷ ADC 预分频（÷2/÷4/÷6/÷8），结果和上限比：F103 是 14MHz，F407 和 F411 都是 36MHz。
你会看到：可能什么异常都没有——这才是最危险的。我们在 F103（ADC 时钟 36MHz，超上限 2.6 倍）和 F407（42MHz）上各采 48 次芯片内部 1.2V 基准：F103 均值 1499 对 1495、峰峰 7 对 5；F407 均值 1484 对 1482、峰峰 7 对 9——读数几乎没有变化。
怎么办：F103 在 PCLK2 = 72MHz 时，÷2 = 36 超、÷4 = 18 还超，必须 ÷6 = 12（或 ÷8 = 9）才合规；F407 在 PCLK2 = 84MHz 时，÷2 = 42 仍超 36，要往 ÷4 = 21 或 ÷6 = 14 走。
错因：ADC 是模拟电路，采样保持之后要做 12 位逐次逼近，每一位都要固定时间比较。时钟太快，比较器还没比完就进下一位。但超出规格不等于立刻坏，ST 只是不再保证精度——所以它查不出来，最容易被埋在项目里。
自测问题：ADC 时钟超过数据手册上限，板子会立刻坏吗？
答案：不会。我们实测两颗芯片超限后读数几乎没变化。但这不代表没问题——ST 不再保证精度，什么时候翻车取决于信号源阻抗和你的精度要求。
出处：【实测·自己板子】F103 ADCCLK 36MHz、F407 ADCCLK 42MHz 采内部基准无显著变化；【手册】RM0008 ADCCLK 最大 14MHz、RM0090 最大 36MHz。

卡片 A3：❌ 17 · 烧录显示成功，但板子像没烧进去（其实没复位）
判定：烧录工具报了 Download verified successfully，但板子行为没有任何变化——串口没输出、LED 不闪。先按顺序查三件事：① 烧完有没有复位；② BOOT0 是不是被拉高；③ 程序有没有卡在 Error_Handler。
你会看到：跟完全没烧进去一模一样。我们烧 F103 时就是这种情况：工具报 verified successfully，但紧接着去读芯片内存，读出来还是上一份程序的残留数据，新固件连一行都没执行；手动复位一次，结果立刻就出来了。
怎么办：烧完按一下板上 RESET 或断电重上电再看；确认 BOOT0 跳线在 0 侧；如果复位后还是不动，去查 HSE 是否起振。
错因：「烧录成功」和「程序在跑」是两件独立的事。SWD 烧录只负责把数据写进 Flash，不负责让 CPU 从头执行一遍。至于烧完要不要自动复位、怎么复位，取决于烧录器和它的参数，不是芯片决定的。
自测问题：烧录工具提示 verified successfully，串口却一个字都没有，最先该查什么？
答案：先按一下 RESET（或断电重上电）——烧录成功只代表 Flash 写对了，不代表 CPU 已经重新启动。
出处：【实测·自己板子】F103 烧录后未自动复位，读回 RAM 仍是旧程序数据；手动复位后立即正常。

做完给我预览。
```

## 第 C 轮 · 把 TIMxCLK 变成独立大格（第二重要）

```
现在改配置台的时钟树区域。

目前「定时器时钟」只是在 APB1、APB2 那两行的小字里提了一句「定时器 72 MHz」，
太不显眼了。这是全站最有价值的一个数，要单独做成一块。

在时钟树区域的最下面，SYSCLK / HCLK / APB1 / APB2 / ADC / USB 这些行之后，
单独加一块，明显比其他行大、边框更亮：

─────────────────────────────
定时器实际时钟（TIMxCLK）      72 MHz
APB1 分频是 ÷2，所以硬件自动把 PCLK1（36MHz）翻倍成 72MHz。
这一格在 CubeMX 里没有可填的地方——你改不了它，只能算进去。
─────────────────────────────

两块都显示：APB1 侧定时器、APB2 侧定时器。

规则：
- 该侧 APB 分频 = ÷1 时，TIMxCLK = 该侧 PCLK
- 该侧 APB 分频 ≠ ÷1 时，TIMxCLK = 该侧 PCLK × 2

字号要比其他结果行大一号，数值用高亮色。
如果哪一侧的定时器时钟超过了该芯片定时器上限（F103 是 72MHz、F407 是 168MHz、F411 是 100MHz），标红。

做完给我预览。
```
