## 1.1 为什么这是 StudyHack

评审最可能先问一句：

> 「这是给工程师配芯片的效率工具，跟 StudyHack 有什么关系？」

这句话必须先答；答不好，后面写得再准，也不算在这个赛道里。

**答案不是「它顺便也能帮人学习」，而是：这个产品的主干就是学习动作——把「猜」去掉，它只剩一个算得挺准的计算器，评审那句话就成立了。**

### 1.1.1 配置是题目，不是目的

学生打开它，不是为了「配完就走」，而是为了回答一个问题：**「我这样配，会发生什么？」**

- **配之前先猜**：这棵树配出来，定时器实际跑多少？ADC 会不会超？USB 认不认得到？
- **揭晓**：页面给出真实结果，并说清「是哪一格造成的」；
- **记住**：把他猜错的那几条写进错题本；
- **回来**：下次打开先考错题，答对两次才移出。

这四步是一个完整的学习闭环：**诊断 → 揭示 → 记住错题 → 复习**。配置是题目，判题才是产品。

### 1.1.2 效率工具和学习判题器，差在哪

| 维度 | 效率工具（旧定位） | 学习判题器（本节定位） |
|---|---|---|
| 度量什么 | 省了多少时间、少了多少次往返 | 原来猜错的，现在还会不会错 |
| 用户什么时候打开 | 卡住的那几分钟，用完就走 | 卡住时来一次；过几天回来复习 |
| 产品在哪一步结束 | 给出正确答案就结束 | 给出答案才开始：错题本、复习、第二次答对 |
| 正确答案怎么用 | 抄走 | 先猜、再对答案；猜错才是内容 |
| 评委当场能验什么 | 算得快不快、准不准 | 做三道题，错题本立刻多三条 |
| 归到哪个赛道 | 工程实践、效率工具 | StudyHack：学习闭环 |

### 1.1.3 闭环四步，每一步为什么是「学」

| 环节 | 学生的动作 | 页面的动作 | 为什么这一步是「学」 |
|---|---|---|---|
| ① 诊断（先猜） | 看题面，先填一个自己的答案 | 先不给答案，只给输入框或选项 | 先有自己的判断，才有落差；没有猜，后面全是「哦」 |
| ② 揭示 | 点「揭晓」 | 亮出真实结果 + 因果链（是哪一格造成的）+ 出处 | 落差被看见的那一下，才记得住 |
| ③ 记住错题 | 看自己错在哪一条 | 写进本地错题本：我的答案、正确答案、错了第几次 | 错题是「我漏了什么」的清单，不是分数 |
| ④ 复习 | 下次打开先考错题 | 只出错过的题；答对两次才移出 | 闭环在这里合上；不复习等于没学 |

### 1.1.4 「猜」在产品里的三处硬绑定

| 产品部位 | 先猜什么 | 揭晓什么 | 错题本记什么 |
|---|---|---|---|
| 三个数卡片（定时器 / ADC / 串口） | 先自己填 PSC / ARR、采样率、波特率误差 | 真实值 + 算式 + 出处 | 你算错的是哪一步（时钟来源？×2？） |
| 屏 2 体检台 | 给一个现象，先猜是哪一格配错 | 真正的原因、改哪一格、改成几 | 现象 → 原因的反查错在哪 |
| 判题卡（一道配置题） | 猜「这样配会怎样」 | 真实后果 + 证据 | 这一条认知（例：不红不等于对） |

### 1.1.5 反过来验：把「猜」拿掉会怎样

把「先猜」拿掉，这个产品还剩什么？一张能拖的时钟树，加一个会算定时器参数的网页。它有用，但它是效率工具——评审那句话就成立了。

所以「猜」不是交互装饰，是「能不能算 StudyHack」的分界线。第 2 节的降级方案（做不完时，时钟树退化成一张静态图，只保留三个数卡片和现象清单）也按这条口径落地：**屏可以少，先猜这一步不能少**——三个数卡片里先填猜测再揭晓，现象清单里先猜原因再展开。

### 1.1.6 它真的在教吗：能测的、不能吹的

站内能算的只有三件事：**错题率**（第一次答错的比例）、**复习通过率**（错题第二次答对的比例）、**隔天再答正确率**（同一道题隔一天再出）。这三样只用本地数据算，不需要服务器。

不能吹的也写在这：真实用户的学习效果现在没有样本，不承诺「提升 xx%」；「先猜后揭为什么有效」也只是产品判断【判断】，没有引学习科学文献、也没有对照实验。这两条都记在 1.10 的待核清单里。

评委不用等这些数据——**做三道题，错题本立刻多三条**，这是当场可验的；1.6 末尾一口气列了三件当场可验的事。

## 1.2 一句话：是什么、谁用、什么时候用

**3 秒版**

> 配完 CubeMX，先别急着烧进板子：猜一句「这样能跑吗」，再看答案，再把你猜错的收进错题本。

**一句话定义**

> 给电子类专业学生用的 STM32 配置判题器：配之前先猜「这样配会怎样」，揭晓真实结果，把猜错的那几条记成错题，下次回来只考错题；同时给出「改哪个、改成几」。

| 问题 | 答案 |
|---|---|
| 谁 | 电子、自动化、机电类学生，第一次独立配 STM32 的人（大二大三为主：课设、电赛、毕设） |
| 什么场景 | ① 配之前：先做题，猜「这样配会怎样」；② 点「生成」之前：对答案、看因果；③ 过几天：回来复习错题 |
| 解决什么 | 让你先猜、再揭晓；猜错的进错题本；同时告诉你「改哪个、改成几」 |
| 不是什么 | 不替代 CubeMX、不生成代码、不做仿真、不做题库 / 刷题 App（见 1.8） |

**先把七个词说清（给非本专业评委）**

| 词 | 大白话 |
|---|---|
| 晶振（HSE） | 板子上的小金属壳，给芯片打节拍；不同板子可能装 8 或 25 MHz |
| PLL 与分频 | 芯片里的变速齿轮：PLL 把晶振节拍成倍放大，分频反过来整数除小，给跑得慢的总线用 |
| 总线（APB1、APB2） | 芯片内部两条马路，各有自己的限速；超了 CubeMX 会标红【视频B@14:12】 |
| ADC | 把电压变成数字的部件，自己也有节拍上限——F103 上是 14 MHz【实测】 |
| 定时器时钟（TIMxCLK） | 定时器真正拿到的节拍。它不等于屏幕上那个 PCLK，中间还有一个硬件自动的 ×2【实测 + 视频A 字幕原话】 |
| 判题（先猜后揭） | 先让你押一个答案，再告诉你对不对。不是看完就算——先有自己的判断，错了才记得住 |
| 错题本 | 你猜错的那几条，存在你自己的浏览器里；下次打开先考它们 |

## 1.3 三个真实场景

> 三个人是按三条视频里学生的真实动作合成的典型画像，不是采访对象；动作、界面反应、老师原话都能指到分秒。这一版不写「他浪费了多少时间」——没有计时样本就不编；写的是**他错在哪一步**，而那一步有视频画面或实测支撑。

### 场景一 · 消红、收工，然后定时器跑出一倍（F103C8T6）

**人**：小周，大二自动化，第一次独立做课设。板子是 F103C8T6，8 MHz 晶振（这颗芯片在 CubeMX 里的默认值【实测】）。目标：TIM3 出 1 kHz 方波，再采一路 ADC。

| 项 | 具体发生什么 |
|---|---|
| 卡在哪一步 | ① 看到 HCLK 下印着「72 MHz max」，照视频里那句「它这里显示最大是 72 兆赫兹，那么咱们直接给它拉满」填 72【视频B@14:29】；② 回车后弹 Searching Solution，自己把 PLL 倍频和分频倒推好【视频A@00:35–01:00】；③ PCLK1 变品红——「这边出现红色了，红色的就有问题」【视频B@14:12】，旁边印着 36 MHz max，于是「咱们直接除以 2」【视频B@14:51】，红消；④ 生成、烧写、收工。 |
| 他以为 | 红消了 = 配对了 = 能跑。以后再出问题，一定是代码、传感器或者板子。 |
| 其实是 | 红色只说明「总线超了」；红消掉，只解决了界面会喊的那一类问题。影响他要的功能的两件事，界面没喊：① ADC 拿到的是 PCLK2 的 72 再 ÷2 = 36 MHz，超了 F103 的 14 MHz 上限，这一格只灰、不红、不拦生成【实测 + 视频A@12:10 画面】，改 ÷6 得 12 MHz 才合规【实测：72 ÷ 6 = 12】；② 定时器真正拿到的是 72 MHz，不是屏幕上的 36——APB 分频不是 1 时，硬件自动把定时器时钟 ×2，这个 ×2 不在任何可改的格子里【实测 + 视频A 字幕原话】。按 36 填出来的分频，实际跑是 2 kHz【推算：72,000,000 ÷ (36 × 1,000) = 2,000】。 |
| 界面没告诉他 | 灰 ≠ 安全；屏幕上的 PCLK1 ≠ 定时器拿到的时钟。 |
| 现在怎么解决 | 没解决。他认定「不红 = 对」，这个错会跟着他整个项目周期：往后每个异常都要从传感器、代码、板子重查一遍。 |

**判题卡（产品里这道题的样子）**

> **题面**：「F103，HCLK = 72、APB1 = ÷2，TIM3 要出 1 kHz。PSC 和 ARR 填几？实际会跑多少？」
> **最常见的猜法**：按屏幕上的 PCLK1 = 36 MHz 算 → PSC = 35、ARR = 999，以为正好 1 kHz。
> **揭晓**：定时器时钟其实是 72 MHz（×2 是硬件自动的）。同一组参数回代是 2,000 Hz；按 72 MHz 重算，PSC = 1、ARR = 35,999，回代正好 1,000.00 Hz【推算，算法与第 4 节 4.4.1 同一套】。
> **错题本记一条**：「屏幕上的 PCLK1 不是定时器时钟；总线分频不是 ÷1 时，定时器时钟自动 ×2，用户改不了。」

### 场景二 · 在「100 MHz」和「USB 48」之间来回试（F411CEU6）

**人**：小陈，大二，准备电赛。板子是 F411CEU6（Black Pill，板载 25 MHz 晶振，也是 CubeMX 的默认值【实测】）。他要跑满 100 MHz，同时用 USB 虚拟串口往电脑打数据。

| 项 | 具体发生什么 |
|---|---|
| 卡在哪一步 | CubeMX 按 100 MHz 自动倒推出 PLLM = 25、PLLN = 200、PLLP = 2【实测】；可 USB 不是 48 MHz——USB 取自 PLL 的中间频率 200 MHz 再除以 PLLQ：取 4 得 50【实测】，取 5 得 40【推算：200 ÷ 5 = 40】，怎么都到不了 48。他开始换参数：P 改 4？N 减小一点？每换一次，别处又不对。 |
| 他以为 | 这是「还没调对」，多试几轮总能试出来。 |
| 其实是 | 这不是手感问题，是数学问题：这组目标**无解**。要 100 MHz，中间频率只能是 100 × PLLP，而 PLLP 只能 2 / 4 / 6 / 8，又要落在 100~432 MHz 之间，所以只剩 200 和 400【手册 + 推算】；要 USB 48，中间频率又必须能被某个整数整除成 48——200 ÷ 48 和 400 ÷ 48 都不是整数【推算】。两边凑不到一起。 |
| 界面没告诉他 | CubeMX 会按 100 MHz 算出一整套 PLL 参数，但不会说「USB 这格从此无解」；它只报单格合不合法，不报「你要的这组目标凑不出来」。 |
| 现在怎么解决 | 去群里问，最常见的答复是「你 PLLQ 设错了」，但设成几才对，没人给具体数。最后只有两条路：放弃 USB 跑 100 MHz，或降到 96 MHz 保住 USB（PLLN = 192、PLLP = 2、PLLQ = 4）【实测】。 |

**判题卡**

> **题面**：「F411、25 MHz 晶振，想同时要 100 MHz 和 USB 48 MHz，能不能做到？」
> **最常见的猜法**：「能，再调调 PLLQ 就行」／「不能，但说不清为什么」。
> **揭晓**：不能。两条可选的中间频率 200、400 都不是 48 的整数倍【推算】。可行的两条路：96 MHz + USB 48（N = 192、P = 2、Q = 4，实测）、或 100 MHz 放弃 USB（PLLQ = 4 只得 50，实测）。
> **错题本记一条**：「有些目标组合本身无解；无解要能证明，不是多试几轮。」

### 场景三 · 不跑，第二次还下不进去（F407ZGT6）

**人**：小吴，大三，做毕设。板子是 F407ZGT6，三款里时钟树最复杂的一款【判断】；板载晶振到底几 MHz 他没看过（CubeMX 默认 25 MHz，而国内常见的 F407 板多为 8 MHz【实测默认值 + 待核：具体板型需对原理图】）。

| 项 | 具体发生什么 |
|---|---|
| 卡在哪一步 | 配完、生成、烧写，板子不跑；再烧一次，报错下不进去；换线、换口、换电脑都不行。搜索出来的答案互相矛盾：改 BOOT0、装驱动、勾 Reset and Run、换芯片。而他的配置里至少有一条「完全合法、却致命」的选项：SYS 里的 Debug 选成 No Debug，「会导致芯片程序只能下载一次，第二次下不进去了」【视频B@07:01 原话】。 |
| 他以为 | 编译通过 + 烧写成功 = 配置没错；问题在硬件、线材、电脑，或者芯片坏了。 |
| 其实是 | 合法性检查和可用性是两件事。No Debug 这一格 CubeMX 不拦、不红，代价是下载口被关掉——第一次下载成功，正是关掉它的那一次；之后电脑再也连不上芯片，而芯片还在跑上一次的程序。 |
| 界面没告诉他 | 「这一格合法，但会让你下次连不上。」 |
| 现在怎么解决 | 穷举 + 问人 + 刷视频。答案在视频里，但他不知道该看哪一期、看到第几分钟。 |

**判题卡**

> **题面**：「第一次能烧、程序也能跑；第二次下载报错，电脑连不上芯片。最可能是哪一格？」
> **选项**：BOOT0 / 驱动 / 晶振 / SYS → Debug。
> **揭晓**：SYS → Debug 选成了 No Debug【视频B@07:01】。改回 Serial Wire，重新生成再烧一次。
> **错题本记一条**：「合法 ≠ 可用；现象要能反查到具体的配置格。」

### 三个人卡住的是同一件事

连讲这套课的老师，开口第一句都要先安抚：「大家看到这样一框图看起来非常复杂是吗？大家不要慌」【视频B@08:36】——这张图本来就不是给初学者「看懂」用的。

学生手上只有两种信息：**界面的颜色**和**板子的现象**。中间那一层「这颜色 / 这现象意味着什么、把哪个值改成几」是空的。CubeMX 回答的是「合法不合法」；学生要问的是「能不能跑、怎么改」。

三个人卡住的其实是同一件事——**每个人都有一个「以为」，而那个「以为」从头到尾没有人当场纠正过**。

| 场景 | 他以为 | 真相 | 这个错会跟他多久【判断】 |
|---|---|---|---|
| 一 | 不红 = 对 | 灰的格子也能错；屏幕上的数不是定时器的数 | 整个项目周期：每个异常都归到传感器和代码头上 |
| 二 | 没调对，再试试 | 这组目标无解 | 到有人点破，或者放弃一个功能 |
| 三 | 能烧 = 配置对 | 合法 ≠ 可用 | 到重刷、换板、问人，甚至换芯片 |

这三条「以为」，就是产品里的三道判题卡。判题器的全部内容就是：把这一类「以为」一条条挖出来、当场揭晓、记进错题本。

## 1.4 诚实对比：CubeMX 做什么、教学视频做什么、我做什么

先把最容易被一句话打回的话说在前面：**CubeMX 会自动算时钟树，而且算得比我好；这件事我不做，也不该做。** 证据很直接：把 HCLK 改成 72 再回车，界面弹出 Searching Solution，自己把 PLL 倍频和各级分频倒推好【视频A@00:35–01:00】。

| 这件事 | CubeMX 6.15.0 | 三条教学视频 | 本作品 | 它让人学懂了吗 | 出处 |
|---|---|---|---|---|---|
| 自动算时钟树 | ✅ 强项：回车即倒推 | 讲原理，不替你算 | ❌ 不做，直接用它的结果 | ✅ 换个问法：先猜它会倒推出什么，再对答案——猜错的同学才知道 PLL 是怎么来的 | 视频A@00:35–01:00 |
| 显示上限 | ✅ 印着「72 MHz max」「36 MHz max」 | 提到 | ✅ 显示，并说明这个数从哪来 | △ 摆出数字不等于懂；本作品追问「这个上限对你现在的目标意味着什么」 | 视频B 画面 |

## 1.5 三个致命质疑，正面回答

### 1.5.1 「网上的 STM32 定时器计算器、PWM 计算器已经很多了，你有什么不同？」

**它们算的是最后一步，我从时钟树一路算到你手上。**

现成计算器的输入是 **TIMxCLK（定时器时钟）**——要你自己先从时钟树推出来。而「从 APB 分频推出 TIMxCLK」恰恰是最容易错的一步：分频 = 1 时不翻倍，分频 ≠ 1 时硬件自动 ×2，这个 ×2 你改不了，界面也不给你翻译【实测 + 视频A 字幕原话，07:30–11:15 段】。

还是场景一：屏幕上是 PCLK1 = 36 MHz，你要的 1 kHz 该拿来除的却是 72 MHz。把 36 填进现成计算器，它算得一丝不差，结果你得到 2 kHz【推算】。**计算器没错，错在它不问你这个 36 是从哪来的。** 同类例子还有两个：F103 时钟树上 USB 那格写 72（那是 PLL 输出，不是 USB 实际频率），USB 真正要的是 72 ÷ 1.5 = 48【手册 + 实测 + 视频A@00:55 画面】；HSE 进 PLL 前选 ÷1 还是 ÷2，÷1 × 9 = 72 MHz、÷2 × 9 = 36 MHz【实测】——界面上的数，不等于你要的数。

| | 现成定时器或 PWM 计算器 | 本作品 |
|---|---|---|
| 输入 | TIMxCLK（要你自己推） | 芯片 + 晶振 + 你要的频率 |
| 谁负责「APB 分频 → TIMxCLK」的 ×1 或 ×2 | 你 | 工具 |
| 这个时钟组合本身合法吗（USB 48、ADC 14） | 不检查 | 检查，并指出哪一格超了 |
| 配错了板上会看到什么 | 不管 | 管，且带证据等级（见 1.5.2） |
| 你算错了会不会被记住 | 不会 | 会：错的那条进错题本，下次先考它 |

它们在定时器细节上可能比我全（死区、互补输出这类进阶项），我不跟它们比这个【判断】。差别在问题的起点：现成计算器是给「已经知道自己该填什么」的人用的，而且是算完就走；这个作品是给「还不知道自己该问什么」的人用的，算完还要把你错在哪记住。

### 1.5.2 「你说配错会出什么现象，你自己烧板子验过吗？」

**先把话说死：本节列的现象，没有一条是我上板复现的。** 不拿「我看过」「我知道」冒充实测。证据分四档，产品里每条现象后面都带这个标签：

| 档 | 本节有哪些 | 来源 |
|---|---|---|
| 直接证据 · 公开可回看 | 「红字消了不等于对了」的整条动作链（拉满 → 红 → 除以 2）；No Debug 导致只能下载一次；ADC ÷2 得 36 MHz 时只灰不红 | 视频B@14:12 / 14:29 / 14:51、视频B@07:01、视频A@12:10 画面 |
| 直接证据 · 本机可复跑 | 三款芯片的各档上限（F103：主频 72、APB1 36、APB2 72、ADC 14、USB 48）；÷1 × 9 = 72,000,000、÷2 × 9 = 36,000,000；F411 的 96 MHz 组回读到 USB 48，按同一组公式算 100 MHz 时 USB 只有 50【实测 + 推算】 | 本机 CubeMX 6.15.0 命令行回读【实测】 |
| 机制推断 · 有公式没上板 | ADC 超 14 MHz 后读数乱跳、定时器频率比算出来的快一倍、USB 认不到、串口乱码 | 【推断】+ 手册机制；上板复现【待核】 |
| 没有出处 | BOOT0 上电不跑一类的说法 | 【待核】 |

第 3 节的 16 条规则里，8 条的现象有视频画面或实测直接支撑，另外 8 条的上板表现标【待核】（第 3 节 3.6）。**能分清这两类，本身就是设计的一部分**：页面上每条现象都带等级，评委可以随手抽一条核对。

错题本里的每一条答案也带出处：猜错之后，学生点开就能看到「这条结论来自哪、第几分钟」。**学习产品比工具更不能编证据**——错了还要被记住，就更要让人当场核对。

### 1.5.3 「这不就是 CubeMX 的 Clock Configuration 换个皮？」

**如果这个作品只有那棵树，这句话完全成立。所以树不是主角。**

树在屏 1 只做一件事：让你看见你改的是哪一格——点哪一格、下游谁跟着变、哪一格是锁死的。它是键盘，不是产品。

主角是树下面那三张换算卡和屏 2 的体检，再加上一个 CubeMX 根本没有的东西：错题本。

| 主角 | 回答什么 | CubeMX 给不给 | 学生在这里学到什么 |
|---|---|---|---|
| ① 定时器卡 | 我要 1 kHz，PSC 和 ARR 填几？定时器真实时钟是 72 还是 36？ | 不给（只到 PCLK1 的 36） | 屏幕上的 PCLK 不是定时器时钟；×2 是硬件行为 |
| ② ADC 卡 | 我要每秒采多少次？现在这个 ADC 时钟超了没有？ | 不给（36 超 14 只灰不红） | 灰的那一格也可能是错的 |
| ③ 串口卡 | 115200 的实际误差是多少？ | 不给（时钟页没有波特率） | 误差是算出来的，不是猜出来的 |
| 屏 2 体检台 | 我这个现象是哪个配置造成的？改哪一格、改成几？ | 完全不涉及（No Debug 它不提示） | 现象 → 配置的反查 |
| 错题本 + 复习列表 | 我上次错在哪？今天该复习哪几条？ | 完全没有这个概念 | 学习闭环的后半段 |

可检验的证明在第 2 节：那里写死了降级方案——真做不完时，时钟树退化成一张静态图，只保留三个数卡片和现象清单，**产品仍然成立**。反过来读这句话：树是可以被替换的，三个数和体检不是。这就是「换皮」和「换产品」的区别。

再补一层：换的不只是界面，还有数据模型。CubeMX 的数据只到总线和主频（所以 ADC 36 超 14 它不管【实测】）；本作品多存了外设上限、定时器那个隐藏的 ×1 或 ×2、USB 的 ÷1.5，以及三个换算公式（第 4 节）。同一棵树，它算合法性，我算后果。

另外，我不做 CubeMX 的求解器：它改 HCLK 会弹 Searching Solution，我不会。我改一格只往下重算，让「这一格」和「你那三个数」的因果露出来。所以「换皮」这个质疑在这一版更站不住：换皮换不出错题本。

## 1.6 学习闭环怎么在纯静态站里实现

赛道论证不能停在口号上。这一节写清楚：**没有服务器、没有账号、没有后端**，这个学习闭环怎么真的跑起来。纯静态站是比赛约束，也刚好是产品优势——评委断网就能验。

### 1.6.1 四个机制

| 机制 | 学生的体验 | 纯静态站怎么做到 | 数据存在哪 | 边界 |
|---|---|---|---|---|
| 先猜后揭（predict-then-reveal） | 每题先自己填或选，点「揭晓」才出答案 | 题面和答案写在同一份静态文件里；页面先只渲染题面，点按钮才渲染答案 | 不需要存 | 答案就在源码里，看源码的人能提前看到——这不是防作弊产品，不设防 |
| 错题本 | 答错一条，自动记下；下次能翻 | 每答错一条，往浏览器本地存储（localStorage）写一条记录 | 学生自己的浏览器 | 清缓存会丢；换设备带不走（用导出补） |
| 进度 | 首页显示「已答 / 答对 / 待复习」 | 每次作答更新计数 | 同上 | 同上 |
| 复习列表 | 打开先考错题，答对两次移出 | 从错题本生成列表，按「错了第几次、多久没复习」排序 | 同上 | 移出规则是产品判断【判断】，不是学习科学的定论 |

### 1.6.2 一条错题长这样

| 字段 | 例子 | 为什么要存 |
|---|---|---|
| 题号 | F103-TIM-01 | 页面靠它找回题目 |
| 我猜的 | 36 MHz（把屏幕上的 PCLK1 当成了定时器时钟） | 复习时要看见自己当时怎么想的——错题本不是答案本 |
| 正确答案 | 72 MHz（总线分频 ≠ 1 时硬件自动 ×2） | 对照 |
| 错了第几次 | 2 | 排序：错得多的先出 |
| 上次复习 | 上周 | 排序：久没看的先出 |

### 1.6.3 为什么不用后端

| 需求 | 常规做法（要后端） | 纯静态做法 | 本作品 |
|---|---|---|---|
| 账号 | 注册登录 | 不需要账号 | 静态 |
| 数据 | 存服务器数据库 | 存本机浏览器 | 静态 |
| 隐私 | 要收集学号、成绩 | 一条都不收集，页面不发请求 | 静态 |
| 评委验证 | 要联网、要等服务器 | 断网也能用 | 静态 |
| 代价 | — | 清缓存、换设备会丢 | 明说：提供「导出 / 导入」一段文本兜底 |

### 1.6.4 学习效果怎么算：能算的、不能吹的

站内三个指标：**错题率**（第一次答错的比例）、**复习通过率**（错题第二次答对的比例）、**隔天再答正确率**（同一道题隔一天再出）。有真实用户之后才有意义，现在没有数据，不吹提升幅度。

### 1.6.5 评委当场能验的三件事

1. **做三道题**：错题本立刻多三条——不需要等用户研究，现场就看得见；
2. **断网再打开**：功能不变，页面不发任何请求——证明没有后台、没有上传；
3. **点开任一条揭晓**：底下有出处（视频时间点 / 实测 / 手册），可以当场回看核对。

这三件事比任何「学习效果 +xx%」都硬：它们是现场可复现的。

### 2.3.0 先把这一屏读对（上一版这里写错过，重点看）

「满频基准」这个画面里，**4 个关键项摆在一起是 3 绿 1 灰，不是全绿**：

| 项 | 数值 | 状态 | 为什么 |
|---|---|---|---|
| SYSCLK（PLL） | 72 MHz | 绿 | 上限 72，正好顶格【实测】 |
| PCLK1（APB1） | 36 MHz | 绿 | 上限 36，正好顶格【实测】 |
| PCLK2（APB2） | 72 MHz | 绿 | 上限 72【实测】 |
| USB | 72 MHz | **灰** | USB 预分频**默认是 ÷1**，72 ÷ 1 = 72 ≠ 48；必须**手动**改成 ÷1.5 才是 48MHz【实测】 |

谁要是说「官方默认就是 72MHz 全绿」，那是两处都错：

1. CubeMX **新建工程**的默认**不是** 72MHz，是 **HSI 跑起来、PLL 关、HSE Disable**：F1 的 SYSCLK 只有 8MHz，F4 是 16MHz【实测】；
2. 就算摆成 72MHz 的满频配置，USB 也不绿——它要你手动拨 ÷1.5。

顺带一个更狠的结论：**「绿」只代表这一格没超上限，不代表配置对。** 新建默认状态下除了 USB 之外几乎全绿（频率低，谁都不超），可那套配置没人真用——三个数全是没意义的小值，USB 也因为没有 PLL 根本没到 48；满频基准反而带一个灰。所以页面不拿颜色当结论，颜色只回答「这格超没超上限」。

- 每一格右边并排两种写法：`72 MHz` 和 `72,000,000 Hz`——学生报频率两种都有人用。
- 每格可点开一行说明，例如 HSE ÷2：「÷2 之后最高只能到 64MHz，跑不满 72（【实测】）」；USB ÷1：「默认 ÷1 出来是 72MHz，不是 48；要 48 得手动拨 ÷1.5（【实测】）」。

### 2.3.2 下半：这三个数你要多少

| 卡片 | 你填 | 页面立刻算给你 | 为什么 CubeMX 不给你 | 出处 |
|---|---|---|---|---|
| ① 定时器 | 想要的输出频率（如 1kHz） | 定时器时钟（F103 是 PCLK1 36 的 ×2 = 72MHz）；PSC 与 ARR 该填多少；实际输出与目标的偏差 | CubeMX 只显示 PCLK1 的 36，不给 ×2 之后的定时器时钟，更不管 PSC / ARR | ×2【实测】+【keysking 07:30–11:15】；PSC/ARR 拆分【手册·RM0008 定时器章节】，候选拆分【待核】 |
| ② ADC | 想要的采样率（次/秒） | ADCCLK、每个采样周期数下的**采样率上限**、要达到目标该把 ADC 预分频拨到哪一档；超上限变灰 | CubeMX 只给 ADCCLK，不给「次/秒」；转换时间里那固定的 12.5 个周期它也不讲 | 公式【手册·RM0008】；+12.5 已用【计算】对上数据手册；ADCCLK 上限 14MHz【实测】 |
| ③ 串口 | 想要的波特率 | 用 PCLK 算实际波特率与误差百分比，误差大就变黄 | CubeMX 的时钟页没有波特率这一项 | 公式【手册·RM0008 USART 章节】；误差换算【待核】 |

#### ADC 卡：上一版少算了 12.5 个固定周期（已改）

一次 ADC 转换不只是「采样那几个周期」，后面还固定跟一段逐次逼近的转换时间：

| 系列 | 一次转换要多少个 ADCCLK | 依据 |
|---|---|---|
| F1（F103） | T_conv =（采样周期数 + **12.5**）/ ADCCLK | 【手册】RM0008 ADC 章节 |
| F4（F407 / F411） | T_conv =（采样周期数 + **12**）/ ADCCLK（12 位模式） | 【手册】RM0090 |

所以采样率上限 = ADCCLK ÷（采样周期数 + 12.5 或 12）。而 **ADCCLK = PCLK2 ÷ ADC 预分频**——ADC 挂在 APB2 上【手册】。

**自检（这是算的，不是上机测的）：** F103 把 ADCCLK 拉到合法上限 14MHz、采样 1.5 个周期 → 14,000,000 ÷（1.5 + 12.5）= 14,000,000 ÷ 14 = **1,000,000 次/秒**，正好是 F103 数据手册标的 1 Msps 上限 → 说明里面确实是 **+12.5**，不是 +12。【计算】+【手册】

**F103 · ADCCLK = 12MHz 时的采样率上限**（12MHz = 满频基准下 PCLK2 72MHz ÷ ADC 预分频 ÷6，是合法档，不是超限档）：

| 采样周期数（CubeMX 里那一档，单位：ADCCLK 周期） | 1.5 | 7.5 | 13.5 | 28.5 | 41.5 | 55.5 | 71.5 | 239.5 |
|---|---|---|---|---|---|---|---|---|
| 采样率上限（次/秒） | 85.7 万 | 60.0 万 | 46.2 万 | 29.3 万 | 22.2 万 | 17.6 万 | 14.3 万 | 4.76 万 |

出处：把【实测】回读到的 ADCCLK 12MHz 代进【手册】的 +12.5 公式算出来的（【计算】）。**这一行不是 CLI 回读值**，页面要标清，导出件也不许把它写成「已回读」。

两条能直接讲给学生的话：

- 12MHz 下就算采样只给 1.5 个周期，也只有 85.7 万次/秒——**到不了 100 万**。要 1 Msps 得 ADCCLK = 14MHz，那要另一套配法（HSE 8MHz ÷2 ×7 → 28MHz，APB2 ÷1，ADC ÷2 → 14MHz）【计算】。
- 把 ADC 预分频从 ÷6 拨回 ÷2：ADCCLK = 36MHz，超过上限 14，这一格立刻变灰——**这就是 2.4 里「灰② ADC 数值乱跳」的来源**，也是全场唯一一个 CubeMX 不会提醒你的坑（F4 上不存在，因为它把超限档位禁掉了）【实测】。

公式只写站得住的部分：定时器时钟 = PCLK × 2（硬件自动，【实测】）；「定时器时钟 ÷ 目标频率 =（PSC+1）×（ARR+1）」的候选拆分、串口误差换算来自参考手册，**本轮没逐档回读 → 待核**，不许在页面上假装精确。

### 2.5.1 导出件里的「校验」到底怎么写（状态机）

**先划清一件事，这是上一版的错：** 纯静态站**没有后端**，页面不可能针对「你当前这套配置」去跑 CubeMX CLI。上一版在文件头固定打印「已用 6.15.0 CLI 回读，与页面一致」——这句话对白名单外的组合就是假的，必须删。真正回读过的只有 **9 组固定配置**。其余组合页面照算，但导出件必须自己承认「没回读过」。

| 步 | 做什么 | 怎么判 | 为什么这么定 |
|---|---|---|---|
| 1 | 组指纹 | 关键字段按**固定顺序**拼成一行；缺的字段先补默认值再拼 | 同一套配置只允许有一种写法，否则比对必然漏 |
| 2 | 查白名单 | 拿指纹和白名单 9 条**逐字**比对 | 不用哈希：哈希碰撞会误报「已回读」，比漏报更糟 |

### 2.5.2 「.ioc 关键行」的正反向闭环

屏 3 那份 .ioc 关键行不是死的文本，它是**能读能写**的：写出去的文件必须能被 2.2.1 那个解析器原样读回来。

| 方向 | 动作 | 验收判据 | 判不过怎么办 |
|---|---|---|---|
| 正向（读） | 拖入 .ioc → 反填三屏 | 三屏数字和你电脑上 CubeMX 里看到的逐个一致 | 对不上就是键漏了或归一化错了，修解析器，不许在页面上抹平 |
| 反向（写） | 导出「.ioc 关键行」→ 把这份文件再拖回页面 | 三屏数字和导出前**一字不差**；第 4 行指纹与导出前完全相同 | 指纹变了 = 导出漏键（例如没写 PLLXTPRE），导出件必须报错，不许装作没事 |
| 贴回真工程 | 把这十几行贴进自己的 .ioc、用 CubeMX 打开 | 时钟页显示和页面一致（这一步要人做，页面只负责给出正确的行） | 写明贴到了哪一段；贴错就是人为错误 |

这条闭环的意义：**导出件本身就是「解析器的测试用例」**。能读不能写、能写不能读，都算没做完。

## 2.6 核心交互：改一个分频器，七处一起变

| 序号 | 变化的位置 | 看到什么 | 为什么这么设计 |
|---|---|---|---|
| 1 | 你刚改的那一格 | 数字变、格子高亮 | 先确认改的是它 |
| 2 | 它下游的每个节点 | 全部重算 | 时钟树就是一串乘除法；【实测】÷2 再 ×9 得 36MHz |
| 3 | 下半三张卡 | 重算；超上限的卡变灰或变黄 | 你要的功能频率本来就跟着总线走 |
| 4 | 顶栏红黄灰计数 | 数字跟着变 | 不管你在哪一屏，都看得见问题变多还是变少 |
| 5 | 体检台对应条目 | 从「正常」变成「有这个现象」，或反过来 | 现象清单是结果，结果变它就变 |
| 6 | 导出按钮 | 有红就不可点，旁边写清原因 | 不让人带走一份跑不通的配置 |
| 7 | 导出件的校验状态标 | 从「已回读（白名单 #n）」掉成「公式计算，未回读」——只要新配置不在那 9 条里 | 校验状态是配置的函数，不是页面的常数 |

四条约束：

- **不刷新页面。** 纯前端计算，符合静态站约束。
- **数字不跳位。** 等宽数字 + 固定列宽（见 2.8），改值时布局不能动，否则学生以为自己点错了。
- **一次只改一个变量。** 不提供「一键全设」；现在只有四类例外，全都要先弹预演、把哪几格从什么改成什么列出来：拖入 .ioc（批量反填）、「CubeMX 新建工程默认」、「满频基准」、「一键修复」。
- **一键修复有边界。** 只修能用公式判定的两类：总线超限、ADC 超上限；No Debug 不自动改，可能有人故意不要调试口；USB 预分频那一条也不自动改（要 48MHz 还是不要 USB，得人自己定）。

## 2.7 五步演示流程

评委照着点。第 2–4 步各只动一个控件；第 1 步是拖文件、第 5 步是切屏，都不改配置。

| 步 | 评委操作（一句话） | 屏幕上必须出现 | 这一步值什么 |
|---|---|---|---|
| 1 | 打开页面，把手里那个 .ioc 拖进首屏的框 | 框里出现「读到 项目名.ioc（14 项时钟键）」，三屏被反填成他那套配置；拖个错的文件则落回示例、不报错 | 「打开就能用」——学生不用先学会搭树【实测】键名 |
| 2 | 点「满频基准」 | SYSCLK 72 / PCLK1 36 / PCLK2 72 三格绿，**USB 灰**（默认 ÷1 → 72MHz ≠ 48）；顶栏 ○1 灰，即 3 绿 1 灰 | 基准要标清来历：这是演示基准，不是 CubeMX 官方默认 |
| 3 | 把 HSE 进 PLL 的 ÷1 改成 ÷2 | PLL 掉到 36MHz；再把倍频拖到 ×16，最高也只有 64MHz，跑不满 72 | 同一个 ×9，分频选错就上不去，这是反直觉点【实测】 |
| 4 | 恢复 ÷1 ×9，把 APB1 从 ÷2 改成 ÷1 | PCLK1 变 72MHz 并标红（上限 36），顶栏红 +1；改回 ÷2 立刻变绿 | 复原老师课上「拉满 → 红 → 除以 2」的原路【创客中心 14:29】【创客中心 14:12】 |
| 5 | 切体检台点「下载一次就下不进去」，再切导出 | 体检台给出「Debug 改成 Serial Wire」；导出三件套可复制 / 下载，第 6 行照实写「已回读（白名单 #…）」或「公式计算，未回读」 | 从「看得懂」到「带得走」，最后把「验没验过」也交代清楚【创客中心 07:01】 |

演示时若有人追问「凭什么说 72 不是官方默认」，直接点另一个按钮「CubeMX 新建工程默认」：画面会掉成 HSI 8MHz、PLL 关、HSE 关——那才是新建工程的样子【实测】。

## 2.8 视觉要求

**深色工程师风。** 近黑底、面板比底色亮一档、细分割线；不做圆角大色块和卡片阴影堆叠（堆了就像套模板，学生一眼看得出来）。等宽字体只用于数字和导出预览，正文用普通无衬线。

红黄灰是「这一格超没超上限」，只有一套：

| 色 | 什么时候出现 | 屏幕上必须带的文字 | 出处 | 点了能做什么 |
|---|---|---|---|---|
| ● 红 | 总线超过芯片上限（F103 的 APB1 36、F407 的 42、F411 的 50） | 「超上限：72 比 36 大，CubeMX 也会标红」 | 【实测】+【创客中心 14:12】 | 一键修复 / 跳节点 |
| ◐ 黄 | 数值合法但让「你要的功能」达不到（F411 25MHz 晶振下，100MHz 与 USB 48MHz 只能二选一） | 「能生成，但 USB 会认不到：降主频，或者不要 USB」 | 【实测】 | 给两个选项让人选 |
| ○ 灰 | 超过芯片外设上限、CubeMX 不标红（F103 的 ADCCLK 36MHz 超过 14MHz；F4 上不存在这一档，它直接禁用） | 「CubeMX 不会提醒你这一条」 | 【实测】 | 一键修复 / 跳节点 |

「回读状态」是另一套标，**不要和红黄灰混着用**（一个是配置好坏，一个是验没验过）：

| 标 | 什么时候出现 | 屏幕上必须带的文字 | 出处 |
|---|---|---|---|
| ✔ 已回读 | 指纹命中 9 条白名单 | 「已回读（白名单 #3）：这组数字是 CLI 真的读回来的」 | 【实测】 |
| ⚠ 未回读 | 指纹不在白名单 | 「公式计算，未回读，风险自担：数字是算出来的」 | 静态站无后端 |

- **等宽数字。** 频率同时给 `72 MHz` 和 `72,000,000 Hz` 两种写法；数字右对齐；数字和单位不许断行；改值时列宽不跳。
- **颜色不单独表意。** 每个色点后面必须跟文字（超上限 / 二选一 / CubeMX 不提示 / 未回读），色觉障碍的人也能读。
- **建议色板**（设计值，不是技术事实，可替换）：底 `#0D1117`、面板 `#161B22`、正文 `#C9D1D9`、红 `#F85149`、黄 `#D29922`、灰 `#8B949E`。
- **手机能看**：见 2.9，不是把桌面版缩小，是重新排。

## 2.9 手机与降级方案

### 2.9.1 手机上怎么排

| 屏 | 桌面 | 手机（窄屏） | 少掉的体验 |
|---|---|---|---|
| 入口 | 把 .ioc 拖进框里 | 同一个框，但只能点「选择文件」（手机上拖拽不可用） | 不能拖，只能选；某些手机浏览器打不开文件选择器时落回手动示例（与解析失败同一条路） |
| 1 时钟树 | 一棵完整的树 | 只展开「上游一格 + 当前格 + 下游两格」，其余折叠成「展开上游 / 下游」 | 不能一眼看全树 |
| 1 三张卡 | 并排三张 | 竖排，一张接近一屏 | 不能同屏对比三个数 |
| 2 体检台 | 左右分栏 | 单列；先列红和黄，灰放最后 | 灰要多滑几屏才看到（取舍） |
| 3 导出 | 预览 + 按钮 | 只留三个下载按钮和一行「红 0 条，可导出；校验：未回读」 | 手机上不预览长文本 |

- 拖动改分频器，手机换成「− / +」点按循环候选值。竖屏拖拽容易误触，这是设计取舍，不是实测结论。
- 手机上不删功能，只折叠布局；三屏算出来的数字和桌面一致；**回读状态在手机上也必须显示**（否则导出件的那行字就成了没人看的注脚）。

### 2.9.2 只支持一款芯片时怎么砍（只留 F103C8T6）

| 动作 | 内容 | 理由 |
|---|---|---|
| 保留 | 首屏拖 .ioc（只解析 F1 那套键：PLLMUL + 进 PLL 前 ÷1/÷2） | 这是「打开就能用」的唯一来源，砍了产品就退回手动玩具 |
| 保留 | 进 PLL 前 ÷1/÷2 与 72 / 64 的对照、APB1 36 / APB2 72、定时器 ×2、USB ÷1 与 ÷1.5、ADC 14、37 个可用 IO | 视频里老师用的就是这块板，「拉满 72 → 标红 → 除以 2」整条故事都在它身上【创客中心 14:29】 |
| 砍 | F4 系列的 PLLM / PLLN / PLLP / PLLQ 四格 | F103 的 PLL 只有「进 PLL 前 ÷1/÷2」和「×2~×16」两格【实测】，留着会让人以为 F103 也有 |
| 砍 | HSE 25MHz 默认的提醒、F411 的 100MHz 与 USB 二选一、F4 的 ADC 档位禁用行为 | 都是 F4 专属的坑 |
| 砍 | 芯片之间的 IO 数量对比（114 / 36） | 只做一款时引脚表就是 37 行，对比失去意义 |
| 保留 | 9 条白名单砍到只剩 F103 的 6 条 | 白名单是「已回读」的唯一依据，随芯片一起砍，不能没有 |

砍到只剩 F103，产品仍然成立：屏 2 的核心现象（下不进程序、总线标红、USB 默认 ÷1、ADC 灰、定时器差一倍、默认只有 8MHz）全部在它身上。

**再退一步**（连三屏都做不完时）：保留「三个数卡片 + 现象清单」两件，时钟树退化成一张静态图（标出当前值、不可拖），导出退化成「一键复制一段文字 + 照实写校验状态」，.ioc 拖入保留（它只是一个文本框加十几条正则，成本最低、收益最大）。理由：三个数、现象清单和「拖进来就能看」是评委没见过的部分，时钟树是可替代的。

## 3.1 为什么按现象组织，不按配置项

学生记不住、也不关心"APB1 预分频"这个词。他们记得的是"程序下不进去""灯不亮""串口全是乱码"。

视频 B 里，老师自己也承认这块吓人：「**大家看到这样一框图看起来非常复杂是吗？大家不要慌**」【视频B@08:36】。他接下来的完整动作是：看到 HCLK 下面印着"72 MHz max"，说「**它这里显示最大是 72 兆赫兹，那么咱们直接给它拉满**」【视频B@14:29】；拉满后界面变红，说「**这边出现红色了，红色的就有问题**」【视频B@14:12】；然后「**咱们直接除以 2**」【视频B@14:51】，红消失，结束。

这条链里，**红色消失不等于配置对了**——整段没有一句在查"这对我要的功能意味着什么"。而且现在的 CubeMX 会自动求解：你一改 HCLK 按回车，它就开始 Searching Solution 帮你把分频配到合法【实测】，**但它只保证"不违规"，不保证"符合你的用途"**。视频 B 全长 25:02，配时钟只占约 5 分钟【视频B】；学生卡住的是"点完为什么不跑"，不是"怎么点"。

| | 按配置项组织（旧版） | 按现象组织（本节） |
|---|---|---|
| 入口 | RCC / SYS / GPIO / 时钟树 各一节 | 下不进程序 / 灯不亮 / 数值不对 |
| 学生要做的 | 先知道自己该看哪一项 | 认出自己看到的现象即可 |
| 一个现象多条原因 | 散落在不同章节 | 同一组里连续列出（如"板子不跑"有 4 条） |
| 评委试用的感觉 | 像看手册目录 | 像在问诊 |

**两个代价**：① 16 条里有不少名字仍是技术名（SYSCLK、APB1、HSE……），因为要能检索、要能和界面词对上；做法是**组按现象分，规则名保留技术名**，名字后面紧跟"你会看到"。② 每条要多写"错因""自测"两行，字数变多——但这是把"工具"变成"教材"的必要成本：体检台报错时，顺手把原理和小测递给学生。

**时钟怎么算（学生要会这一行）**

| 家族 | 算式 | 约束 |
|---|---|---|
| F1 | 输入 = HSE ÷ PLLXTPRE（÷1 或 ÷2），或 HSI ÷2（固定）；SYSCLK = 输入 × PLLMUL | PLLMUL ×2~×16；AHB ÷1~÷512；APB ÷1/2/4/8/16 |
| F4 | VCO_in = HSE ÷ PLLM；VCO_out = VCO_in × PLLN；SYSCLK = VCO_out ÷ PLLP；USB = VCO_out ÷ PLLQ | VCO_in 1~2MHz；VCO_out 100~432MHz；PLLP 只能 2/4/6/8 |

【手册】RM0008 / RM0090；【实测】F103：HSE 8MHz ÷1 ×9 = 72MHz、÷2 ×9 = 36MHz；F407：25 / 336 / 2 / 7 → 168 / 42 / 84 / 48；F411：25 / 200 / 2 → 100MHz（PLLQ=4 → 50，配不出 USB 48），25 / 192 / 2 + PLLQ=4 → 96MHz + USB 48。

补充一句：F103 还有 FCLK、CSS（时钟安全系统）、MCO 时钟输出在 PA8；SysTick 可选 HCLK÷1 或 HCLK÷8【实测】。这些不参与本节 16 条判定，但学生在时钟树里会看到这些灰格，别被吓到。

## 3.3 规则卡：五组 16 条

### 组 A · 烧进去了，板子没反应

> 共同点：界面可能不红、代码能生成、烧录也成功，但板子不跑。按"时钟 → 启动脚 → 晶振脚 → HSE"的顺序查。

#### ❌ 1 · SYSCLK 超频（主频拉到超过芯片上限）

**判定**：把时钟树算到底的 SYSCLK 拿去和上限比：F103 72 / F407 168 / F411 100 MHz【实测·库】。F1 的算法是（HSE ÷ PLLXTPRE，或 HSI÷2）× PLLMUL；F4 的算法是 VCO_in = HSE ÷ PLLM、VCO_out = VCO_in × PLLN、SYSCLK = VCO_out ÷ PLLP【手册】。  
**你会看到**：点 GENERATE CODE 时弹出 `IP not ready for code generation: Clock`，代码生成失败；但时钟树里照样显示你填的超频值，不自动降频【实测：F411 超上限时生成被拦、界面不降】。如果绕过这一步、或工程是旧的，烧进板子就是"不按预期跑"【待核：未上板复现】。  
**怎么办**：把乘数降回来。F411 的 PLLN 从 336 改回 200 → 100MHz，正好压在上限【实测】；F103 把 HSE ÷1 送进 PLL、PLLMUL 改成 ×9 → 72MHz（改成 ÷2 ×9 就是 36MHz）【实测】。  
**错因**：SYSCLK 是芯片的总节拍，CPU、Flash 取指、总线全按它走。数据手册写的 72/168/100 是"保证能正常工作的上限"，不是建议值——超了，Flash 等待周期档位、PLL 锁定范围都开始不保证，取回来的指令可能是错的。所以超频的后果不是"跑快点"，是"跑飞"；CubeMX 只是个计算器，它算得出数不代表芯片受得住。  
**自测**：Q：F411 用 25MHz 晶振、PLLM=25、PLLN=200、PLLP=2，SYSCLK 是多少？能不能生成代码？　<details><summary>答案</summary>A：VCO_in = 25÷25 = 1MHz → VCO_out = 200MHz → SYSCLK = 200÷2 = 100MHz，正好等于上限，合法、可以生成【实测：PLLN=200 → 100MHz；合规即可生成】。</details>  
**出处**：【实测·库】三款上限 72 / 168 / 100；【实测】F411 PLLN=200 → 100MHz、PLLN=192 → 96MHz；F103 HSE ÷1×9 = 72、÷2×9 = 36；【实测】SYSCLK 超限时生成报 `IP not ready for code generation: Clock`，时钟树不自动降频；【手册】数据手册"最大主频"、RM0090 的 PLL 公式与 PLLP 取值；【推断】PLLN=336 → 168MHz（25÷25×336÷2 = 168）；【待核】超频配置烧进板子的实际表现。

#### ❌ 7 · BOOT0 当普通 IO（板子上电从"错的存储器"启动）

**判定**：功能落在 BOOT0 上（按键、LED、串口），或 BOOT0 在上电瞬间被外设拉高。CubeMX 器件库里 BOOT0 是启动脚，不计入可分配的普通 IO（F103 的 37 个里没有它）【实测·库】。  
**你会看到**：程序上电不跑——芯片从系统存储器启动，停在等串口下载的状态；按一下复位有时又能跑【待核：三条视频都没演示】。  
**怎么办**：BOOT0 还给启动电路：按板子原理图接下拉到地，别在 CubeMX 里把它配成外设；按键/灯换一个普通 IO。  
**错因**：上电或复位的一瞬间，芯片会"看一眼"BOOT0 的电平，据此决定从哪块存储器取第一条指令——0 从 Flash（你的程序），1 从系统存储器（ST 内置的串口下载程序）【手册】。这个锁存只在上电那一瞬间发生，之后你在程序里怎么改都晚了，所以"程序里点灯"永远等不到。它不是可分配的外设脚，是"开机开关"。  
**自测**：Q：板子上电后程序不跑、串口没输出，但按一下复位又能跑，先怀疑哪里？　<details><summary>答案</summary>A：先怀疑 BOOT0 上电时被拉高或悬空，芯片从系统存储器启动；查 BOOT0 的下拉电阻【手册；具体表现待核】。</details>  
**出处**：【手册】RM0008 启动配置（BOOT0/BOOT1 决定 Flash / 系统存储器 / SRAM）；【实测·库】BOOT0 列为启动脚、不计入 37 个可用 IO；【推断】"上电不跑、复位能跑"的机制；【待核】三条视频都没演示这个现象。

#### ❌ 8 · 选了 HSE 但晶振脚被占

**判定**：RCC 里 HSE 选了 Crystal/Ceramic Resonator，但主晶振脚已被别的功能占用：F103 是 PD0/PD1，F407 和 F411 是 PH0/PH1；开了 LSE 还要算上 PC14/PC15【实测·库】。  
**你会看到**：引脚图上这对脚立刻变绿，标上 `RCC_OSC_IN` / `RCC_OSC_OUT`（开了 LSE 则是 `RCC_OSC32_IN/OUT`）；你在别处再点这个脚就冲突；时钟树里 HSE 那格可能灰着改不动【待核：该界面表现未逐帧截到】；或者代码里时钟初始化卡在超时等待，串口一个字都不打【待核：未上板复现】。  
**怎么办**：两条路——把占脚的功能挪走（视频里老师点开 PC14 看到第一项就是 RCC_OSC32_IN，于是把 LED 改到 PC13）【视频B@16:18】；或者干脆关掉 HSE/LSE，用内部 HSI（代价：F103 主频最高 64MHz，见第 16 条）。  
**错因**：晶振脚在封装里直接连着芯片内部的振荡器电路，它的"第一职业"就是接晶振。RCC 一旦把 HSE 打开，CubeMX 就把这一对脚锁给 RCC，别的功能再点它就是抢同一个物理脚。晶振起不来 → PLL 拿不到输入 → 后面整棵时钟树全是空算，芯片停在等就绪。  
**自测**：Q：F103 想把 LED 接 PC14，同时还要开 LSE 跑 RTC，行不行？　<details><summary>答案</summary>A：不行。PC14 是 LSE 的 OSC32_IN【视频B@09:18】，开了 LSE 就归 RCC。视频里老师正是看到 PC14 下拉第一项是 RCC_OSC32_IN，才把 LED 改到 PC13【视频B@16:18】。</details>  
**出处**：【视频B@06:24】HSE 改 Crystal 后 PD0/PD1 立刻变绿标 RCC_OSC_IN/OUT；【视频B@09:18】LSE 一开 PC14/PC15 变绿标 RCC_OSC32_IN/OUT；【视频B@16:18】点开 PC14 下拉第一项就是 RCC_OSC32_IN，老师因此改用 PC13；【实测·库】三款主晶振脚 / 低速晶振脚如上；【待核】上板卡死的具体表现。

#### ❌ 16 · RCC 里没开 HSE 就用 PLL（主频顶到 64 就上不去）

**判定**：主时钟用了 PLL，但 RCC 的 High Speed Clock (HSE) 还是 Disable——PLL 的输入只能落回内部 HSI。注意：**CubeMX 新建工程默认就是 HSI + PLL 关 + HSE Disable，不是"72MHz 全绿"**【实测】。  
**你会看到**：HSE 那一格是灰的；PLL Source 只能选 HSI，前面还挂着一个 ÷2，输入显示 4MHz；HCLK 最高只到 64MHz，72 怎么调都出不来【实测：默认态与 HSI 参数；64 为推断：4×16】。  
**怎么办**：先到 RCC 把 HSE 从 Disable 改成 Crystal/Ceramic Resonator，再回时钟树把 PLL Source 选成 HSE；F103 要跑满 72，就是 HSE 8MHz ÷1 ×9【实测】。  
**错因**：F1 的 PLL 只有两个输入源：HSE（外部晶振，可再 ÷1 或 ÷2）和 HSI÷2。HSI 是芯片内部 RC 振荡器，出厂 8MHz、精度差；进 PLL 前固定 ÷2，只剩 4MHz。PLL 倍频上限 ×16，所以天花板是 4×16 = 64MHz——这是硬约束：缺了外部晶振，72MHz 在物理上就不成立。F4 同理，PLL 输入要靠 HSE ÷ PLLM 落进 1~2MHz，HSI 那条路精度不够，要 USB 这种精确 48MHz 的功能更别想。  
**自测**：Q：F103 没焊外部晶振、只开 HSI，PLL 倍频拉到最大能到多少？为什么到不了 72？　<details><summary>答案</summary>A：8MHz ÷2 = 4MHz，×16 = 64MHz；72 需要 HSE 8 ÷1 ×9 = 72，没有外部晶振就凑不出来【手册 + 推断：4×16 = 64】。</details>  
**出处**：【实测】新建工程默认 HSI 8MHz（F4 16MHz）/ PLL 关 / HSE Disable；HSI 8MHz、进 PLL 前固定 ÷2、PLL 倍频 ×2~×16；F103 HSE ÷1×9 = 72；【视频B@05:24→06:24】RCC 页 HSE 从 Disable 改成 Crystal/Ceramic Resonator 的完整动作；【视频B@10:00 一带】默认状态 PLL 源是 HSI、前面一个 ÷2、输入为 4；【视频A@11:15–11:35】HSI 进 PLL 前固定 ÷2（画面蓝色 /2）；【手册】RM0008 时钟树；【推断】64 = 4×16；【待核】上板实际最高主频未测。

### 组 B · 第二次就下不进去了

> 共同点：第一次烧进去都正常，之后电脑再也连不上芯片。原因都是"下载/调试用的那两根线（或那个选项）没保住"。

#### ❌ 6 · 调试脚被占用（SWD 被改成别的功能）

**判定**：PA13/PA14 被配成别的功能，或者 SYS 的 Debug 不是 Serial Wire——这两根就是下载/调试用的 SWD 线【实测·库】。  
**你会看到**：第一次烧完还能连；改完再烧，烧录软件报"找不到目标 / No target connected"，电脑连不上芯片，板子还在跑上一次的程序【待核：与第 13 条同一现象，本轮未上板复现】。  
**怎么办**：PA13/PA14 让给 SWD（SYS → Debug 选 Serial Wire），要当 IO 就换脚；已经连不上的，按老师说的用串口方式重刷一遍。  
**错因**：SWD 是两线调试口：SWDIO 走 PA13、SWCLK 走 PA14。程序一旦把这两脚改成普通输出，调试模块就没了对外通路；下次烧录器连上来，芯片已经"不在听"——这叫把梯子踢了，人还在楼上。所以这两脚永远要留给调试，别拿它点灯。  
**自测**：Q：把 PA13 配成 GPIO 用来点灯，会有什么后果？　<details><summary>答案</summary>A：第一次能烧，之后烧录器连不上——SWD 两线被占，调试口没了；点灯请换脚【与视频B@07:01 同一机制；上板表现待核】。</details>  
**出处**：【视频B@07:01】原话「如果你这个地方选 No Debug……会导致你的芯片程序只能下载一次，第二次下不进去了……」；【视频B@06:54–07:18】Serial Wire 时 PA13/PA14 变绿标 SWDIO/SWCLK，改回 No Debug 标注立刻消失；【实测·库】三款 SWD 都是 PA13/PA14；【待核】"找不到目标"的报错原文没截到。

#### ❌ 13 · Debug 选 No Debug（程序只能下载一次）

**判定**：SYS → Debug 这一格是 No Debug，没有选 Serial Wire。  
**你会看到**：第一次下载正常、程序也能跑；第二次按下载，烧录器连不上——就是老师说的"只能下载一次，第二次下不进去了"。  
**怎么办**：SYS → Debug 改成 Serial Wire，重新生成代码、再烧一次；已经锁住的，用串口烧录方式救回来。  
**错因**：Debug 这一项决定芯片给"下载/调试"留哪套口：JTAG、Serial Wire、还是全不留（No Debug）。选了 No Debug，生成的初始化代码会把调试口的脚全交还给 GPIO、调试模块关掉。下次烧录器想通过 SWD 说话，芯片已经没有这个口了——"只能下载一次"就是这么来的。  
**自测**：Q：老师说的"芯片程序只能下载一次"，是哪一个选项选错了？　<details><summary>答案</summary>A：SYS → Debug 选了 No Debug；改成 Serial Wire 就恢复【视频B@07:01】。</details>  
**出处**：【视频B@07:01】老师原话（全文见第 6 条）；【视频B@06:54 设成 Serial Wire → 07:06 改回 No Debug 演示区别 → 07:18 又改回 Serial Wire】画面实证；【手册】RM0008 调试口与 AFIO。

### 组 C · 灯不亮 / 引脚不听使唤

> 共同点：程序在跑，别的功能也正常，就是某个脚不听话。先确认这个脚在不在封装上，再看它被谁占着，最后看输出模式。

#### ❌ 9 · 同一引脚被两个外设抢

**判定**：两个功能点名同一个引脚。芯片里每个脚能接哪几个外设是定死的，同一时刻只能开一个（F4 看 AFR 复用功能选择，F1 看各外设配置位 + AFIO 重映射）【手册】。  
**你会看到**：刚配好一个功能，另一个悄悄被顶掉、引脚变回黄色；或者代码里一个外设没初始化，上板一个正常、另一个没反应【待核：CubeMX 弹窗原文未逐帧截到】。  
**怎么办**：换脚或换外设实例。例：F103 的 PA2 上，USART2_TX 和 TIM2_CH3 是同一个脚的两个候选【实测·库】，两个都要用就有一个得换脚。  
**错因**：芯片内部每个引脚只有一条"通道"能接到外设，走哪条由复用功能选择寄存器决定，一个位置只能填一个外设编号。你配第二个，就把第一个的编号覆盖了——脚上的信号没了内部通路，前一个外设看起来像"没初始化"。这不是资源不够，是"一个插座只插一个插头"，后插的把先插的顶掉。  
**自测**：Q：PA2 上同时要 USART2_TX 和 TIM2_CH3，能都工作吗？　<details><summary>答案</summary>A：不能。PA2 的候选功能里两者并列【实测·库】，同一时刻只能选一个；要两个都跑，其中一个必须换脚。</details>  
**出处**：【实测·库】PA2 的复用功能列表 = ADC1_IN2 / ADC2_IN2 / TIM2_CH3 / USART2_TX（一个脚挂着四个候选）；【手册】RM0008 复用功能表与 AFIO；【待核】顶掉时的界面提示原文。

#### ❌ 11 · 引脚不属于当前封装（F411 没有 PB11）

**判定**：功能落到当前封装没有的引脚上。可用 IO：F103 LQFP48 = 37 个、F407 LQFP144 = 114 个、F411 UFQFPN48 = 36 个；F411 的 UFQFPN48 没有 PB11【实测·库】。  
**你会看到**：在 CubeMX 引脚图上根本找不到这个脚（不是灰，是没有）；板上也焊不出这根脚；代码里对它的操作落不到硬件上。  
**怎么办**：换成当前封装里有的脚，或者换封装/换芯片；工具在用户点名时直接说"这颗封装没有这个脚"。  
**错因**：芯片裸片里有这个引脚，不代表封装（黑色塑封壳 + 那几十根金属脚）把它引出来了。封装越小能引出的脚越少，芯片内部的功能被"关在壳里"。所以能不能用，取决于"这颗芯片 + 这个封装"的组合，不是只看芯片型号的功能表。  
**自测**：Q：F411CEU6（UFQFPN48）能用 PB11 吗？　<details><summary>答案</summary>A：不能，这颗封装的引脚表里没有 PB11（可用 IO 只有 36 个）【实测·库】；换脚或换封装。</details>  
**出处**：【实测·库】本机 CubeMX 6.15.0 器件库：F411 的 UFQFPN48 引脚表里没有 PB11（可用 IO 36）；F103 LQFP48 = 37、F407 LQFP144 = 114；【手册】ST 数据手册的引脚定义表。

#### ❌ 12 · JTAG 脚当 IO 用

**判定**：用 PA15 / PB3 / PB4（或 PA13/PA14）当普通 GPIO，而 SYS 的 Debug 还停在 JTAG。  
**你会看到**：这几个脚配成输出后没反应、电平一直不变，换成别的脚就正常；把 Debug 改成 Serial Wire 之后，这几个脚才开始听使唤【待核：未上板复现】。  
**怎么办**：SYS → Debug 选 Serial Wire（只占 PA13/PA14 两线，把 PA15/PB3/PB4 放出来），或者把这几个功能换到别的脚。  
**错因**：芯片上电默认把 JTAG 全功能打开，占 5 个脚（PA13/PA14/PA15/PB3/PB4）。JTAG 模块没关，这 5 个脚就归调试口管，你的 GPIO 配置写下去不生效——像房间还被占着，你贴的标签没人看。改成 Serial Wire 只留两线，剩下三个才交还给你。  
**自测**：Q：为什么把 Debug 从 JTAG 改成 Serial Wire 之后，PB3 突然能点灯了？　<details><summary>答案</summary>A：JTAG 占 5 个脚，Serial Wire 只占 PA13/PA14；改成 Serial Wire 后 PB3/PB4/PA15 被放出来归 GPIO【实测·库 + 手册】。</details>  
**出处**：【实测·库】三款 JTAG 脚都是 PA13/PA14/PA15/PB3/PB4；【手册】RM0008 的 AFIO 重映射与 JTAG 禁用；【待核】PB3/PB4 作 GPIO 的上板表现未复现。

#### ❌ 15 · GPIO 开漏输出驱动 LED（灯不亮）

**判定**：GPIO 设成 Output Open Drain，而 LED 是"引脚→电阻→地"的接法——这种接法要引脚输出高电平才亮。  
**你会看到**：灯不亮（或一直暗着），万用表/示波器量这个脚永远是低；改成 Push Pull 立刻正常。  
**怎么办**：GPIO mode 从 Output Open Drain 改回 Output Push Pull。  
**错因**：开漏输出只有一个"往下拉"的开关（N 沟道 MOS 接地），没有"往上推"的管子。它输出"1"其实是"松手"，靠外部上拉电阻把电平拉高；没有外部上拉就是高阻态，灯拿不到电流。推挽有上下两个管子，能真正把脚推到高电平。  
**自测**：Q：LED 一头接 3.3V、一头接引脚（低电平点亮），开漏能点亮吗？　<details><summary>答案</summary>A：能——开漏能把脚拉到低，灯就亮（这也正是开漏擅长的方向）。但如果 LED 是"引脚→电阻→地"（要高电平点亮），开漏就点不亮。关键看 LED 接法。</details>  
**出处**：【视频B@18:34】老师把 GPIO mode 切成 Output Open Drain 演示、18:48 又切回 Push Pull；【视频B@17:33–18:36 台词】推挽有驱动能力、能强制拉高拉低，开漏没有驱动能力、要变高必须外部加上拉；【手册】RM0008 GPIO 输出模式。

### 组 D · 能跑，但数值不对

> 共同点：板子在跑、现象不是"死"而是"不对"。这一组最容易被当成"传感器坏了""板子有问题"。

#### ❌ 5 · USB 时钟不是 48MHz

**判定**：USB 时钟 ≠ 48MHz。F103：USB = PLLCLK ÷ USB 预分频，这一档只有 ÷1（默认）和 ÷1.5 两个选择，要 48 必须手动选 ÷1.5 且 PLL 正好 72MHz【实测 + 手册】；F4：USB = PLL 的 VCO 输出 ÷ PLLQ，要 48 就得让 VCO_out ÷ PLLQ = 48【手册】。  
**你会看到**：插上电脑认不到设备、虚拟串口不出来、枚举反复重试【待核：未上板复现】。F103 时钟树上 USB 那格写的 72 是 PLL 输出，不是 USB 实际频率；USB 分频器灰色只代表 USB 没开，不代表 0MHz【视频B@12:33】。  
**怎么办**：F103 两步走——先把 PLL 调到 72（HSE ÷1 ×9），再把 USB 预分频从默认的 ÷1 改成 ÷1.5，72 ÷ 1.5 = 48；F411 在 25MHz 晶振下二选一——PLLN=192 + PLLQ=4 → 96MHz 且 USB 48【实测】，或者 PLLN=200 → 100MHz 但 PLLQ=4 只有 50，USB 保不住【实测】。  
**错因**：USB 全速口是 12Mbps 的串行通信，芯片内部要一个正好 48MHz 的时钟去采每一位；差一点就采错位，电脑那边握手失败 → 认不到设备。F103 只有 PLLCLK 一个源，72 ÷ 1.5 = 48 是唯一走法，默认的 ÷1 会把 72MHz 直接送进 USB（超上限）。F4 多一个 PLLQ 通道，48 由 VCO_out ÷ PLLQ 凑，所以 PLLN 和 PLLQ 要一起配。  
**自测**：Q：F103 的 PLL 已经调成 72MHz，USB 为什么还是认不到？　<details><summary>答案</summary>A：因为 USB 预分频还停在默认的 ÷1（72MHz 直进 USB，超了 48 上限）。手动改成 ÷1.5 → 72÷1.5 = 48MHz 才行【实测：档位只有 1 和 1.5；推断：72÷1.5 = 48】。</details>  
**出处**：【实测】F103 的 USB 预分频只有 ÷1（默认）/÷1.5 两档；【实测】F411：PLLN=192/PLLP=2/PLLQ=4 → 96MHz + USB 48；PLLN=200 → 100MHz、PLLQ=4 → 50；【实测】F407：PLLM=25/PLLN=336/PLLP=2/PLLQ=7 → 168MHz、USB 48；【手册】RM0008（F103 USB = PLLCLK÷1.5）、RM0090（F4 USB = VCO÷PLLQ）；【视频B@12:33】灰格含义；【推断】72÷1.5 = 48、÷1 时 72 超 48 上限；【待核】上板枚举表现、CubeMX 对 F103 "USB=72" 是否变红。

#### ❌ 10 · 定时器时钟翻倍（硬件自动，用户改不了）

**判定**：APB1 或 APB2 的分频不等于 ÷1 时，硬件自动把定时器时钟翻倍：TIMxCLK = PCLK × 2。这个 ×2 不在任何可填的格子里【手册 + 实测】。  
**你会看到**：定时器/PWM 的频率比按 PCLK 算出来的快一倍——你以为按 PCLK 算出 1kHz，示波器上是它的两倍；定时中断也比预期来得快【待核：未上板复现】。  
**怎么办**：算 PSC/ARR 时用 ×2 后的定时器时钟，不要用 PCLK；工具直接给出 TIMxCLK 和该填的 PSC/ARR。  
**错因**：定时器挂在 APB 总线上，但它内部要按"总线时钟的 2 倍"来数数，才能做到高分辨率。ST 把它做成硬件自动：只要 APB 分频不是 1，定时器时钟就自动 ×2。这个倍频器在时钟树图上画着，但**没有可填的格子**——你改不了它，只能算进去。  
**自测**：Q：F103 的 APB1 用 ÷2，PCLK1 = 36MHz，挂在上面的定时器时钟是多少？　<details><summary>答案</summary>A：72MHz（36 × 2），不是 36【实测：时钟树显示 APB1 Tim = 72】。</details>  
**出处**：【视频A@08:30 字幕原话】「此倍频器有 ×1 和 ×2 两个值，但我们无法自己设置」；【实测】F103：APB1 ÷2 → PCLK1 36MHz，但 APB1 Tim = 72MHz；F407：APB1 42 → Tim 84、APB2 84 → Tim 168；【手册】RM0008/RM0090 定时器时钟；【待核】上板 PWM 频率未实测。

#### ❌ 14 · HSE 频率和板子实际晶振不一致（8 vs 25）

**判定**：CubeMX 里 RCC 填的 HSE 输入频率，和板子上那颗晶振不是同一个数。默认值：F103 8MHz、F407 25MHz、F411 25MHz【实测】。  
**你会看到**：串口全是乱码、延时明显变长或变短、USB 认不到、定时器频率不对；时钟树上每个数字都"对"，因为它们全按你填错的晶振算【待核：未上板复现】。  
**怎么办**：看板子上晶振的丝印，把 RCC 的 HSE 输入频率改成实际值（F407 国内板多是 8MHz，就从默认 25 改成 8），整棵树会跟着重算。  
**错因**：整棵时钟树都是从 HSE 这一个数乘除出来的，而这个数是"你告诉 CubeMX 的"，不是它自己量的。填 25 实际 8，所有倍频分频都按 25 算：主频、串口波特率、定时器、USB 全部按 8/25（约 0.32 倍）偏。波特率一偏，串口收到的每一位都对不上，就是乱码。  
**自测**：Q：板子上是 8MHz 晶振，CubeMX 里 HSE 填了 25，串口会怎样？　<details><summary>答案</summary>A：实际波特率变成设定值的 8/25 ≈ 0.32 倍，收发每一位错位，串口乱码；看晶振丝印改成 8 就对【推断：8÷25 ≈ 0.32】。</details>  
**出处**：【视频B@09:29】原话「这个 8 是可以改的……如果你用到一些其他开发板，你可能需要去查一下那个硬件电路，以防止这里晶振频率变了」；【实测】三款默认 HSE 8 / 25 / 25；【推断】波特率按 8/25 偏；【待核】F407 国内 8MHz 板的具体板型、上板乱码现象。

### 组 E · 红色和灰色：CubeMX 到底在提醒什么

> 这一段最容易误读：红色只说明"总线超了"，灰色连提醒都不算。而且灰色有两种——**F103 的 ADC 格是"不拦你"，F4 的 ADC 档位是"根本不让你选"**。老师看到红色只做了一件事——「咱们直接除以 2」【视频B@14:51】，但除完的代价（定时器 ×2、外设变慢）没人算给他看。

#### ❌ 2 · APB1 超限

**判定**：算出来的 PCLK1 大于上限（F103 36 / F407 42 / F411 50 MHz）【实测·库】。  
**你会看到**：PCLK1 那个数字变成品红色，APB1 预分频那一格也是品红，Clock Configuration 标签页前冒出一个品红小圆点，Resolve Clock Issues 按钮从灰变可点；但界面不告诉你该改成几、改完别处会变成多少【视频B@14:03–15:00】。  
**怎么办**：APB1 预分频加大一档：F103 从 ÷1 到 ÷2（PCLK1 72→36）；F407 用 ÷4 → 42；F411 用 ÷2 → 50【实测】。代价是挂在 APB1 上的外设时钟跟着降，定时器还要再翻倍一次（见第 10 条）。改 HCLK 回车 CubeMX 会自动求解（Searching Solution），但它只帮你凑合法，不帮你算代价【实测】。  
**错因**：APB1 是低速外设总线，串口 2~5、I2C、TIM2~7 这些挂在上面。芯片工艺决定了它跑不到 CPU 那么快，超了不是"更快"，是总线时序不满足、外设读写可能出错。工具只标红不自动改，因为它不知道你要保哪些外设——分频一改，挂在上面的所有外设时钟一起降。  
**自测**：Q：F103 的 HCLK = 72MHz，APB1 停在 ÷1，PCLK1 是多少？合规吗？　<details><summary>答案</summary>A：72MHz，超了 36MHz 上限，必须改成 ÷2（72÷2 = 36，正好卡上限）【实测】。</details>  
**出处**：【视频B@14:03–15:00】选中 PLLCLK 后 PCLK1=72 立刻品红、标签页出现品红点、Resolve 按钮可点；【视频B@14:12】原话「这边出现红色了，红色的就有问题」；【视频B@14:51】原话「他这里写着是 36 兆赫兹是最大值……咱们直接除以 2」；【实测·库】三款 APB1 上限 36 / 42 / 50；【实测】改 HCLK 回车触发自动求解。

#### ❌ 3 · APB2 超限

**判定**：算出来的 PCLK2 大于上限（F103 72 / F407 84 / F411 100 MHz）【实测·库】。  
**你会看到**：PCLK2 数字变品红、APB2 预分频那一格变红，和 APB1 超限是同一套提示；F407 上要特别小心：HCLK 拉到 168，APB2 上限只有 84，分频停在 ÷1 就是 168。  
**怎么办**：APB2 预分频 ÷1 → ÷2（F407：168→84，正好压到上限）。改完挂 APB2 的 ADC、串口 1 时钟都会变，ADC 那条要回头查（见第 4 条）。  
**错因**：APB2 是高速外设总线，ADC、串口 1、SPI1、TIM1/8 都挂在上面。它的上限比 APB1 高一倍，但也不是和 CPU 同频：F407 HCLK 168 时 APB2 最多 84，所以必须 ÷2。关键是——**ADC 就挂在 APB2 上**，你在这里按下的分频，会直接改掉第 4 条要算的 ADC 时钟。  
**自测**：Q：F407 的 HCLK = 168MHz，APB2 用 ÷1 行不行？　<details><summary>答案</summary>A：不行，168 > 84 上限；改成 ÷2 → 84 正好合规【实测】。</details>  
**出处**：【实测·库】三款 APB2 上限 72 / 84 / 100；【视频B@14:12】同一套红色提示机制；【视频B@14:29】原话「它这里显示最大是 72 兆赫兹」——PCLK2 旁印的就是 72 MHz max；【视频B@14:51】同类超限的处置就是"除以 2"；【手册】RM0008/RM0090 总线与 ADC 挂载关系。

#### ❌ 4 · ADC 时钟超 14 / 36MHz（附带采样率换算）

**判定**：ADC 时钟 = PCLK2 ÷ ADC 预分频（÷2 / ÷4 / ÷6 / ÷8），结果拿去和上限比：F103 是 14MHz，F407 和 F411 都是 36MHz【实测·库】。**两家的预分频位置和拦法完全不同，不能一句话带过**：  

| 对比项 | F103（F1） | F407 / F411（F4） |
|---|---|---|
| 预分频在哪 | Clock Configuration **时钟树里的一格** | **ADC 参数页**（Parameter Settings） |
| 可选档位 | ÷2 / ÷4 / ÷6 / ÷8 | ÷2 / ÷4 / ÷6 / ÷8 |
| 超过 14 / 36 时 CubeMX 怎么办 | **不红、不拦、照样能点生成**（结果数字不标红） | **把超限档位直接禁用**（Action=DISABLE，下拉里选不到） |
| 学生怎么判 | 必须自己算：PCLK2 ÷ 当前档位 ≤ 14 | 看下拉里还有哪几档活着——能选的就是合规的 |

要算"这个采样时间能不能达到我要的速率"，用转换时间公式：F1 是 T_conv = (采样周期数 + **12.5**) ÷ ADCCLK【手册 RM0008】，F4 是 T_conv = (采样周期数 + **12**) ÷ ADCCLK【手册 RM0090，12 位模式】。自检：F103 在合法上限 ADCCLK = 14MHz、采样 1.5 周期 → (1.5 + 12.5) ÷ 14MHz = 1µs → 正好 1 Msps，跟数据手册对得上【推断·按手册公式】。（14MHz 是手册上限，这里只用它验算；72MHz 主频下 ÷2/÷4/÷6/÷8 只能得 36/18/12/9，凑不出 14。）**注意 F1 的 12.5 与 F4 的 12 不能混用，代公式前先看自己哪颗芯片。**

**你会看到**：F103 上什么都不发生——ADC 那一格显示 36MHz，字是灰的、不是红的，照样能点 GENERATE CODE【视频A@12:10 画面 + 实测】；F4 上超限的档位在下拉里是灰的/选不到（F407 在 PCLK2 = 84 时，÷2 → 42 被禁用，只剩 ÷4 = 21 及以下）【实测】。上板后 ADC 读数乱跳、不稳，你会去怀疑传感器和地线，而不会怀疑时钟【待核：未上板复现】。  
**怎么办**：F103：PCLK2 = 72 时 ÷2 = 36 超、÷4 = 18 还是超，必须 ÷6 = 12（或 ÷8 = 9）才合规【推断：72÷2、72÷4、72÷6】；F407：PCLK2 = 84 时 ÷2 = 42 仍超 36，要往 ÷4 = 21 或 ÷6 = 14 走【推断：84÷2 = 42】；F411：PCLK2 = 100 时 ÷2 = 50 被禁、÷4 = 25 合规【推断·F4 机制，F411 未逐项验】。注意 **ADC 挂在 APB2 上**，改 APB1 的分频（第 2 条）不会顺手修好它——视频里 PCLK1 已经变红时，旁边的 ADC 36 仍是灰的【视频B@14:03】。F4 的 CubeMX 会禁掉超限档位，但**它只管"时钟合规"，不管你"够不够快"**，采样率仍要自己按公式算。  
**错因**：ADC 是模拟电路，采样保持之后要做 12 位逐次逼近，每一位都要固定时间比较。时钟给太快，比较器还没比完就进下一位，高位错、低位更乱 → 读数跳。它也不是 CPU 时钟：ADC 时钟从 APB2 再分一次频，所以就算主频、APB2 都合规，最后这一格仍可能超。F1 这颗 ADC 的上限只有 14MHz（还不到 72MHz 的 1/5），最容易踩；而 12.5 个周期是采样结束后的固定转换开销，所以算速度必须带它，不能只拿采样周期数除以时钟。  
**自测**：Q：F103 在合法上限 ADCCLK = 14MHz、采样 1.5 周期，转换一次要多久？1 秒最多采多少次？　<details><summary>答案</summary>A：(1.5 + 12.5) ÷ 14MHz = 1µs → 1 秒 100 万次 = 1 Msps（和数据手册一致）。别用 1.5 ÷ 14MHz 得 9.33Msps，那是漏掉转换周期的错答案【手册公式 + 推断】。</details>  
**出处**：【实测】F103：ADC 预分频在时钟树里、回读 ÷2 得 36MHz、界面不报错、能生成；【实测】F4：ADC 预分频在 ADC 参数页、超限档位 Action=DISABLE（F407 的 PCLK2 = 84 时 ÷2 被禁）；【实测·库】上限 14 / 36 / 36；【手册】RM0008：F1 转换时间 = N + 12.5 个 ADC 时钟、ADCCLK 最大 14MHz；RM0090：F4 12 位模式 = N + 12、ADCCLK 最大 36MHz；【视频A@12:10】ADC ÷2 → 36 To ADC1,2，灰、无红、无解释；【视频B@14:03】同一屏 PCLK1 已品红报错、旁边 ADC 36 仍灰；【视频A@09:40】动画示例 ADC ÷6 → 12MHz；【推断】14MHz/1.5 周期 = 1Msps 自检、72÷2=36 / ÷4=18 / ÷6=12、84÷2=42；【待核】上板"读数乱跳"未复现、12MHz 采样率表未上板核对。

**第 4 条附表 · F103 在 ADCCLK = 12MHz 时的采样率上限**

12MHz 是 F103 在 72MHz 主频下把 ADC 预分频取 ÷6 的合规值。下表按 T_conv = (N + 12.5) ÷ 12MHz 算，**不是上板测的**【推断·按 F1 手册公式】：

| 采样周期数 N | 1.5 | 7.5 | 13.5 | 28.5 | 41.5 | 55.5 | 71.5 | 239.5 |
|---|---|---|---|---|---|---|---|---|
| 转换一次 T_conv（µs） | 1.167 | 1.667 | 2.167 | 3.417 | 4.50 | 5.667 | 7.00 | 21.0 |
| 1 秒最多采（上限） | **85.7 万** | **60.0 万** | **46.2 万** | **29.3 万** | **22.2 万** | **17.6 万** | **14.3 万** | **4.76 万** |

读法：① 12MHz 下想做 1Msps 是做不到的——采样周期拉到最短（1.5）也只有 85.7 万；要 1Msps 必须把 ADCCLK 提到 14MHz 上限，并配 1.5 周期【推断】。② 采样周期数越大，读数越稳（给采样电容的充电时间更长），但速度越慢，按信号源内阻选【手册】。③ 别拿"采样周期数 ÷ 时钟"当速度，漏掉 12.5 会让结果偏大——这是本轮修掉的那个错。

## 3.5 哪些是实测、哪些是机制推断（16 条逐条对账）

先说三条结论，评委按这三条查最省事：

1. **16 条的"界面层判定"全部是本机实测或器件库读出**——不是猜的（判限量、上限、预分频档位、引脚有无、生成是否报错）。
2. **16 条的上板故障表现全部没有逐条复现**，所以凡涉及"板子会怎样"的地方都标了【待核】。

| 1 | ADC 采样率 = `ADCCLK ÷ 采样周期数`；12MHz、1.5 周期 = 800 万次/秒 | 漏了"固定转换时间"：F1 采完样还要再花 **12.5 个 ADCCLK 周期**把模拟量转成 12 位数字。漏掉它，12MHz 那一格算成 800 万，是正确值（85.7 万）的 **9.3 倍**；而且 800 万已经超过 F103 数据手册的 1 Msps 物理上限（每秒 100 万次）——一个永远跑不到的数被写成了"上限" | 改成 `T_conv = (采样周期数 + 12.5) ÷ ADCCLK`，采样率上限 = 1 ÷ T_conv；整张表按 +12.5 重算；再加一条自检：14MHz、1.5 周期 → 正好 1 Msps | 手册 RM0008（12 位模式）+ 数据手册（1 Msps） |
| 2 | USB 时钟固定 ÷1.5 | F103 的 USB 预分频是**可选**的：÷1（默认）或 ÷1.5。写死 ÷1.5 会让人以为"PLL 配到 72，USB 自然就是 48"；实际默认 ÷1 时 USB 拿到的是 72MHz，远超 48 上限 | 改成「可选 ÷1（默认）/ ÷1.5；要 48MHz 必须手动选 ÷1.5 且 PLL=72MHz」，数据模型补 `usb_div_options` / `usb_div_default` | 实测：`.ioc` 回读 `USBFreq_Value=72000000`（默认 ÷1 的取值）+ 手册 RM0008 |
| 3 | 只说"ADC 预分频在时钟树"，F4 的 ADC 预分频记成"待补" | F4 的 ADC 预分频不在时钟树，在 ADC 参数页；而且 CubeMX 会把超上限的档位直接**禁用**（Action=DISABLE）。两族行为相反，一句"在时钟树里"只对 F1 成立 | data.json 新增 `adc_presc_location` / `adc_cubemx_enforced` 两个字段，数据模型、提示语、换算器都按芯片分支 | 实测：CubeMX 6.15.0 界面与 CLI 回读（F4 超限档 Action=DISABLE）+ 手册 RM0090 |
| 4 | 「所以表里的数是**上限**，不是实测采样率」 | 800 万这个数在那套公式下永远跑不到，还硬说它是上限，等于把推导当成了芯片的物理事实 | 改成「**理论最高值**」：含固定转换时间，但不含触发与传输开销；再受 1 Msps 上限和信号源阻抗两道限制 | 手册 RM0008 / RM0090 + 数据手册 |

工具要同时做三件事：把 CubeMX 的红字翻成人话、算出 CubeMX 不给的外设实际值、预测配错后的现象。这三件事只靠两样东西站住：**内置的数据对不对**，**套用的公式对不对**。下面把数据文件逐字段拆开，把两套时钟公式和三个换算器写成能直接照抄进代码的形式，最后给出每个数字的出处和复核方法。

**为什么单为 ADC 预分频多存两个字段**：同一件事在两族芯片上的界面行为相反。F1 把预分频放在**时钟树**里，超上限的档位照样能选、只灰不红（`adc_cubemx_enforced: false`）；F4 把它放在**ADC 参数页**，超上限的档位 CubeMX 直接禁用、点不动（`true`）。所以工具的提示语也必须分两种——F1 是「你现在选的 /2 会到 36MHz，超过 14 上限，改成 /6」；F4 是「/2 这一档已被 CubeMX 禁用，你能选的最高合法档是 /4 = 21MHz」。用同一句话提示，总有一族是错的。（实测 + 手册 RM0008 / RM0090）

**为什么要单存 USB 预分频的"默认值"**：因为"没动过"不等于"配好了"。F103 的默认是 ÷1，此时 USB 拿到的是 PLL 的 72MHz（超 48 上限），插电脑认不到；只有手动改成 ÷1.5 才是 48。工具要能一眼说出「你现在是 ÷1，USB 是 72MHz，超限」——这句话 CubeMX 不说。

三个附加机制的含义：FCLK 是 HCLK 停住时仍然运行的时钟，给中断采样用；CSS 是时钟安全系统，HSE 失效时自动切回 HSI 并产生中断；MCO 是时钟输出，从 PA8 引脚送出来——三条都在视频1 的 12:45–14:00 有画面，数据里只存"有没有"的布尔值，具体逻辑由界面决定是否展示。

## 4.2 第一套公式：F1 的时钟链（以 STM32F103C8T6 为例）

先看整条链，再看每一级的算式。视频2 08:36 老师原话「大家看到这样一框图看起来非常复杂是吗？大家不要慌」——学生第一眼怕的就是这张图，所以本节先把图讲成人话，再给算式。

**注意两个分叉**：ADC 接在 APB2 这条路后面，不是 APB1；SYSCLK 除了来自 PLL，也可以直接选 HSI 或 HSE。图里的 AHB 是芯片的主总线（连着内核、内存、DMA），APB1 / APB2 是两条外设总线，速度更慢，所以要先分频再挂外设。

```
HSE 8MHz ──[÷1 或 ÷2，可选]──┐
                             ├── PLL ──[×2…×16]── PLLCLK ──┐
HSI 8MHz ──[固定 ÷2 = 4MHz]──┘                             │
        （SYSCLK 也可直接选 HSI 8MHz 或当前的 HSE）           ↓
                                                        SYSCLK
                                                          ↓ [AHB ÷1…÷512]
                                                         HCLK
                        ┌─────────────────────────────────┴──────────────────┐
                        ↓ [APB1 ÷1…÷16]                                      ↓ [APB2 ÷1…÷16]
                     PCLK1（上限 36）                                     PCLK2（上限 72）
                        ↓                                                    ├──[ADC ÷2/4/6/8]── ADCCLK（上限 14）
                 APB1 定时器时钟（硬件 ×1 或 ×2）                            └── APB2 定时器时钟（硬件 ×1 或 ×2）
```

| 量 | 算式 | 出处 |
|---|---|---|
| PLL 输入 | HSE ÷ `hse_pll_div`（÷1 或 ÷2，可选）；或 HSI ÷2 = 4MHz | 实测：÷1×9=72,000,000；÷2×9=36,000,000；视频1 11:35 画面；手册 |
| SYSCLK | PLL 输入 × `pll_mul`（×2 ~ ×16）；或直接选 HSI/HSE | 实测；视频2 12:48–13:58 画面（三选一） |
| PLLCLK | 同上，PLL 的输出 | 实测 `.ioc`：`PLLCLKFreq_Value=72000000` |
| HCLK（内核和总线时钟） | SYSCLK ÷ `ahb_presc` | 实测 |
| PCLK1 / PCLK2（两条外设总线的时钟） | HCLK ÷ `apb1_presc` / ÷ `apb2_presc` | 实测 |
| ADCCLK（ADC 的采样时钟） | PCLK2 ÷ `adc_presc`（/2 /4 /6 /8）；上限 14MHz；**CubeMX 不拦**（`adc_cubemx_enforced: false`） | 实测 `.ioc`：`ADCPresc=RCC_ADCPCLK2_DIV6`、`ADCFreqValue=12000000`；视频1 C 段画面；手册 |
| USB 时钟 | USB 预分频 **可选 ÷1（默认）或 ÷1.5**：÷1.5 时 = PLLCLK ÷ 1.5（要 48MHz，PLL 必须正好 72MHz）；÷1 时 = PLLCLK = 72MHz（超 48 上限） | 实测 `.ioc`：`USBFreq_Value=72000000`（默认 ÷1）、`usb_div_default=1`；手册 RM0008 |
| TIMx 时钟（定时器时钟） | APB 分频为 1 时 = PCLK；分频不为 1 时 = PCLK × 2（×2 是硬件自动，改不了） | 实测：`APB1Freq=36,000,000` 而 `APB1TimFreq=72,000,000`；视频1 C 段原话 |
| SysTick 时钟 | HCLK ÷ 1 或 ÷ 8 | 实测；视频1 06:45–07:10 |

**★ ADC 的输入是 PCLK2，不是 PCLK1。** 实测 `.ioc` 里这个字段的名字就直接写着 `ADCPCLK2_DIV6`；视频1 的时钟树也是从 APB2 一路下来接 ADC；手册同样把 ADC 挂在 APB2。如果按"PCLK1 后面接 ADC"写，F103 会算出 36 ÷ 2 = 18MHz，与实测的 36MHz 差一倍，后面所有采样率都会跟着错。这一处值得在代码里写一行注释。

**★ 三个必须写死的点：**

1. **HSE 进 PLL 前有 ÷1/÷2，是可选的，不是固定 ÷2。** 寄存器位叫 PLLXTPRE，CubeMX 里叫 HSEDivPLL。默认 ÷1；想跑满 72MHz 必须用 ÷1（8 × 9 = 72）。用 ÷2 时 8MHz 先变 4MHz，最高 ×16 = 64MHz，反而上不了 72。证据：CubeMX CLI 两组回读（÷1×9 → 72,000,000；÷2×9 → 36,000,000）、视频1 11:35 的 ÷1/÷2 选择框、器件库时钟定义文件 `db\plugins\clock\STM32F102.xml` 里有 `HSEDivPLL` 元素。
2. **USB 预分频是可选档，默认 ÷1——要 48MHz 必须手动改成 ÷1.5。** 72 ÷ 1.5 = 48（合法）；72 ÷ 1 = 72（超 48 上限）。坑在于：实测 F103 的 `.ioc` 里 `USBFreq_Value=72000000`，正说明那份工程用的是默认 ÷1，USB 拿到的是 72 而不是 48——界面上那格数不是 USB 该有的频率，得自己按 ÷1.5 换算并检查。这正是"界面上的数不等于你要的数"的第一个例子。
3. **定时器的 ×2 是硬件自动的。** 视频1 字幕原话「此倍频器有 ×1 和 ×2 两个值，但我们无法自己设置」。所以正确说法是：APB 分频≠1 时，硬件自动把定时器时钟翻倍，你改不了，但算 PWM 时必须知道。

**实测对照**（公式算 / CubeMX 回读，全部同源：`D:\cube-verify\` 下三个工程）：

| 配置 | 公式算出来 | CubeMX 回读 | 结论 |
|---|---|---|---|
| HSE 8、÷1、×9、AHB/1、APB1/2、APB2/1、ADC/6 | 72 / 72 / 36 / 72 / ADCCLK 12 / TIM 72 | 72 / 72 / 36 / 72 / 12 / TIM 72；USB 框 72,000,000 | 时钟逐项一致；USB 那格 72 说明这份工程是**默认 ÷1**，不是 48 |
| 同上，只把 USB 预分频改成 ÷1.5 | USB = 72 ÷ 1.5 = 48 | （按回读的 PLL 72MHz 折算） | 推导；要 48 必须手动选 ÷1.5 |
| HSE 8、÷2、×9 | SYSCLK 36 | 36,000,000 | 一致（÷2 只到 36） |
| HSE 8、÷2、最高 ×16 | 64（到不了 72） | — | 由实测结论推出 |
| APB1 分频 /2 | 定时器时钟 36×2 = 72 | 72 | 一致 |
| ADC 预分频 /2 | 72÷2 = 36（上限 14） | 36，灰色、不标红 | CubeMX 不管外设上限（`adc_cubemx_enforced: false` 就是这个现象） |

最后一行就是产品存在的理由之一：总线超了 CubeMX 会标红（视频2 14:03 起品红、14:12 原话「这边出现红色了，红色的就有问题」），但外设超了它只灰显（视频1 画面 ADC /2 → 36，上限 14，无任何提示）。所以 ADC 上限必须由网页自己判，判定用的就是 `limits.adc`。**F4 不一样**：它的 ADC 预分频在 ADC 参数页，超上限的档位直接被禁用（见 4.3、4.4.2）。

## 4.3 第二套公式：F4 的时钟链（以 F407、F411 为例）

F4 的 PLL 不是"一个倍频"，而是四个系数：先除、再乘、再除两次。链条如下：

```
HSE 25MHz ──[÷PLLM]── VCO_in（推荐 1~2MHz）──[×PLLN]── VCO_out（100~432MHz）
                                                          ├──[÷PLLP 2/4/6/8]── SYSCLK ──[÷AHB]── HCLK ──[÷APB1/2]── PCLK1/PCLK2
                                                          └──[÷PLLQ]────────── USB（必须 48）
```

| 量 | 算式 | 出处 |
|---|---|---|
| VCO_in | HSE ÷ `pll_m` | 实测：F407 的 `VCOInputFreq_Value=1,000,000`（25 ÷ 25） |
| VCO_out | VCO_in × `pll_n` | 实测：`VCOOutputFreq_Value=336,000,000`（1 × 336） |
| SYSCLK | VCO_out ÷ `pll_p`（PLLP 只能 2/4/6/8） | 实测：168,000,000 |
| USB | VCO_out ÷ `pll_q`（必须正好 48） | 实测：`PLLQCLKFreq_Value=48,000,000`（336 ÷ 7） |
| HCLK / PCLK | 与 F1 相同（÷AHB、÷APB） | 实测 |
| TIMx / SysTick | 与 F1 相同（APB≠1 时 ×2；SysTick ÷1/÷8） | 实测：F407 的 `APB1Tim=84,000,000`、`APB2Tim=168,000,000` |
| ADCCLK | PCLK2 ÷ `adc_presc`（/2 /4 /6 /8）；上限 36MHz；**预分频在 ADC 参数页，超限档被 CubeMX 禁用**（`adc_presc_location` / `adc_cubemx_enforced: true`）。一次转换怎么算时间见 4.4.2 | 实测：`.ioc` 回读 + CubeMX 界面（超限档 Action=DISABLE）；手册 RM0090 |

F4 的约束（写进校验器，不满足就提示改哪一项）：

| 约束 | 值 | 出处 |
|---|---|---|
| VCO_in 推荐范围 | 1 ~ 2MHz | 手册 |
| VCO_out 范围 | 100 ~ 432MHz | 手册 |
| PLLP 允许值 | 2 / 4 / 6 / 8 | 手册、器件库 |
| PLLQ | 让 VCO_out ÷ PLLQ 正好等于 48 | 手册 |
| PLLM / PLLN 允许值 | 见 data.json（F407：PLLM 2~63、PLLN 50~432；F411 的清单更短，标【待核】） | data.json |
| ADCCLK 上限 | 36MHz | 手册 RM0090 |

**实测对照：**

| 配置 | 公式算出来 | CubeMX 回读 | 结论 |
|---|---|---|---|
| F407：HSE 25、M25、N336、P2、Q7、AHB/1、APB1/4、APB2/2 | 168 / 168 / 42 / 84 / USB 48 / TIM 84、168 | 全部一致 | 一致 |
| F411：HSE 25、M25、N200、P2、Q4、APB1/2、APB2/1 | 100 / 100 / 50 / 100 / USB 50 | 主频与外设逐项一致，USB 未单独回读 | USB 只有 50，要 48 必须降到 96MHz |
| F411：HSE 25、M25、N192、P2、Q4、APB1/2、APB2/1 | 96 / 96 / 48 / 96 / USB 48 | 全部一致 | 一致 |
| F411 故意超频：N336 | 168（上限 100），PCLK1 84 | 照样回读 168，只在生成代码时报 `IP not ready for code generation: Clock` | **CubeMX 不拦，工具必须自己判** |
| F407 满频下的 ADC：PCLK2 = 84 | /2 = 42（超 36，这一档被 CubeMX 禁用）、/4 = 21（合法） | 界面：超限档点不动 | 推导 + 实测行为；能选的最高合法档是 /4 = 21MHz |

**F1 与 F4 的区别，一张表说清：**

| 对比项 | F1（F103） | F4（F407 / F411） |
|---|---|---|
| PLL 结构 | 只有倍频 ×2~×16；HSE 侧有可选 ÷1/÷2 | 四个系数 M/N/P/Q（先除、再乘、再除、再除） |
| HSE 默认值 | 8MHz | 25MHz（但国内正点原子/野火 F407 板多为 8MHz，必须让用户选） |
| HSI | 8MHz，进 PLL 前固定 ÷2 | 16MHz，直接进 PLLM（data.json 的 `pll_source` 里没有 "HSI/2"） |
| USB 时钟算法 | 预分频**可选 ÷1（默认）/ ÷1.5**；要 48 必须手选 ÷1.5 且 PLL=72 | VCO_out ÷ PLLQ（没有预分频档可选） |
| ADC 时钟 | PCLK2 ÷ (2/4/6/8)，上限 14；**预分频在时钟树，CubeMX 不拦** | PCLK2 ÷ (2/4/6/8)，上限 36；**预分频在 ADC 参数页，CubeMX 禁用超限档** |
| ADC 一次转换的固定部分 | **12.5** 个 ADCCLK 周期 | **12** 个 ADCCLK 周期 |
| 典型满频组合 | 8MHz、÷1、×9 | 25MHz、M25、N336、P2（F407）；25MHz、M25、N200、P2（F411） |

**F411 的"做不到"要算给用户看**（这是换算器价值最硬的例子）：25MHz 晶振下想要 SYSCLK 100MHz，VCO_out 只能是 100 × PLLP，即 200MHz（PLLP=2）或 400MHz（PLLP=4，仍在 432 上限内）；想要 USB 48MHz，VCO_out 又必须是 48 × PLLQ（PLLQ 为整数）。200 ÷ 48 和 400 ÷ 48 都不是整数，同一个 VCO_out 不可能同时满足两边。实测的两组结果正好印证：要 100MHz 就给不了 48MHz USB（PLLQ=4 只得 50），要 USB 48 就把主频降到 96MHz（N192、P2、Q4）。工具在这里应该直接说人话：「不是你不会配，是这颗芯片在 25MHz 晶振下同时要这两个数做不到。」

## 4.4 三个换算器：把总线时钟换成学生真正要的数

CubeMX 的时钟页停在外设总线上限——PCLK1 旁印着 `36 MHz max`、HCLK 旁印着 `72 MHz max`（视频2 14:12–15:00 画面）；它不会告诉你：TIM3 要出 1kHz 该填多少、ADC 每秒最多采几个点、115200 波特率实际误差多少。这三个数才是学生写代码时要填的，也是本工具的核心增量。而且要记住：你改完 HCLK 一回车，CubeMX 只是开始 Searching Solution 把时钟搜出一组合法解（实测 6.15.0 界面），采样率、PSC/ARR、误差它一个都不显示。

### 4.4.1 定时器 PWM：先算总计数，再反解 PSC / ARR

PWM 就是调亮度、调转速用的方波：频率决定"闪不闪、响不响"，占空比决定"亮多少、转多快"。

**正算公式**：`f = TIMxCLK ÷ (PSC + 1) ÷ (ARR + 1)`（式子的来源是手册的定时器章节，F1 见 RM0008、F4 见 RM0090）

| 符号 | 含义 | 从哪来 |
|---|---|---|
| `f` | 你要的 PWM 频率（Hz） | 学生输入 |
| `TIMxCLK` | 这个定时器的时钟 | 按 4.2/4.3 算；★ APB 分频≠1 时是 PCLK×2 |
| `PSC` | 预分频值，实际分频是 PSC+1 | 工具反解 |
| `ARR` | 自动重装值，实际计数是 ARR+1 | 工具反解 |

**反解四步**（工具按这个顺序做，不做"猜"）：

1. 算总计数 `N = TIMxCLK ÷ f目标`（向下取整）。
2. 让 `PSC+1` 从 1 开始，每次 ×2，直到 `N ÷ (PSC+1)` 能装进定时器的 16 位计数器（手册）。
3. 得到 `PSC = (PSC+1) − 1`、`ARR = (N ÷ (PSC+1)) − 1`。
4. 回代算实际频率，并报误差 `|f实际 − f目标| ÷ f目标`；除不尽时取最近整数再回代，**不四舍五入假装精确**。

**算例（推导，不是实测）**：F103 的 TIM3 挂在 APB1（RM0008），APB1 分频 /2 时定时器时钟 = 72MHz；目标 1kHz。

- 总计数 N = 72,000,000 ÷ 1000 = 72,000。
- 先试 PSC+1 = 1：72,000 超过 16 位计数器能装的范围，装不下。
- 改 PSC+1 = 2：36,000 装得下 → `PSC = 1`、`ARR = 35,999`。
- 回代：72,000,000 ÷ 2 ÷ 36,000 = **1000.00Hz，误差 0**。
- 对照另一套常见填法：`PSC = 71`、`ARR = 999` 也是 1000.00Hz，但占空比只能分 1,000 档；上面那套能分 36,000 档，调亮度/转速更细。工具应该把两套都摆出来，并说明"都对，但精度不一样"。

### 4.4.2 ADC 采样率上限：为什么不能只除采样周期数

**这个量的正式名字叫「采样率上限（含固定转换时间，不含触发与传输开销）」。** 界面上也写这一串，不写"采样率"——因为它不是你实际能拿到的采样率，而是这套配法在理想条件下能到的天花板，而且连触发和搬运（DMA/中断）的时间都还没算进去。

**公式（两族差 0.5 个周期，不能混用）**：

| 系列 | 一次转换占多少 ADCCLK 周期 | 采样率上限 | 出处 |
|---|---|---|---|
| F1（F103） | `T_conv = (采样周期数 + 12.5) ÷ ADCCLK` | `f = 1 ÷ T_conv` | 手册 RM0008（12 位模式） |
| F4（F407 / F411） | `T_conv = (采样周期数 + 12) ÷ ADCCLK` | `f = 1 ÷ T_conv` | 手册 RM0090（12 位模式） |

一句话记住：**采样周期只是"给采样电容充电"的时间，充完还有一段固定的"把电压转成 12 位数字"的时间——F1 是 12.5 个时钟周期，F4 是 12 个，一个都不能少。**

**上一版错在哪（这条要写在页面上，不是藏在附录里）**：

| 上一版 | 现在 |
|---|---|
| `采样率 = ADCCLK ÷ 采样周期数`；12MHz、1.5 周期 → 800 万次/秒 | `采样率上限 = 1 ÷ ((采样周期数 + 12.5) ÷ ADCCLK)`；同一格 → 85.7 万次/秒 |

差 **9.3 倍**（8,000,000 ÷ 857,143）。而且 800 万还有第二个问题：F103 数据手册写死 12 位模式下最大 **1 Msps（每秒 100 万次）**，800 万是它的 8 倍——一个物理上永远跑不到的数，不能叫"上限"。

**自检（页面上的断言，任何人按计算器都能复核）**：

> **断言**：F103 在 ADCCLK = 14MHz（数据手册的合法上限）、采样周期取最短的 1.5 周期时：
>
> T_conv = (1.5 + 12.5) ÷ 14,000,000 = 1.000000 µs
>
> 采样率上限 = 1 ÷ 1µs = **1,000,000 次/秒 = 1 Msps**
>
> 正好等于 F103 数据手册标称的 1 Msps。反过来验：漏掉 12.5 的话，14e6 ÷ 1.5 = 933 万次/秒，是数据手册上限的 9.3 倍。
> **能对上 1 Msps 的公式才是对的；对不上，就是少了那 12.5 个周期。**
>
> 出处：手册 RM0008（12 位模式 12.5 周期）+ 数据手册（1 Msps）+ 推导（算式本身）。

**12MHz 下重算的完整表**（ADCCLK = 12MHz 是实测值：`.ioc` 里 `ADCFreqValue=12000000`、`ADCPresc=RCC_ADCPCLK2_DIV6`；表里的数都是按 +12.5 周期推导出来的。最后一行就是「采样率上限（含固定转换时间，不含触发与传输开销）」）：

| 采样周期（个 ADCCLK 周期） | 1.5 | 7.5 | 13.5 | 28.5 | 41.5 | 55.5 | 71.5 | 239.5 |
|---|---|---|---|---|---|---|---|---|
| 一次转换耗时（µs，含固定 12.5） | 1.167 | 1.667 | 2.167 | 3.417 | 4.500 | 5.667 | 7.000 | 21.00 |
| **采样率上限（次/秒）** | **85.7 万** | **60.0 万** | **46.2 万** | **29.3 万** | **22.2 万** | **17.6 万** | **14.3 万** | **4.76 万** |

（85.7 万 = 857,143 次/秒；4.76 万 = 47,619 次/秒。12MHz 是 F103 在 PCLK2 = 72MHz、ADC 分频 /6 时的值。）

**怎么读这张表**：采样周期越长，一次转换越慢，每秒点数越少——这就是"精度换速度"的直接代价。1.5 周期最快（85.7 万），但充电时间短，信号源内阻一大就不准；239.5 周期最慢（4.76 万），适合高阻抗信号。选哪个不是看谁快，是看你的信号源扛不扛得住这么短的采样窗。

**为什么 F103 满频时 ADCCLK 只能是 12MHz**（推导，用 4.2 的链算）：PCLK2 = 72MHz 时，ADC 分频 /2 = 36MHz、/4 = 18MHz、/6 = 12MHz、/8 = 9MHz；上限 14MHz，所以 /2 和 /4 都超了，合法的最高档就是 /6 = 12MHz——这正是实测那个工程的取值。

**超限联动（工具必须替 CubeMX 报的一条）**：

ADCCLK = PCLK2 ÷ 分频。F103 在 PCLK2 = 72MHz 时，ADC 分频如果还停在 /2，ADCCLK = 36MHz，而上限只有 14MHz——**CubeMX 只灰显、不报红、不阻止生成**（实测：ADC /2 配出 36，灰色不标红；数据字段 `adc_cubemx_enforced: false` 记的就是这件事）。这不是学生没注意，是他被界面说服了：视频2 14:29 老师原话「它这里显示最大是 72 兆赫兹，那么咱们直接给它拉满」——拉满之后 ADC 分频没人再动，ADCCLK 就跟着 PCLK2 一起超了。工具应当直接提示：「ADC 时钟 36MHz，超过 14MHz 上限；把 ADC 分频改成 /6（12MHz），此时 1.5 周期的采样率上限是 85.7 万次/秒」。注意超出数据手册规定的时钟上限后，转换结果不再保证正确（数据手册），不是"读数跳一点"这么轻。

**F4 的表（按 +12 周期，实测算出的 21MHz）**：

F4 的 ADC 预分频不在时钟树里，在 ADC 参数页（`adc_presc_location`），超上限的档位 CubeMX 会直接禁用（`adc_cubemx_enforced: true`）。F407 满频那组实测配置下 PCLK2 = 84MHz：

| 分频 | /2 | /4 | /6 | /8 |
|---|---|---|---|---|
| ADCCLK | 42MHz ❌ 超 36 上限（这一档按 CubeMX 的实测行为会被禁用） | **21MHz ✅** | 14MHz | 10.5MHz |

取 /4 = 21MHz，按 F4 的 `(采样周期数 + 12) ÷ ADCCLK` 算（F4 的采样周期档位来自手册 RM0090）：

| 采样周期（F4 档位） | 3 | 15 | 28 | 56 | 84 | 112 | 144 | 480 |
|---|---|---|---|---|---|---|---|---|
| 一次转换耗时（µs，含固定 12） | 0.714 | 1.286 | 1.905 | 3.238 | 4.571 | 5.905 | 7.429 | 23.43 |
| **采样率上限（次/秒）** | **140 万** | **77.8 万** | **52.5 万** | **30.9 万** | **21.9 万** | **16.9 万** | **13.5 万** | **4.27 万** |

（出处：ADCCLK 21MHz 由实测 PCLK2 84MHz ÷4 得到；档位来自手册 RM0090；每秒点数按公式推导。F4 数据手册的 12 位最大采样率本表未核对原文，标【待核】。F411 满频 100MHz 时 PCLK2 = 100MHz，/4 = 25MHz 合法、/2 = 50MHz 被禁用——同理推导。）

**边界要说清**：表里的数是**理论最高值**，不是实测采样率，也不是你可能拿到的采样率。它含了固定转换时间，但不含触发开销（定时器/外部触发的一次事件）和传输开销（DMA/中断搬数据），这两块还要再吃掉时间；同时被两件事压着：① 芯片的 **1 Msps** 是绝对上限（F103 12 位，数据手册）——公式在 14MHz、1.5 周期时正好顶到它，所以任何合法配置都不可能超过 1 Msps；② 外部信号源有内阻，内阻越大采样电容充电越慢，手册要求改用更长的采样周期才保得住精度，点数只会更低。所以界面上写「采样率上限（含固定转换时间，不含触发与传输开销）」，不写「采样率」。

### 4.4.3 串口波特率误差：先算 USARTDIV，再算回实际值

**公式**：`USARTDIV = fCK ÷ (16 × 波特率目标)`；硬件只能填"整数 + n/16"（n = 0~15，手册），所以还要回算：`实际波特率 = fCK ÷ (16 × 实际可填的 USARTDIV)`；`误差 = |实际 − 目标| ÷ 目标`。

以学生最常用的 115200 为目标（这只是输入示例，不是芯片参数），F103 的两个串口分别挂在两条总线上（USART1 在 APB2、USART2/3 在 APB1，按 RM0008），结果不同：

| 串口 | 挂在 | fCK | USARTDIV | 最接近的可填值 | 实际波特率（推导） | 误差 |
|---|---|---|---|---|---|---|
| USART1 | APB2 | 72MHz | 39.0625 | 39 + 1/16 | 115,200 | 0 |
| USART2 / USART3 | APB1 | 36MHz | 19.53125 | 19 + 9/16 = 19.5625 | 115,016 | 约 0.16% |

0% 的原因很具体：72MHz ÷（16 × 115200）= 39.0625，小数部分 0.0625 正好是 1/16，硬件能精确表示；36MHz 时算出来是 19.53125，小数 0.53125 × 16 = 8.5，不是整数，只能就近填 9/16，于是偏了约 0.16%。**同一个波特率，挂在两条总线上误差不一样——这就是 CubeMX 不会告诉你的那类数。**

工具只把百分比摆出来，不给"合格线"：不同接收端、不同波特率能容忍的误差不同，编一个门限反而误导，标【待核】。

**PLL 结构与实测满频组合**：

| 芯片 | PLL 配置 | SYSCLK | 分频 | 外设实际时钟 | 回读 |
|---|---|---|---|---|---|
| F103 | HSE 8、÷1、×9 | 72 | AHB/1，APB1/2，APB2/1，ADC/6 | PCLK1 36 / PCLK2 72 / ADCCLK 12 / TIM 72 / USB 默认 ÷1 = 72（超 48）→ 手动 ÷1.5 才 48 | 一致 |
| F407 | HSE 25、M25、N336、P2、Q7 | 168 | AHB/1，APB1/4，APB2/2 | PCLK1 42 / PCLK2 84 / ADCCLK 21（/4，推导）/ TIM 84、168 / USB 48 | 一致 |
| F411 | HSE 25、M25、N200、P2、Q4 | 100 | AHB/1，APB1/2，APB2/1 | PCLK1 50 / PCLK2 100 / ADCCLK 25（/4，推导）/ USB 50（要 48 不行） | 一致 |
| F411 | HSE 25、M25、N192、P2、Q4 | 96 | AHB/1，APB1/2，APB2/1 | PCLK1 48 / PCLK2 96 / ADCCLK 24（/4，推导）/ USB 48 | 一致 |

**CubeMX 新建工程的默认值——不是"满频全绿"**（实测：新建工程后回读 `.ioc`）：

| 项 | F103 | F407 / F411 | 说明 |
|---|---|---|---|
| SYSCLK 来源 | HSI（内部 RC） | HSI（内部 RC） | 不是 PLL |
| SYSCLK 频率 | 8MHz | 16MHz | 跟芯片的 HSI 频率走 |
| PLL | 关闭 | 关闭 | 所以没有 72/168MHz |
| HSE | Disable | Disable | 默认不启用外部晶振 |

这条决定了页面的第一条提示：学生刚建工程看到的一切都是"内部 RC 直跑"的低速配置，而教程里的 72MHz/168MHz 全是手动配出来的——"CubeMX 默认就配好了"这个印象是错的。

**为什么 HSE 必须做成可选项**：CubeMX 给 F407 的默认晶振是 25MHz，而国内正点原子/野火板大多是 8MHz；用户不选板载值，PLLM 会差三倍左右（25 ÷ 8 ≈ 3.1），整条时钟链全错（视频2 09:29 老师原话提醒过"换开发板要去查硬件电路"）。所以页面第一步就是选晶振，不能写死 8MHz。

**范围边界**：以上数值只对这三款成立；同一系列换封装、换容量，引脚和上限都可能变，不能套用。

我是 <学校> <专业> 的 <年级> 学生，方向是 <电气/自动化/机电>。这一两年在做课程设计和电赛，STM32 从 F103 用到 F407。卡住我最多的不是写代码，是点配置——尤其是打开 CubeMX 那个像地铁线路图的时钟页，每次都要盯很久。

我不算会写代码的人，这个作品是我在 Qoder 里一句一句描述出来、再一条一条验收出来的。

二、你的作品是什么

一句话：给电子类专业学生用的 STM32 配置台——把 CubeMX 里的红字翻译成「改哪个、改成几」，算出你要的那个功能实际是多少，再告诉你配成这样会看到什么现象。

谁在什么场景下用：大二大三第一次用 CubeMX 配时钟和外设的时候，具体是四个时刻——

· 时钟页变红、变品红，不知道该动哪一格、该把数字改成多少；
· 功能还没跑，先要知道「我要 TIM3 出 1kHz，PSC 和 ARR 到底填几」；
· 程序烧进去不跑，想知道「我现在这个配法，正常应该出现什么现象」；
· 换了块 8MHz 晶振的开发板，而 CubeMX 里 F407 默认写的是 25MHz，整棵时钟树的分频全都对不上。

它明确不是什么：不是 CubeMX 的替代品，不生成代码，不替代数据手册，只做上面四个时刻中间那一步。

三、为什么做

<这里写你真实卡住的那一件事：要有型号、有外设、有现象。示例——我第一次配 F103，学视频里那样把 HCLK 拉到 72，PCLK1 变红，除以 2，红没了就生成代码，烧进去串口一句都不打印。>

后来我把三条教学视频逐帧看完，发现这不是我一个人的问题，是这套工具和这类教程中间留了一个洞。我直接引用原话（出处都标在后面）：

· 「大家看到这样一框图看起来非常复杂是吗？大家不要慌」——电子科技大学创客中心《如何使用 STM32CubeMX 快速配置工程》08:36。
· 「它这里显示最大是 72 兆赫兹，那么咱们直接给它拉满」——同一条视频 14:29。
· 「如果你这个地方选 No Debug……会导致芯片程序只能下载一次，第二次下不进去了」——同一条视频 07:01。

第三句最扎人：老师讲的是「现象」，学生记住的也是「现象」，不是寄存器名。

把前两句拼起来，就是大多数人配时钟的全部方法：看最大值 → 拉满 → 看到红 → 除以 2 → 红没了 → 生成 → 烧进去。红字消掉那一刻，配置在工具眼里已经合法了；可它在你的板子上会变成什么，没有人说过。

「会变成什么」到底长什么样，我在另一条讲 ADC+DMA 采波形的视频里数出来了。采样率不够的时候，波形会退化成台阶，而串口打印出来的原始数据是**五个值一循环**——3968、2509、290、365、2635，然后 3967、2525、297、356、2620，一个信号周期只被采到 5 个点。这不是玄学，是能一个数一个数数出来的。

同一条视频里还有一次：Overrun 选项选成「保留」，读数值就**卡死在 747** 一动不动，曲线变成一条平线；改成「覆盖」才恢复。屏幕上没有任何报错、没有红灯，只有一条不动的线和一组不变的数。

我把这两件事记下来，是因为它们说明了一个很朴素的道理：**配错的时候，芯片不会告诉你「你配错了」，它只会给你一个看不懂的现象。**

顺手记两个数字：讲结构的那条视频（keysking《STM32 时钟树动画讲解》）全长 14:53，只讲结构；创客中心那条全长 25:02，真正配时钟只占大约 5 分钟（10:00–15:00）。讲结构能讲 15 分钟，落到「我这个功能到底要填几」，一句话都没有。

所以这个作品不做「帮你算时钟树」——CubeMX 自己就会算：在时钟页把 HCLK 改一下回车，它会弹 Searching Solution 自己倒推 PLL 和分频（keysking 00:35–01:00 的画面）。我做的是它不做的三件事：

1）把红字翻译成人话。不只是「超了」，而是「哪一格超了、改成几、改完是多少」。例：F103 的 ADC 预分频配到 /2，ADC 时钟 = 72 ÷ 2 = 36MHz，手册上限 14MHz——CubeMX 这里只灰不红；改成 /6 就是 72 ÷ 6 = 12MHz，合规。

2）算它不算的那个数。总线时钟它给你，可「TIM3 出 1kHz 要填多少」它不给。F103 满频时 PCLK1 = 36MHz，APB1 分频不是 1，硬件自动把定时器时钟翻倍成 36 × 2 = 72MHz（这个 ×2 用户改不了）；72,000,000 ÷ 1,000 = 72,000，取 PSC = 71、ARR = 999，就是 1,000.0Hz。

这一条不是我猜的：CubeMX 的 TIM 配置页里，PSC 和 ARR 两个框你能填，但它**从头到尾不显示这两个数算出来是多少赫兹**。我把那条 32 分钟的 ADC+TIM+DMA 教程逐帧看完，那个 100kHz 是老师在口播里自己算的（170MHz ÷ 170 ÷ 10），界面上一个字都没有。

3）预测现象。不只看时钟：SYS 里的 Debug 选了 No Debug，你会看到「程序只能下载一次，第二次下不进去」（这是 07:01 那句原话）；PLL 只配到 36MHz 却想用 USB，你会看到电脑认不到设备——因为 F103 的 USB 预分频默认是 ÷1，36MHz 会直接灌进 USB（上限 48）；就算你手动拨到 ÷1.5，也只有 36 ÷ 1.5 = 24MHz，还是不对。这些你都该先知道，而不是烧进去以后去怀疑传感器和晶振。

四、怎么用（5 步）

1. 打开 <作品链接>，不用登录、不用装任何东西。
2. 选芯片：STM32F103C8T6 / STM32F407ZGT6 / STM32F411CEU6（只做这三款，都逐条核过）。
3. 填一句你手上的需求，或者点页面上的「示例」：比如 `TIM3 出 1kHz PWM`、`USART2 115200`。
4. 一眼看三个结果：红字被翻成「改哪个、改成几」；你要的功能实际是多少（PSC/ARR、ADC 时钟、USB 能不能拿到 48MHz）；照这个配法你会看到什么现象。
5. 点「导出」，把配置摘要和自查清单复制走；想反过来验，点「模拟配错」，看现象预测怎么变。

## 5.5 第③段的三句原话：出处与用法

素材里的 5 句原话，这一段只放 3 句；剩下 2 句在别处用（见下表最后两行）。

| 序 | 原话 | 出处 | 它在论证里干什么 |
|---|---|---|---|
| 1 | 「大家看到这样一框图看起来非常复杂是吗？大家不要慌」 | 创客中心 08:36 | 证明「这图吓人」不是我编的，连教这门课的老师都要先安抚一句 |
| 2 | 「它这里显示最大是 72 兆赫兹，那么咱们直接给它拉满」 | 创客中心 14:29 | 证明学生的配法就是「拉满」，不是「先想清楚我要多少」 |
| 3 | 「如果你这个地方选 No Debug……会导致芯片程序只能下载一次，第二次下不进去了」 | 创客中心 07:01 | 证明学生真正记住的是**现象**，而且是「第二次下不进去」这种具体症状 |
| 备 | 「此倍频器有 ×1 和 ×2 两个值，但我们无法自己设置」 | keysking（C 段） | 用在图 3：证明「我纠正了 Qoder 一个专业错误」 |

| **证** | **「五个值一循环」+ 梯形波**（不是原话，是我从画面里一个数一个数数出来的） | 小努班《STM32HAL库教程(ADC+TIM+DMA)波形采集》**30:30 之后** | 用在第③段：证明「配错的时候，芯片只给你一个看不懂的现象」 |
| **证** | **读数值卡死在 747**、曲线变一条平线 | 同一条视频 **08:21–08:33** | 同上，第二个例子 |
| **证** | **CubeMX 的 TIM 页不显示算出来的频率**（只有 `PSC = 170-1`、`ARR = 10-1` 两个框） | 同一条视频 **26:48 / 30:48** | 用在卖点 2：证明「它不算这个数」 |

## 5.7 结尾三件套怎么写

| 件 | 必须包含 | 为什么（出处） |
|---|---|---|
| 技术说明 | ①纯静态、无后端；②数据从哪来；③怎么核对；④边界在哪 | 评委要看「你是不是真做了」，不是「你说得多好」〔赛题正文 §四〕 |
| 明确不做什么 | 不替代 CubeMX / 不生成工程 / 不做代码生成 / 不全覆盖外设 / 只做 3 款 | 主动写边界，比等人挑刺强；也挡住「你这不就是 CubeMX 吗」这一刀 |
| Qoder 账号 | 单独一行，别藏在正文里 | 缺这一项算提交不合格〔赛题正文 §七 FAQ〕 |

「明确不做」这五条，每条配一句解释：

| 不做 | 一句话解释 |
|---|---|
| 不替代 CubeMX、不生成工程 | 生成工程要全系列外设库，那是 CubeMX 的活，做不完整就不做 |
| 不做代码生成 | 代码怎么写跟用什么库有关，和配时钟是两件事 |
| 不全覆盖外设 | 只做时钟、引脚和常用外设，做全了每一项都会变浅 |
| 只做 3 款 | 这 3 款逐条核过；器件库其余型号只有型号列表、没有逐条核对，宁可不开 |
