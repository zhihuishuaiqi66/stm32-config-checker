## 1.1 为什么这是 StudyHack

评审最可能先问一句：

> 「这是给工程师配芯片的效率工具，跟 StudyHack 有什么关系？」

这句话必须先答；答不好，后面写得再准，也不算在这个赛道里。

**答案不是「它顺便也能帮人学习」，而是：这个产品的主干就是学习动作——把「猜」去掉，它只剩一个算得挺准的计算器，评审那句话就成立了。**

### 1.1.1 配置是题目，不是目的

学生打开它，不是为了「配完就走」，而是为了回答一个问题：**「我这样配，会发生什么？」**

- **配之前先猜**：这棵树配出来，定时器实际跑多少？ADC 会不会超？USB 认不认得到？
- **揭晓**：页面给出真实结果，并说清「是哪一格造成的」；
- **记住**：把他猜错的那几条写进错题本；
- **回来**：下次打开先考错题，答对两次才移出。

这四步是一个完整的学习闭环：**诊断 → 揭示 → 记住错题 → 复习**。配置是题目，判题才是产品。

### 1.1.2 效率工具和学习判题器，差在哪

| 维度 | 效率工具（旧定位） | 学习判题器（本节定位） |
|---|---|---|
| 度量什么 | 省了多少时间、少了多少次往返 | 原来猜错的，现在还会不会错 |
| 用户什么时候打开 | 卡住的那几分钟，用完就走 | 卡住时来一次；过几天回来复习 |
| 产品在哪一步结束 | 给出正确答案就结束 | 给出答案才开始：错题本、复习、第二次答对 |
| 正确答案怎么用 | 抄走 | 先猜、再对答案；猜错才是内容 |
| 评委当场能验什么 | 算得快不快、准不准 | 做三道题，错题本立刻多三条 |
| 归到哪个赛道 | 工程实践、效率工具 | StudyHack：学习闭环 |

### 1.1.3 闭环四步，每一步为什么是「学」

| 环节 | 学生的动作 | 页面的动作 | 为什么这一步是「学」 |
|---|---|---|---|
| ① 诊断（先猜） | 看题面，先填一个自己的答案 | 先不给答案，只给输入框或选项 | 先有自己的判断，才有落差；没有猜，后面全是「哦」 |
| ② 揭示 | 点「揭晓」 | 亮出真实结果 + 因果链（是哪一格造成的）+ 出处 | 落差被看见的那一下，才记得住 |
| ③ 记住错题 | 看自己错在哪一条 | 写进本地错题本：我的答案、正确答案、错了第几次 | 错题是「我漏了什么」的清单，不是分数 |
| ④ 复习 | 下次打开先考错题 | 只出错过的题；答对两次才移出 | 闭环在这里合上；不复习等于没学 |

### 1.1.4 「猜」在产品里的三处硬绑定

| 产品部位 | 先猜什么 | 揭晓什么 | 错题本记什么 |
|---|---|---|---|
| 三个数卡片（定时器 / ADC / 串口） | 先自己填 PSC / ARR、采样率、波特率误差 | 真实值 + 算式 + 出处 | 你算错的是哪一步（时钟来源？×2？） |
| 屏 2 体检台 | 给一个现象，先猜是哪一格配错 | 真正的原因、改哪一格、改成几 | 现象 → 原因的反查错在哪 |
| 判题卡（一道配置题） | 猜「这样配会怎样」 | 真实后果 + 证据 | 这一条认知（例：不红不等于对） |

### 1.1.5 反过来验：把「猜」拿掉会怎样

把「先猜」拿掉，这个产品还剩什么？一张能拖的时钟树，加一个会算定时器参数的网页。它有用，但它是效率工具——评审那句话就成立了。

所以「猜」不是交互装饰，是「能不能算 StudyHack」的分界线。第 2 节的降级方案（做不完时，时钟树退化成一张静态图，只保留三个数卡片和现象清单）也按这条口径落地：**屏可以少，先猜这一步不能少**——三个数卡片里先填猜测再揭晓，现象清单里先猜原因再展开。

### 1.1.6 它真的在教吗：能测的、不能吹的

站内能算的只有三件事：**错题率**（第一次答错的比例）、**复习通过率**（错题第二次答对的比例）、**隔天再答正确率**（同一道题隔一天再出）。这三样只用本地数据算，不需要服务器。

不能吹的也写在这：真实用户的学习效果现在没有样本，不承诺「提升 xx%」；「先猜后揭为什么有效」也只是产品判断【判断】，没有引学习科学文献、也没有对照实验。这两条都记在 1.10 的待核清单里。

评委不用等这些数据——**做三道题，错题本立刻多三条**，这是当场可验的；1.6 末尾一口气列了三件当场可验的事。

## 1.2 一句话：是什么、谁用、什么时候用

**3 秒版**

> 配完 CubeMX，先别急着烧进板子：猜一句「这样能跑吗」，再看答案，再把你猜错的收进错题本。

**一句话定义**

> 给电子类专业学生用的 STM32 配置判题器：配之前先猜「这样配会怎样」，揭晓真实结果，把猜错的那几条记成错题，下次回来只考错题；同时给出「改哪个、改成几」。

| 问题 | 答案 |
|---|---|
| 谁 | 电子、自动化、机电类学生，第一次独立配 STM32 的人（大二大三为主：课设、电赛、毕设） |
| 什么场景 | ① 配之前：先做题，猜「这样配会怎样」；② 点「生成」之前：对答案、看因果；③ 过几天：回来复习错题 |
| 解决什么 | 让你先猜、再揭晓；猜错的进错题本；同时告诉你「改哪个、改成几」 |
| 不是什么 | 不替代 CubeMX、不生成代码、不做仿真、不做题库 / 刷题 App（见 1.8） |

**先把七个词说清（给非本专业评委）**

| 词 | 大白话 |
|---|---|
| 晶振（HSE） | 板子上的小金属壳，给芯片打节拍；不同板子可能装 8 或 25 MHz |
| PLL 与分频 | 芯片里的变速齿轮：PLL 把晶振节拍成倍放大，分频反过来整数除小，给跑得慢的总线用 |
| 总线（APB1、APB2） | 芯片内部两条马路，各有自己的限速；超了 CubeMX 会标红【视频B@14:12】 |
| ADC | 把电压变成数字的部件，自己也有节拍上限——F103 上是 14 MHz【实测】 |
| 定时器时钟（TIMxCLK） | 定时器真正拿到的节拍。它不等于屏幕上那个 PCLK，中间还有一个硬件自动的 ×2【实测 + 视频A 字幕原话】 |
| 判题（先猜后揭） | 先让你押一个答案，再告诉你对不对。不是看完就算——先有自己的判断，错了才记得住 |
| 错题本 | 你猜错的那几条，存在你自己的浏览器里；下次打开先考它们 |

## 1.3 三个真实场景

> 三个人是按三条视频里学生的真实动作合成的典型画像，不是采访对象；动作、界面反应、老师原话都能指到分秒。这一版不写「他浪费了多少时间」——没有计时样本就不编；写的是**他错在哪一步**，而那一步有视频画面或实测支撑。

### 场景一 · 消红、收工，然后定时器跑出一倍（F103C8T6）

**人**：小周，大二自动化，第一次独立做课设。板子是 F103C8T6，8 MHz 晶振（这颗芯片在 CubeMX 里的默认值【实测】）。目标：TIM3 出 1 kHz 方波，再采一路 ADC。

| 项 | 具体发生什么 |
|---|---|
| 卡在哪一步 | ① 看到 HCLK 下印着「72 MHz max」，照视频里那句「它这里显示最大是 72 兆赫兹，那么咱们直接给它拉满」填 72【视频B@14:29】；② 回车后弹 Searching Solution，自己把 PLL 倍频和分频倒推好【视频A@00:35–01:00】；③ PCLK1 变品红——「这边出现红色了，红色的就有问题」【视频B@14:12】，旁边印着 36 MHz max，于是「咱们直接除以 2」【视频B@14:51】，红消；④ 生成、烧写、收工。 |
| 他以为 | 红消了 = 配对了 = 能跑。以后再出问题，一定是代码、传感器或者板子。 |
| 其实是 | 红色只说明「总线超了」；红消掉，只解决了界面会喊的那一类问题。影响他要的功能的两件事，界面没喊：① ADC 拿到的是 PCLK2 的 72 再 ÷2 = 36 MHz，超了 F103 的 14 MHz 上限，这一格只灰、不红、不拦生成【实测 + 视频A@12:10 画面】，改 ÷6 得 12 MHz 才合规【实测：72 ÷ 6 = 12】；② 定时器真正拿到的是 72 MHz，不是屏幕上的 36——APB 分频不是 1 时，硬件自动把定时器时钟 ×2，这个 ×2 不在任何可改的格子里【实测 + 视频A 字幕原话】。按 36 填出来的分频，实际跑是 2 kHz【推算：72,000,000 ÷ (36 × 1,000) = 2,000】。 |
| 界面没告诉他 | 灰 ≠ 安全；屏幕上的 PCLK1 ≠ 定时器拿到的时钟。 |
| 现在怎么解决 | 没解决。他认定「不红 = 对」，这个错会跟着他整个项目周期：往后每个异常都要从传感器、代码、板子重查一遍。 |

**判题卡（产品里这道题的样子）**

> **题面**：「F103，HCLK = 72、APB1 = ÷2，TIM3 要出 1 kHz。PSC 和 ARR 填几？实际会跑多少？」
> **最常见的猜法**：按屏幕上的 PCLK1 = 36 MHz 算 → PSC = 35、ARR = 999，以为正好 1 kHz。
> **揭晓**：定时器时钟其实是 72 MHz（×2 是硬件自动的）。同一组参数回代是 2,000 Hz；按 72 MHz 重算，PSC = 1、ARR = 35,999，回代正好 1,000.00 Hz【推算，算法与第 4 节 4.4.1 同一套】。
> **错题本记一条**：「屏幕上的 PCLK1 不是定时器时钟；总线分频不是 ÷1 时，定时器时钟自动 ×2，用户改不了。」

### 场景二 · 在「100 MHz」和「USB 48」之间来回试（F411CEU6）

**人**：小陈，大二，准备电赛。板子是 F411CEU6（Black Pill，板载 25 MHz 晶振，也是 CubeMX 的默认值【实测】）。他要跑满 100 MHz，同时用 USB 虚拟串口往电脑打数据。

| 项 | 具体发生什么 |
|---|---|
| 卡在哪一步 | CubeMX 按 100 MHz 自动倒推出 PLLM = 25、PLLN = 200、PLLP = 2【实测】；可 USB 不是 48 MHz——USB 取自 PLL 的中间频率 200 MHz 再除以 PLLQ：取 4 得 50【实测】，取 5 得 40【推算：200 ÷ 5 = 40】，怎么都到不了 48。他开始换参数：P 改 4？N 减小一点？每换一次，别处又不对。 |
| 他以为 | 这是「还没调对」，多试几轮总能试出来。 |
| 其实是 | 这不是手感问题，是数学问题：这组目标**无解**。要 100 MHz，中间频率只能是 100 × PLLP，而 PLLP 只能 2 / 4 / 6 / 8，又要落在 100~432 MHz 之间，所以只剩 200 和 400【手册 + 推算】；要 USB 48，中间频率又必须能被某个整数整除成 48——200 ÷ 48 和 400 ÷ 48 都不是整数【推算】。两边凑不到一起。 |
| 界面没告诉他 | CubeMX 会按 100 MHz 算出一整套 PLL 参数，但不会说「USB 这格从此无解」；它只报单格合不合法，不报「你要的这组目标凑不出来」。 |
| 现在怎么解决 | 去群里问，最常见的答复是「你 PLLQ 设错了」，但设成几才对，没人给具体数。最后只有两条路：放弃 USB 跑 100 MHz，或降到 96 MHz 保住 USB（PLLN = 192、PLLP = 2、PLLQ = 4）【实测】。 |

**判题卡**

> **题面**：「F411、25 MHz 晶振，想同时要 100 MHz 和 USB 48 MHz，能不能做到？」
> **最常见的猜法**：「能，再调调 PLLQ 就行」／「不能，但说不清为什么」。
> **揭晓**：不能。两条可选的中间频率 200、400 都不是 48 的整数倍【推算】。可行的两条路：96 MHz + USB 48（N = 192、P = 2、Q = 4，实测）、或 100 MHz 放弃 USB（PLLQ = 4 只得 50，实测）。
> **错题本记一条**：「有些目标组合本身无解；无解要能证明，不是多试几轮。」

### 场景三 · 不跑，第二次还下不进去（F407ZGT6）

**人**：小吴，大三，做毕设。板子是 F407ZGT6，三款里时钟树最复杂的一款【判断】；板载晶振到底几 MHz 他没看过（CubeMX 默认 25 MHz，而国内常见的 F407 板多为 8 MHz【实测默认值 + 待核：具体板型需对原理图】）。

| 项 | 具体发生什么 |
|---|---|
| 卡在哪一步 | 配完、生成、烧写，板子不跑；再烧一次，报错下不进去；换线、换口、换电脑都不行。搜索出来的答案互相矛盾：改 BOOT0、装驱动、勾 Reset and Run、换芯片。而他的配置里至少有一条「完全合法、却致命」的选项：SYS 里的 Debug 选成 No Debug，「会导致芯片程序只能下载一次，第二次下不进去了」【视频B@07:01 原话】。 |
| 他以为 | 编译通过 + 烧写成功 = 配置没错；问题在硬件、线材、电脑，或者芯片坏了。 |
| 其实是 | 合法性检查和可用性是两件事。No Debug 这一格 CubeMX 不拦、不红，代价是下载口被关掉——第一次下载成功，正是关掉它的那一次；之后电脑再也连不上芯片，而芯片还在跑上一次的程序。 |
| 界面没告诉他 | 「这一格合法，但会让你下次连不上。」 |
| 现在怎么解决 | 穷举 + 问人 + 刷视频。答案在视频里，但他不知道该看哪一期、看到第几分钟。 |

**判题卡**

> **题面**：「第一次能烧、程序也能跑；第二次下载报错，电脑连不上芯片。最可能是哪一格？」
> **选项**：BOOT0 / 驱动 / 晶振 / SYS → Debug。
> **揭晓**：SYS → Debug 选成了 No Debug【视频B@07:01】。改回 Serial Wire，重新生成再烧一次。
> **错题本记一条**：「合法 ≠ 可用；现象要能反查到具体的配置格。」

### 三个人卡住的是同一件事

连讲这套课的老师，开口第一句都要先安抚：「大家看到这样一框图看起来非常复杂是吗？大家不要慌」【视频B@08:36】——这张图本来就不是给初学者「看懂」用的。

学生手上只有两种信息：**界面的颜色**和**板子的现象**。中间那一层「这颜色 / 这现象意味着什么、把哪个值改成几」是空的。CubeMX 回答的是「合法不合法」；学生要问的是「能不能跑、怎么改」。

三个人卡住的其实是同一件事——**每个人都有一个「以为」，而那个「以为」从头到尾没有人当场纠正过**。

| 场景 | 他以为 | 真相 | 这个错会跟他多久【判断】 |
|---|---|---|---|
| 一 | 不红 = 对 | 灰的格子也能错；屏幕上的数不是定时器的数 | 整个项目周期：每个异常都归到传感器和代码头上 |
| 二 | 没调对，再试试 | 这组目标无解 | 到有人点破，或者放弃一个功能 |
| 三 | 能烧 = 配置对 | 合法 ≠ 可用 | 到重刷、换板、问人，甚至换芯片 |

这三条「以为」，就是产品里的三道判题卡。判题器的全部内容就是：把这一类「以为」一条条挖出来、当场揭晓、记进错题本。

## 1.4 诚实对比：CubeMX 做什么、教学视频做什么、我做什么

先把最容易被一句话打回的话说在前面：**CubeMX 会自动算时钟树，而且算得比我好；这件事我不做，也不该做。** 证据很直接：把 HCLK 改成 72 再回车，界面弹出 Searching Solution，自己把 PLL 倍频和各级分频倒推好【视频A@00:35–01:00】。

| 这件事 | CubeMX 6.15.0 | 三条教学视频 | 本作品 | 它让人学懂了吗 | 出处 |
|---|---|---|---|---|---|
| 自动算时钟树 | ✅ 强项：回车即倒推 | 讲原理，不替你算 | ❌ 不做，直接用它的结果 | ✅ 换个问法：先猜它会倒推出什么，再对答案——猜错的同学才知道 PLL 是怎么来的 | 视频A@00:35–01:00 |
| 显示上限 | ✅ 印着「72 MHz max」「36 MHz max」 | 提到 | ✅ 显示，并说明这个数从哪来 | △ 摆出数字不等于懂；本作品追问「这个上限对你现在的目标意味着什么」 | 视频B 画面 |
| 总线超限 | ✅ 变红或品红，还有 Resolve 按钮 | 演示「拉满 → 红 → 除以 2」 | ✅ 翻成「改哪个、改成几、代价是什么」 | △ 视频教了动作；本作品让人先猜「不红的那一格有没有错」 | 视频B@14:12 / 14:29 / 14:51 |

## 1.5 三个致命质疑，正面回答

### 1.5.1 「网上的 STM32 定时器计算器、PWM 计算器已经很多了，你有什么不同？」

**它们算的是最后一步，我从时钟树一路算到你手上。**

现成计算器的输入是 **TIMxCLK（定时器时钟）**——要你自己先从时钟树推出来。而「从 APB 分频推出 TIMxCLK」恰恰是最容易错的一步：分频 = 1 时不翻倍，分频 ≠ 1 时硬件自动 ×2，这个 ×2 你改不了，界面也不给你翻译【实测 + 视频A 字幕原话，07:30–11:15 段】。

还是场景一：屏幕上是 PCLK1 = 36 MHz，你要的 1 kHz 该拿来除的却是 72 MHz。把 36 填进现成计算器，它算得一丝不差，结果你得到 2 kHz【推算】。**计算器没错，错在它不问你这个 36 是从哪来的。** 同类例子还有两个：F103 时钟树上 USB 那格写 72（那是 PLL 输出，不是 USB 实际频率），USB 真正要的是 72 ÷ 1.5 = 48【手册 + 实测 + 视频A@00:55 画面】；HSE 进 PLL 前选 ÷1 还是 ÷2，÷1 × 9 = 72 MHz、÷2 × 9 = 36 MHz【实测】——界面上的数，不等于你要的数。

| | 现成定时器或 PWM 计算器 | 本作品 |
|---|---|---|
| 输入 | TIMxCLK（要你自己推） | 芯片 + 晶振 + 你要的频率 |
| 谁负责「APB 分频 → TIMxCLK」的 ×1 或 ×2 | 你 | 工具 |
| 这个时钟组合本身合法吗（USB 48、ADC 14） | 不检查 | 检查，并指出哪一格超了 |
| 配错了板上会看到什么 | 不管 | 管，且带证据等级（见 1.5.2） |
| 你算错了会不会被记住 | 不会 | 会：错的那条进错题本，下次先考它 |

它们在定时器细节上可能比我全（死区、互补输出这类进阶项），我不跟它们比这个【判断】。差别在问题的起点：现成计算器是给「已经知道自己该填什么」的人用的，而且是算完就走；这个作品是给「还不知道自己该问什么」的人用的，算完还要把你错在哪记住。

### 1.5.2 「你说配错会出什么现象，你自己烧板子验过吗？」

**先把话说死：本节列的现象，没有一条是我上板复现的。** 不拿「我看过」「我知道」冒充实测。证据分四档，产品里每条现象后面都带这个标签：

| 档 | 本节有哪些 | 来源 |
|---|---|---|
| 直接证据 · 公开可回看 | 「红字消了不等于对了」的整条动作链（拉满 → 红 → 除以 2）；No Debug 导致只能下载一次；ADC ÷2 得 36 MHz 时只灰不红 | 视频B@14:12 / 14:29 / 14:51、视频B@07:01、视频A@12:10 画面 |
| 直接证据 · 本机可复跑 | 三款芯片的各档上限（F103：主频 72、APB1 36、APB2 72、ADC 14、USB 48）；÷1 × 9 = 72,000,000、÷2 × 9 = 36,000,000；F411 的 96 MHz 组回读到 USB 48，按同一组公式算 100 MHz 时 USB 只有 50【实测 + 推算】 | 本机 CubeMX 6.15.0 命令行回读【实测】 |
| 机制推断 · 有公式没上板 | ADC 超 14 MHz 后读数乱跳、定时器频率比算出来的快一倍、USB 认不到、串口乱码 | 【推断】+ 手册机制；上板复现【待核】 |
| 没有出处 | BOOT0 上电不跑一类的说法 | 【待核】 |

第 3 节的 16 条规则里，8 条的现象有视频画面或实测直接支撑，另外 8 条的上板表现标【待核】（第 3 节 3.6）。**能分清这两类，本身就是设计的一部分**：页面上每条现象都带等级，评委可以随手抽一条核对。

错题本里的每一条答案也带出处：猜错之后，学生点开就能看到「这条结论来自哪、第几分钟」。**学习产品比工具更不能编证据**——错了还要被记住，就更要让人当场核对。

### 1.5.3 「这不就是 CubeMX 的 Clock Configuration 换个皮？」

**如果这个作品只有那棵树，这句话完全成立。所以树不是主角。**

树在屏 1 只做一件事：让你看见你改的是哪一格——点哪一格、下游谁跟着变、哪一格是锁死的。它是键盘，不是产品。

主角是树下面那三张换算卡和屏 2 的体检，再加上一个 CubeMX 根本没有的东西：错题本。

| 主角 | 回答什么 | CubeMX 给不给 | 学生在这里学到什么 |
|---|---|---|---|
| ① 定时器卡 | 我要 1 kHz，PSC 和 ARR 填几？定时器真实时钟是 72 还是 36？ | 不给（只到 PCLK1 的 36） | 屏幕上的 PCLK 不是定时器时钟；×2 是硬件行为 |
| ② ADC 卡 | 我要每秒采多少次？现在这个 ADC 时钟超了没有？ | 不给（36 超 14 只灰不红） | 灰的那一格也可能是错的 |
| ③ 串口卡 | 115200 的实际误差是多少？ | 不给（时钟页没有波特率） | 误差是算出来的，不是猜出来的 |
| 屏 2 体检台 | 我这个现象是哪个配置造成的？改哪一格、改成几？ | 完全不涉及（No Debug 它不提示） | 现象 → 配置的反查 |
| 错题本 + 复习列表 | 我上次错在哪？今天该复习哪几条？ | 完全没有这个概念 | 学习闭环的后半段 |

可检验的证明在第 2 节：那里写死了降级方案——真做不完时，时钟树退化成一张静态图，只保留三个数卡片和现象清单，**产品仍然成立**。反过来读这句话：树是可以被替换的，三个数和体检不是。这就是「换皮」和「换产品」的区别。

再补一层：换的不只是界面，还有数据模型。CubeMX 的数据只到总线和主频（所以 ADC 36 超 14 它不管【实测】）；本作品多存了外设上限、定时器那个隐藏的 ×1 或 ×2、USB 的 ÷1.5，以及三个换算公式（第 4 节）。同一棵树，它算合法性，我算后果。

另外，我不做 CubeMX 的求解器：它改 HCLK 会弹 Searching Solution，我不会。我改一格只往下重算，让「这一格」和「你那三个数」的因果露出来。所以「换皮」这个质疑在这一版更站不住：换皮换不出错题本。

## 1.6 学习闭环怎么在纯静态站里实现

赛道论证不能停在口号上。这一节写清楚：**没有服务器、没有账号、没有后端**，这个学习闭环怎么真的跑起来。纯静态站是比赛约束，也刚好是产品优势——评委断网就能验。

### 1.6.1 四个机制

| 机制 | 学生的体验 | 纯静态站怎么做到 | 数据存在哪 | 边界 |
|---|---|---|---|---|
| 先猜后揭（predict-then-reveal） | 每题先自己填或选，点「揭晓」才出答案 | 题面和答案写在同一份静态文件里；页面先只渲染题面，点按钮才渲染答案 | 不需要存 | 答案就在源码里，看源码的人能提前看到——这不是防作弊产品，不设防 |
| 错题本 | 答错一条，自动记下；下次能翻 | 每答错一条，往浏览器本地存储（localStorage）写一条记录 | 学生自己的浏览器 | 清缓存会丢；换设备带不走（用导出补） |
| 进度 | 首页显示「已答 / 答对 / 待复习」 | 每次作答更新计数 | 同上 | 同上 |
| 复习列表 | 打开先考错题，答对两次移出 | 从错题本生成列表，按「错了第几次、多久没复习」排序 | 同上 | 移出规则是产品判断【判断】，不是学习科学的定论 |

### 1.6.2 一条错题长这样

| 字段 | 例子 | 为什么要存 |
|---|---|---|
| 题号 | F103-TIM-01 | 页面靠它找回题目 |
| 我猜的 | 36 MHz（把屏幕上的 PCLK1 当成了定时器时钟） | 复习时要看见自己当时怎么想的——错题本不是答案本 |
| 正确答案 | 72 MHz（总线分频 ≠ 1 时硬件自动 ×2） | 对照 |
| 错了第几次 | 2 | 排序：错得多的先出 |
| 上次复习 | 上周 | 排序：久没看的先出 |

### 1.6.3 为什么不用后端

| 需求 | 常规做法（要后端） | 纯静态做法 | 本作品 |
|---|---|---|---|
| 账号 | 注册登录 | 不需要账号 | 静态 |
| 数据 | 存服务器数据库 | 存本机浏览器 | 静态 |
| 隐私 | 要收集学号、成绩 | 一条都不收集，页面不发请求 | 静态 |
| 评委验证 | 要联网、要等服务器 | 断网也能用 | 静态 |
| 代价 | — | 清缓存、换设备会丢 | 明说：提供「导出 / 导入」一段文本兜底 |

### 1.6.4 学习效果怎么算：能算的、不能吹的

站内三个指标：**错题率**（第一次答错的比例）、**复习通过率**（错题第二次答对的比例）、**隔天再答正确率**（同一道题隔一天再出）。有真实用户之后才有意义，现在没有数据，不吹提升幅度。

### 1.6.5 评委当场能验的三件事

1. **做三道题**：错题本立刻多三条——不需要等用户研究，现场就看得见；
2. **断网再打开**：功能不变，页面不发任何请求——证明没有后台、没有上传；
3. **点开任一条揭晓**：底下有出处（视频时间点 / 实测 / 手册），可以当场回看核对。

这三件事比任何「学习效果 +xx%」都硬：它们是现场可复现的。
