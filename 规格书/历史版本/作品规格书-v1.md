## 2. 目标用户与痛点（这段可直接抄进论坛帖第 ③ 段）

**谁**：电子/自动化/机电专业的大二大三学生，课程设计、电赛、毕设第一次真正用 STM32。

**真实场景**：
打开 STM32CubeMX，为了配一个「USART2 + TIM3 出 PWM」：
- 先在 Pinout 图里找到 PA2/PA3，点开下拉菜单挑 `USART2_TX`、`USART2_RX`；
- 再去 Clock Configuration 那个像地铁线路图的界面，把 HSE 拉进 PLL，算 PLLMUL，算 APB1/APB2 分频；
- 算错了不会报错——**编译能过、能烧进去、程序就是不跑**；
- 于是开始怀疑晶振坏、怀疑烧录器坏、怀疑板子坏，三小时后发现是 APB1 超了 36MHz。

**这就是我要解决的事**：把「查手册 + 心算分频 + 试错」变成「说一句话 + 看一眼红不红」。

## 3. 范围：做什么 / 明确不做什么

### 做（v1 全量）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 一句话解析 | 输入 `USART2 115200 TX=PA2 RX=PA3` → 解析出外设/参数/引脚 |
| 2 | 引脚占用图 | 按封装画引脚网格，已用=绿、冲突=红、空闲=灰 |
| 3 | 时钟树实时计算 | HSE→PLL→SYSCLK→AHB→APB1/APB2→ADC/TIM，每节点显示 MHz |
| 4 | 超限标红 | 超过芯片手册上限的节点变红并给一句人话解释 |
| 5 | 自查清单 | 12 条常见误配逐条判定 ✅/⚠️/❌ |
| 6 | 导出 | CubeMX CLI 脚本 / `.ioc` 关键行 / 引脚表 CSV |

### **不做**（写进页面底部或 About，显得专业）

- 不做完整的 CubeMX 替代品 —— **只做 3 款**（底层器件库其实覆盖 19 个系列 / 4801 颗，但只开放核对过的这 3 款）
- 不生成完整工程文件，只给可粘进 CubeMX 的配置片段
- 不做代码生成（那是 CubeMX 的事）
- **和用什么代码库无关**：本工具只管硬件配置（引脚占用 / 时钟树），
  不管你之后用标准库、HAL 还是 LL 写代码，也不管这颗芯片有没有标准库
- 不联网、不需要注册、不收集任何数据

> 明确「不做什么」是加分项：评委看到边界清楚，会认为你真懂这个领域。

### 只做这 3 款（做深不做广）

| 型号 | 内核 | 主频上限 | 封装 | 为什么选它 |
|---|---|---|---|---|
| STM32F103C8T6 | Cortex-M3 | 72 MHz | LQFP48 | 学生最便宜的入门板（Blue Pill），用得最多 |
| STM32F407ZGT6 | Cortex-M4 | 168 MHz | LQFP144 | 课设/电赛主力，时钟树最复杂、最容易算错 |
| STM32F411CEU6 | Cortex-M4 | 100 MHz | UFQFPN48 | Black Pill，HSE 25MHz 与众不同，常被配错 |

> **为什么不支持更多型号**：引脚复用表和上限值必须逐条核对，型号一多必错，评委一试就露馅。3 款做准 = 像产品；30 款做错 = 像作业。

12 条规则，每条一行：


底部一个按钮：`[ 一键修复能修的 ]` —— 只修「时钟超频」这一类能算出来的。

| warn | 含义 | 触发后果 |
|---|---|---|
| `swd` | SWD 调试口 | 占用后下次烧不进程序 |

| `usb` | USB D+/D- | 和 CAN 抢脚（F1 上 PA11/PA12） |
| `jtag` | JTAG 脚（F1：PA13/14/15、PB3/4） | 默认是调试口，当 IO 用要先关 JTAG |

### 5.3 一句话语法（沿用真实工具链的写法）

| 类型 | 示例 | 解析要点 |
|---|---|---|
| GPIO | `LED=PB12 输出 推挽` | 标签 + 引脚 + 方向 |
| USART | `USART1 115200 TX=PA9 RX=PA10` | 波特率 + 两个引脚 |
| I2C | `I2C1 SCL=PB6 SDA=PB7` | 默认引脚可省略 |
| SPI | `SPI1 SCK=PA5 MISO=PA6 MOSI=PA7` | 三线 |
| TIM PWM | `TIM3 PWM CH1=PA6 1kHz duty=25` | 频率 + 占空比 |
| ADC | `ADC1 IN0=PA0` | 通道映射 |
| CAN | `CAN1 TX=PA12 RX=PA11` | 注意和 USB 抢脚 |

**解析器要求**：
- 容错：中文/英文、大小写、空格多少都要能认

## 6. 四段核心逻辑（给 Qoder 的算法说明）

### 6.1 一句话 → 结构化配置

```
输入 → 按行/分号切分 → 每段正则匹配外设类型 → 提取参数 → 生成配置对象
配置对象: { type, instance, params, pins: [{ pin, role }] }
```

### 6.2 引脚冲突检查（按这个优先级）

```
1. 引脚不存在于当前封装        → ❌ 错误
2. 同一引脚被两个外设要         → ❌ 冲突
3. 引脚用了但 warn=swd/boot     → ⚠️ 警告
4. 引脚 warn=osc 且选了 HSE     → ❌ 冲突
5. 引脚 warn=usb 且配了 CAN     → ❌ 冲突
6. 引脚 warn=jtag 且当 GPIO 用  → ⚠️ 警告（需关 JTAG）
```

### 6.3 时钟树计算

**F1 系列**
```
SYSCLK = HSE / pll_input_div × pll_mul        // HSE=8MHz 时 = 8/2×9 = 36? 不对 → 8×9/2 = 36
```
> 注意：F1 的 PLL 输入来自 HSE（不分频）或 HSI/2。**HSE 是直接进的**，所以 `SYSCLK = HSE × PLLMUL`，`8 × 9 = 72 MHz`。
> `pll_input_div = 2` 只适用于「PLL 源 = HSI/2」的情况。**这条写进代码注释，别搞反。**

```
HCLK   = SYSCLK / ahb_presc
PCLK1  = HCLK / apb1_presc     // F1 上限 36 MHz
PCLK2  = HCLK / apb2_presc     // F1 上限 72 MHz
ADCCLK = PCLK2 / adc_presc     // F1 上限 14 MHz
TIMxCLK = (apb_presc == 1) ? PCLKx : PCLKx × 2   // ★ 最容易搞错的一条
```

**F4 系列**
```
VCO_in  = HSE / pllm                  // 推荐 1~2 MHz
VCO_out = VCO_in × plln               // 推荐 100~432 MHz
SYSCLK  = VCO_out / pllp              // F407 目标 168，F411 目标 100
USBCLK  = VCO_out / pllq              // 必须 48 MHz（要用 USB 时）
HCLK    = SYSCLK / ahb_presc
PCLK1   = HCLK / apb1_presc           // F407 上限 42 / F411 上限 50
PCLK2   = HCLK / apb2_presc           // F407 上限 84 / F411 上限 100
```

**F411 特别注意**：Black Pill 板上晶振是 **25 MHz**（不是 8MHz）。

```
要 100MHz（不用 USB）：PLLM=25 → VCO_in 1MHz，PLLN=200 → VCO_out 200MHz，PLLP=2 → 100MHz
要 USB：200MHz 除不出整数 48，必须换一组 —— PLLN=192 → VCO_out 192MHz，
        PLLP=2 → SYSCLK 96MHz，PLLQ=4 → USB 48.000MHz ✅
```

> **这就是最好的例子**：想跑满 100MHz 又要 USB，在 25MHz 晶振上做不到。这个坑很多人在 Black Pill 上踩过，正好拿来当自查清单第 5 条的默认演示。

### 6.4 超限判定与提示文案

```
if (值 > 上限) → ❌ + 一句人话 + 怎么改
if (值 == 上限) → ✅（但要提示"满频运行，注意发热"）
if (值 > 上限 × 0.9) → ⚠️
```

## 7. 十二条误配规则（界面文案，可直接抄）

| # | 规则 | 判定 | 提示语 |
|---|---|---|---|
| 1 | SYSCLK 超频 | SYSCLK > max_sysclk | `算出来 96MHz，这颗芯片上限 72MHz。把 PLLMUL 改成 ×9，或 AHB 分频设 /2。` |
| 2 | APB1 超限 | PCLK1 > max_pclk1 | `APB1 是低速总线，上限 36MHz。分频改成 /2。` |
| 3 | APB2 超限 | PCLK2 > max_pclk2 | `APB2 上限 72MHz，改分频。` |
| 4 | ADC 时钟超限 | ADCCLK > 14 (F1) / 36 (F4) | `ADC 采样时钟不能超过 14MHz，超了采样值会乱跳。ADC 分频改成 /6。` |
| 5 | USB 时钟不是 48MHz | PLLQ 算出来 ≠ 48 | `PLLQ 必须让 USB 拿到 48.000MHz，否则电脑认不到设备。` |
| 6 | 调试脚被占用 | PA13/PA14 被当 IO | `这两个是 SWD 调试口，占了下次烧不进程序。想用就把调试改成 Serial Wire 并少用一根。` |
| 7 | BOOT0 被当普通 IO | PB2/BOOT0 配了外设 | `BOOT0 决定启动模式，当普通 IO 用可能不启动。` |
| 8 | 选了 HSE 但晶振脚被占 | OSC_IN/OSC_OUT 有外设 | `这两脚接晶振，被占了 HSE 起不来，芯片会卡在启动阶段。` |
| 9 | 同一引脚被抢 | 同 pin 两个外设 | `PA9 同时给了 USART1_TX 和 TIM1_CH2，后配的会覆盖前一个。` |
| 10 | 定时器频率算错 | APB 分频 ≠ 1 | `APB 分频不是 1 时，定时器时钟是 PCLK 的 2 倍，PWM 频率会差一半。` |
| 11 | 引脚不属于该封装 | pin 在 absent 列表里 | `LQFP48 上没有 PC0~PC12，换 PA 或 PB 的脚。` |
| 12 | JTAG 脚当 IO 用 | PA15/PB3/PB4 当 GPIO | `这几个默认是 JTAG，当 IO 用要先关 JTAG 只留 SWD。` |

## 8. 数据准确性：怎么核对（这一节决定作品可信度）

### 方法 A：用 CubeMX 官方 CLI 校（推荐，也是作品帖的加分素材）

本机已有：
- `STM32CubeCLT_1.18.0`：`D:\Clion\STM32CubeCLT_1.18.0`
- CubeMX 插件 `dsh-stm32-cubemx` v1.6.0（一句话配外设 + `clock` 工具，会读回真实时钟值）

做法：
1. 网页上算出每组时钟值
2. 用插件的 `stm32_cubemx_clock` 在同一型号 `.ioc` 上设同样的 PLL 参数
3. 读回实际 HCLK/SYSCLK/APB —— 两边一致就通过
4. **把这组对照截图保存**，放进作品帖第 ⑤ 段

> 你之前的记录：F1 做过 15 项回归 + 4 轮独立验收，最大误差 0.001%。这句话写进帖子里，就是「我验过」的硬证据。

```

数据结构（内置 JSON，3 款芯片各一份）：
[把 stm32-data/data.json 整个文件贴进来。里面 mcus.<型号>.limits 是上限、

F1 系列（F103）：PLL 输入源是 HSE，直接进 PLL，所以 SYSCLK = HSE × PLLMUL。

  HCLK = SYSCLK / AHB分频

  PCLK2 = HCLK / APB2分频，上限 72MHz

  VCO_in = HSE / PLLM（推荐 1~2MHz）
  VCO_out = VCO_in × PLLN（推荐 100~432MHz）
  SYSCLK = VCO_out / PLLP
  USB = VCO_out / PLLQ，用 USB 时必须正好 48MHz

注意：STM32F411CEU6 的板子（Black Pill）晶振是 25MHz，不是 8MHz。

用户一旦在配置里写了 USB，就自动提示这组配不出 48MHz，建议换成
PLLM=25、PLLN=192、PLLP=2 → SYSCLK 96MHz、PLLQ=4 → USB 正好 48.000MHz。

> 注意里面所有数值单位是 **MHz**，不要混成 Hz。

时钟树要能交互：点 PLLMUL / 分频的下拉框能改，改完立刻重算。

```

## 附录 A：怎么再加一款芯片（三步，约 3 分钟）

> 这段是**给评委的回答素材**，也是你自己的操作手册。页面上不写，但你要背下来。

### A.1 为什么引脚数据能「白拿」

STM32CubeMX 安装时自带一份完整器件库：`D:\STM32CubeMX\db\mcu\*.xml`。
**2016 个 XML，覆盖 19 个系列、4801 颗 MCU**——C0 / F0 / F1 / F2 / F3 / F4 / F7 / G0 / G4 / H5 / H7 / L0 / L1 / L4 / L5 / N6 / U0 / U3 / U5。

每个 XML 里有：封装名、内核、最高主频、Flash/RAM、**每一个引脚的物理脚号 + 全部可选功能 + 信号类型**。
不需要联网、不需要"装过"那颗芯片、不需要固件包（HAL 源码包是另一回事，我们不用）。

### A.2 三步

**第 1 步 · 找到这颗芯片的库文件名**

```powershell
# 文件名是按型号区间归组的，不是一颗一个文件
Get-ChildItem "D:\STM32CubeMX\db\mcu" -Filter "*G431*"
# → STM32G431C(B)TxZ.xml
```

**第 2 步 · 改两个脚本**

```python
# ① _parse_mcu_db.py 的 SRC 字典加一行
SRC = {
    "STM32F103C8T6": "STM32F103C(8-B)Tx.xml",
    "STM32F407ZGT6": "STM32F407Z(E-G)Tx.xml",
    "STM32F411CEU6": "STM32F411C(C-E)Ux.xml",
    "STM32G431CBT6": "STM32G431C(B)TxZ.xml",      # ← 新增
}

# ② _build_data.py 的 CLOCKS 字典加一段
"STM32G431CBT6": {
    "clock_family": "G4",
    "limits": {"sysclk": __, "hclk": __, "apb1": __,
               "apb2": __, "adc": __, "usb": 48},
    "hse_default_mhz": __,          # CubeMX 里新建工程看一眼就知道
    "hse_options_mhz": [8, 12, 16, 24, 25],
    "hsi_mhz": 16,
    "pll_source": ["HSE", "HSI"],
    "pll_m": [...], "pll_n": [...], "pll_p": [2,4,6,8], "pll_q": [...],
    "ahb_presc": [1,2,4,8,16,32,64,128,256,512],
    "apb_presc": [1,2,4,8,16],
    "tim_doubling": True,
}
```

> `__` 的地方**必须查数据手册填，不能猜**。G4 的 PLL 结构和 F4 一样（M/N/P/Q），F1 不一样（只有 MUL）。

**第 3 步 · 重跑 + 实测校验**

### A.3 时钟上限去哪查（三个来源，按顺序）

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 芯片 **Datasheet** 的 Clock 表格 | 官方数字，最权威 |

| 3 | 你填完之后跑一次 CubeMX 生成 | 能生成 = 配置合法；报 `Clock is not ready` = 有超限 |

**不要用第 4 种「凭印象」**——这是这个作品唯一会翻车的地方。

## 附录 B：「为什么只有 3 款」怎么答

这是最可能被问的问题，给三个场景的现成答案。

### B.1 论坛作品帖里（放第 ⑪ 段「技术说明」）

> 底层数据来自 STM32CubeMX 官方器件库，覆盖 **19 个系列 / 4801 颗 MCU**。
> 本期只开放 3 款（F103C8T6 / F407ZGT6 / F411CEU6），
> 因为这三款的**引脚复用表和时钟上限逐条核对过，并用 CubeMX CLI 回读做了闭环验证**；
> 其余型号数据已就绪，但我没验过的就不放出来。

### B.2 评委现场问你

> 加一款是三步、三分钟：改一行库文件名、填六个上限、重跑脚本。
> 我没做，是因为**没实测过的数字放出去会误导人**——
> 电子方向的学生照着错的时钟值配，烧进去不跑，反而更浪费时间。
> 所以宁可只开 3 款，把这三款做准。

（这段话的价值不在"能扩展"，在于**你知道自己在做什么、以及为什么不做**。）

### B.3 页面底部那行小字（直接抄）

> 数据由 STM32CubeMX 官方器件库生成，底层覆盖 19 个系列 / 4801 颗 MCU；
> 本期开放 3 款（F103C8T6 / F407ZGT6 / F411CEU6），均已用 CubeMX CLI 回读校验。
> 不支持代码生成，不替代 CubeMX。

### B.4 三个坑，别在答辩时踩

| 别这么说 | 为什么 |
|---|---|
| 「我支持全部 4801 颗」 | 数据没验过，评委随手选一颗试就露馅 |
| 「我替代了 CubeMX」 | 明确做不到，生成工程只有 CubeMX 能干 |
| 「能生成标准库代码」 | 新系列根本没有标准库，说了就是外行 |
